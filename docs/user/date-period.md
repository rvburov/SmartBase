# Дата период времени

Свойство **«Дата период времени»** считает длительность диапазона, указанного в одном
свойстве **«Дата»**. Можно учитывать все дни, только будни, только выходные или отдельные
дни недели и ограничить расчет определенными часами каждого дня.

Например, в свойстве «Дата» хранится **01.09.2026–04.09.2026**. При учете всех дней
с **09:00 до 18:00** результат — **1 д 3 ч**: три учитываемых дня по девять часов,
всего 27 часов. Один день в результате всегда равен **24 накопленным часам**.

## Настройка свойства

1. Создайте в коллекции обычное свойство **«Дата»**, если его еще нет. В нем задавайте
   начало и конец диапазона. Дата создания и дата изменения записи для расчета не подходят.
2. Создайте новое свойство с типом **«Дата период времени»**. Без обычного свойства даты
   этот тип недоступен в списке.
3. В поле **«Даты для расчета»** выберите свойство с нужным диапазоном.
4. Отметьте учитываемые дни недели. Будни — **Пн–Пт**, выходные — **Сб–Вс**, все дни —
   все семь флажков. Можно выбрать любое сочетание, например только вторник и четверг.
5. Задайте начало и конец учитываемых часов, например **09:00–18:00**. Для всего дня
   укажите **00:00–24:00**. Конец должен быть позже начала.
6. Оставьте **«Автоматический расчет»** включенным либо выключите его для фиксации результата.
7. Нажмите **«Сохранить»**.

Начало и конец берутся из выбранного значения даты. Отдельно указывать свойство окончания
или выбирать расчет до текущего времени не нужно. Часы считаются так, как записаны в дате,
без перевода в часовой пояс сервера.

## Даты без времени

Для значения **«Весь день»** расчет идет от начала первой даты до начала последней.
Последняя дата не включается: **01.09–04.09** включает 1, 2 и 3 сентября.

В примерах ниже выбран **2026 год**, учтены **все дни недели**, часы **09:00–18:00**.

| Диапазон в свойстве «Дата» | Учтенное время | Результат |
|---|---|---|
| 01.09–04.09 | 3 дня по 9 часов = 27 часов | **1 д 3 ч** |
| 02.09–03.09 | 9 часов | **9 ч** |
| 02.09–04.09 | 18 часов | **18 ч** |
| 14.09–28.09 | 14 дней по 9 часов = 126 часов | **5 д 6 ч** |
| 21.09–27.10 | 36 дней по 9 часов = 324 часа | **13 д 12 ч** |
| 18.03–24.03 | 6 дней по 9 часов = 54 часа | **2 д 6 ч** |
| Только 04.09, без диапазона | Начало и конец совпадают | **0 мин** |

При **00:00–24:00** диапазон **01.09.2026–04.09.2026** даст **3 д**.
Календарная длина месяцев и високосные годы учитываются: **28.02.2024–01.03.2024** даст
**2 д** при учете всех дней целиком.

## Даты со временем

Учитывается только пересечение диапазона с выбранными часами каждого дня.
В примерах выбран **2026 год**, учтены **все дни недели**, часы **09:00–18:00**.

| Диапазон | Как считается | Результат |
|---|---|---|
| 01.09 10:15–13:45 | Весь интервал внутри учитываемых часов | **3 ч 30 мин** |
| 01.09 07:00–20:00 | Учитываются только 09:00–18:00 | **9 ч** |
| 01.09 07:00–08:30 | Пересечения нет | **0 мин** |
| 01.09 18:00–20:00 | Учитываемый интервал уже закончился | **0 мин** |
| 01.09 17:00–02.09 10:00 | Час первого дня и час второго | **2 ч** |
| 01.09 09:00–02.09 18:00 | По девять часов двух дней | **18 ч** |
| Только 01.09 12:00, без диапазона | Указан один момент | **0 мин** |

Сам диапазон может переходить через полночь: **01.09 23:00–02.09 02:00** при часах
**00:00–24:00** даст **3 ч**. Однако ночной ежедневный интервал **22:00–06:00** задать
нельзя: учитываемое окно должно помещаться в одни сутки.

## Дни недели

Для диапазона **04.09.2026 17:00–07.09.2026 10:00** — с пятницы по понедельник —
при часах **09:00–18:00**:

| Выбранные дни | Как считается | Результат |
|---|---|---|
| Все дни | 1 час пятницы + 9 субботы + 9 воскресенья + 1 понедельника | **20 ч** |
| Пн–Пт | По часу пятницы и понедельника | **2 ч** |
| Сб–Вс | По девять часов субботы и воскресенья | **18 ч** |
| Только Вт и Чт | Выбранных дней в диапазоне нет | **0 мин** |

Для дат без времени **14.09.2026–28.09.2026** при выборе **Пн–Пт** получится
**90 часов**, то есть **3 д 18 ч**. Для **21.09.2026–27.10.2026** — **234 часа**,
то есть **9 д 18 ч**. Для **18.03.2026–24.03.2026** — **36 часов**, то есть **1 д 12 ч**.

Праздники и перенесенные рабочие дни отдельно не определяются: расчет использует только
отмеченные дни недели.

## Автоматический и фиксированный расчет

При включенном **«Автоматическом расчете»** результат обновляется после изменения исходной
даты или настроек свойства. Отдельный снимок результата в базу не записывается. Текущее время
в расчете не участвует: ожидание новой минуты само по себе значение не меняет.

При выключенном тумблере результат фиксируется при создании записи. После этого изменение
даты, дней недели или часов не меняет снимок автоматически. Для обновления:

- На [[record-page]] откройте меню свойства и нажмите **«Пересчитать»**.
- В [[table]] выделите нужные записи и выберите **«Пересчитать»** в меню строки.

Если при создании записи дата была пустой, а затем вы ее заполнили, фиксированный результат
появится только после команды **«Пересчитать»**. Эта команда нужна и для записей, которые
существовали до добавления свойства.

## Пустое значение и ноль

**0 мин** означает корректный расчет с нулевой длительностью: одна дата без диапазона,
один момент времени, совпадающие границы или отсутствие пересечения с выбранными днями
и часами.

При автоматическом расчете **пустая ячейка** означает, что посчитать нельзя: исходная дата
не заполнена, значение не распознается, конец раньше начала либо свойство даты удалено
или сменило тип. В фиксированном режиме показан сохраненный снимок, который также может
быть пустым и ожидать команды **«Пересчитать»**.

Сохранить правило без выбранных дней недели, с одинаковыми часами начала и конца или
с концом раньше начала нельзя. **24:00** допускается только как конец учитываемого дня.
Прямое редактирование и вставка в рассчитанную ячейку недоступны.

## Большие коллекции

При обычном открытии и прокрутке таблицы расчет выполняется для запрошенных страниц
и колонок. Остальные миллионы записей для показа видимой части не пересчитываются.
Сортировка или фильтр по периоду обрабатывают весь соответствующий набор записей;
их длительность зависит от размера коллекции и числа разных диапазонов.

## Ранее созданные свойства

Прежнее выбранное свойство начала становится единственным источником диапазона.
Прежнее свойство окончания и режим до текущего времени больше не используются. Проверьте,
что в **«Даты для расчета»** выбрана нужная дата и в ее значениях заполнены обе границы.

Существующие фиксированные результаты сохраняются. Чтобы заменить их расчетом по диапазону
одного свойства, выполните **«Пересчитать»** для нужных записей.
