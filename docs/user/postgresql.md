# База данных на сервере PostgreSQL

Обычная база — файл `.db` на диске. Его достаточно для одного человека и небольшой
команды с общей сетевой папкой. Сервер PostgreSQL нужен, когда:

- одновременно пишут многие — сервер разводит их сам, без блокировки файла;
- общей сетевой папки нет, а база должна быть доступна всем;
- база должна жить на выделенном или виртуальном сервере.

Оба вида баз работают в программе одновременно и на равных: сайдбар, календарь,
задачи, перенос коллекций между базами — все как обычно.

> **Сервер устанавливается один раз** — администратором или вами самим по
> инструкции [[postgresql-server]]. Дальше все делается из программы: базу
> создает окно «Создать базу данных PostgreSQL», а адрес, имя базы и логин для
> коллег показывает кнопка «Данные подключения».

## Подключение

«Настройки → Управление базой данных» → **«Добавить базу данных»** →
**«Подключить сервер PostgreSQL»**.

| Поле | Что вписать |
|---|---|
| Сервер и порт | адрес сервера и порт (обычно 5432) |
| База данных | имя базы, созданной администратором |
| Пользователь | логин на сервере |
| Пароль | пароль этого логина |
| Шифрование (SSL) | «Отключено», «Если доступно» или «Обязательно» |
| Название в списке | как база будет называться в программе |

Кнопка **«Проверить соединение»** пробует подключиться и показывает результат
по-русски: неверный пароль, базы не существует, сервер не отвечает, подключение
запрещено настройками сервера. Кнопка **«Подключить»** делает ту же проверку
и добавляет базу в список.

Это окно подключает **существующую** базу. Если базы на сервере еще нет,
создайте ее соседним пунктом меню — **«Создать базу данных PostgreSQL»**: окно
заводит на сервере базу и роль-владельца с паролем, добавляет базу в список и
показывает сводку для коллег (см. [[postgresql-server]]). Таблицы внутри пустой
базы программа в обоих случаях строит сама при первом подключении.

## Пароль

Введенный пароль хранится защищенно штатными средствами системы: на Windows —
шифрованием вашей учетной записи (DPAPI), на macOS — в Связке ключей. На Linux
защищенного хранилища пока нет — пароль лежит в служебной базе программы открытым
текстом, учитывайте это на общих компьютерах. Отключение базы удаляет сохраненный
пароль.

## Как выглядит в списке баз

У серверной базы в «Управление базой данных» стоит метка **«PostgreSQL»**, второй
строкой — адрес вида `postgres://сервер:порт/база` (без пароля). Шестеренка в строке
открывает **настройки базы**: там кнопка **«Данные подключения»** (сервер, порт, база
и логин — сводку можно скопировать и передать коллеге; пароль в нее не входит,
сообщите его отдельно), живой статус сервера и смена сохраненного пароля
подключения — см. [[settings]].

Отключение убирает базу из программы, данные на сервере остаются нетронутыми.

## Права и пользователи

Допуск к базе, роли и права работают одинаково для файловых и серверных баз —
см. [[profile-access]]. Права хранятся внутри самой базы.
