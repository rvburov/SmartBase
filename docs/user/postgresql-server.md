# Сервер PostgreSQL: установка и доступ

Эта страница — для того, кто сам поднимает сервер: без ИТ-отдела и без опыта
администрирования. Сервер ставится один раз, дальше все делается из программы:
база создается окном (терминал не нужен), данные подключения для коллег
показывает кнопка в настройках. Как подключить уже готовую базу — [[postgresql]].

Подойдет PostgreSQL 14 или новее (проверено на 16).

## Помощник в программе

В окнах «Подключить сервер PostgreSQL» и «Создать базу данных PostgreSQL» есть
ссылка **«Нет сервера? Установка…»** — она открывает помощник:

- **«Сервер работает»** — порт отвечает, можно подключаться и создавать базы;
- **«Сервер установлен, но не запущен»** — программа нашла следы установки,
  запустите сервер по инструкции ниже;
- **«Сервер не найден»** — установите по инструкции ниже.

Кнопка «Скачать PostgreSQL» открывает официальную страницу загрузки для вашей
системы. Проверка идет по сетевому порту: сервер на нестандартном порту или в
docker-контейнере может показаться «не найденным» — впишите его порт в поле
помощника и нажмите «Проверить».

Если установка на этой машине найдена, в помощнике появляются кнопки
**«Запустить сервер»** и **«Остановить сервер»** — терминал не нужен:

- **macOS** — выполняется сразу (Homebrew или Postgres.app), без запросов;
- **Windows** — система покажет окно контроля учетных записей (UAC), это
  нормально: службами управляет только администратор;
- **Linux** — система спросит пароль (polkit); если графического запроса в
  вашем дистрибутиве нет, клик просто скопирует готовую команду
  (`sudo systemctl start postgresql`) — вставьте ее в терминал.

Итог виден по статусу: после запуска помощник сам перепроверяет порт. Подсказка
на кнопке показывает, какая именно команда будет выполнена.

## Установка: Windows

1. Скачайте установщик с официальной страницы (кнопка в помощнике) или выполните
   в PowerShell:

   ```powershell
   winget install PostgreSQL.PostgreSQL.16
   ```

2. **Установщик запросит права администратора** (окно UAC) — это нормально:
   сервер регистрируется как служба Windows. Самой программе SmartBase права
   администратора не нужны — она ставится и работает от обычного пользователя.
3. Во время установки задайте пароль пользователя `postgres` и запомните его —
   он понадобится при создании базы.
4. Готово: служба `postgresql-x64-16` работает в фоне и стартует вместе с
   Windows. Проверить можно в «Службах» (Win+R → `services.msc`) или командой
   `Get-Service postgresql*`.

## Установка: macOS

Через Homebrew (терминал):

```bash
brew install postgresql@16
brew services start postgresql@16
```

`brew services start` включает и работу в фоне, и автозапуск при входе в систему.

Без терминала: скачайте [Postgres.app](https://postgresapp.com) — сервер
запускается как обычное приложение, автозапуск включается галочкой в его
настройках. Пользователь по умолчанию в Postgres.app — имя вашей учетной записи
macOS (не `postgres`).

## Установка: Linux

```bash
# Debian/Ubuntu
sudo apt install postgresql

# Fedora/RHEL
sudo dnf install postgresql-server
sudo postgresql-setup --initdb
```

Запуск и автозапуск одной командой:

```bash
sudo systemctl enable --now postgresql
```

Команды требуют `sudo` — права администратора системы.

## Создать базу из программы

«Настройки → Управление базой данных» → **«Добавить базу данных»** →
**«Создать базу данных PostgreSQL»**. Терминал не нужен.

| Поле | Что вписать |
|---|---|
| Сервер и порт | где работает сервер (свой компьютер — `localhost`, порт обычно 5432) |
| Администратор сервера | `postgres` (пароль задан при установке) |
| Пароль администратора | его пароль |
| Имя новой базы данных | строчными латинскими, например `projects` |
| Роль-владелец | логин, которым будут подключаться к базе; по умолчанию — имя базы |
| Пароль роли | придумайте или нажмите «Сгенерировать» |
| Название в списке | как база будет называться в программе |

Окно создает на сервере базу и роль-владельца, проверяет, что этой ролью реально
можно подключиться, добавляет базу в список и сразу показывает **«Данные
подключения»** — сводку для коллег. Таблицы внутри пустой базы программа строит
сама при первом подключении; первый подключившийся становится администратором
базы ([[profile-access]]).

Пароль роли из окна нигде потом не показывается — скопируйте его сразу и
сохраните. Администратора (`postgres`) для повседневной работы не используйте:
подключайтесь ролью-владельцем.

## Дать доступ коллегам

Коллеге нужны четыре вещи: адрес сервера, порт, имя базы и логин с паролем.
Первые четыре показывает кнопка **«Данные подключения»** в настройках базы
(«Настройки → Управление базой данных» → шестеренка в строке); пароль сообщите
отдельно. Коллега вводит их у себя в окне «Подключить сервер PostgreSQL» —
см. [[postgresql]].

Если сервер и программа коллеги — на разных компьютерах, серверу нужно разрешить
подключения по сети (по умолчанию он слушает только свой компьютер):

1. Найдите файлы настроек — в psql выполните `SHOW config_file;` и `SHOW hba_file;`.
2. В `postgresql.conf` разрешите слушать сеть:

   ```
   listen_addresses = '*'
   ```

3. В `pg_hba.conf` добавьте строку для своей сети (пример для 192.168.1.0/24):

   ```
   host  all  all  192.168.1.0/24  scram-sha-256
   ```

4. Перезапустите сервер: Windows — `Restart-Service postgresql-x64-16` (PowerShell
   от имени администратора), macOS — `brew services restart postgresql@16`,
   Linux — `sudo systemctl restart postgresql`. Правку только `pg_hba.conf` можно
   применить без перезапуска: `SELECT pg_reload_conf();` в psql.
5. Откройте порт 5432 в файрволе компьютера с сервером. Windows (PowerShell от
   имени администратора):

   ```powershell
   New-NetFirewallRule -DisplayName "PostgreSQL" -Direction Inbound `
     -Protocol TCP -LocalPort 5432 -Action Allow
   ```

   Linux с ufw: `sudo ufw allow 5432/tcp`.

Для сервера в интернете — только через VPN либо SSL на сервере (`ssl = on` +
сертификат) и режим шифрования «Обязательно» в программе.

### Роли: одна общая или личные

Проще всего дать всем один логин — роль-владельца из окна создания: права внутри
программы (кто что видит и правит) все равно определяет профиль пользователя, а
не роль PostgreSQL ([[profile-access]]). Если нужны отдельные логины на сервере
(например, чтобы отзывать доступ по одному), администратор создает их в psql:

```sql
CREATE ROLE ivanov LOGIN PASSWORD 'пароль';
GRANT ALL ON DATABASE projects TO ivanov;
GRANT ALL ON SCHEMA public TO ivanov;
GRANT ALL ON ALL TABLES IN SCHEMA public TO ivanov;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO ivanov;
```

Отозвать доступ: `DROP ROLE ivanov;` (сначала `REVOKE`-команды или
`REASSIGN OWNED`, если роль что-то создавала).

## Резервная копия

Кнопка «Резервная копия…» в настройках работает только для файловых баз —
серверную копирует штатная утилита сервера:

```bash
pg_dump -h localhost -p 5432 -U projects -F c -f projects.backup projects
```

Восстановление в пустую базу:

```bash
pg_restore -h localhost -p 5432 -U postgres -d projects projects.backup
```

На Windows обе утилиты лежат рядом с сервером:
`C:\Program Files\PostgreSQL\16\bin\`. Делайте копию по расписанию — сервер сам
себя не бэкапит.

## Если что-то не работает

- **Жив ли сервер:** `pg_isready -h localhost -p 5432` — ответ
  `accepting connections` значит «работает». Помощник в программе показывает то
  же самое проще.
- **Служба не стартует / порт занят:** возможно, порт 5432 занят другим сервером
  PostgreSQL (или другой программой). Либо остановите его, либо ставьте на другой
  порт — программа поддерживает любой, впишите его в поле «Сервер и порт».
- **Логи сервера:** Windows — `C:\Program Files\PostgreSQL\16\data\log\`;
  Homebrew — `/opt/homebrew/var/log/postgresql@16.log`; Linux —
  `sudo journalctl -u postgresql` или `/var/log/postgresql/`.
- **«Сервер отклонил подключение (pg_hba.conf)»** у коллеги — нет разрешающей
  строки для его адреса, см. «Дать доступ коллегам» выше.
- **Сервер в docker-контейнере** помощник по каталогам не находит — это нормально,
  проверяйте его по порту.
