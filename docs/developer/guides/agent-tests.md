# Проверка веток агентов на GitHub

Модульные тесты и тесты расширений на Linux для каждой ветки, отправленной на GitHub, и каждого
PR в `main`. Запускается сам — в отличие от [полной проверки](ci.md), которую запускают по команде.

## Зачем

ИИ-агенты (облачные копии и рабочие папки на компьютерах) отправляют свои ветки на GitHub, а в
`main` идут только перемоткой — правила в [AGENTS.md](../../../AGENTS.md). Тесты агент гоняет
сам, но «агент сказал, что проверил» — не то же, что проверка на чистой машине. Этот прогон дает
серверное подтверждение:

- перед отправкой в `main` агент смотрит, что проверка его ветки зеленая;
- у PR («сделай через PR») результат виден прямо в PR — сливать красный PR не нужно.

## Где в коде

| Файл | Роль |
|---|---|
| [.github/workflows/agent-tests.yml](../../../.github/workflows/agent-tests.yml) | сам прогон: один job на `ubuntu-latest` |
| `docs/developer/guides/agent-tests.md` | этот файл |

## Когда запускается

| Событие | Запуск |
|---|---|
| push любой ветки, кроме `main` и `ci` | да |
| PR в `main` (открыт или обновлен) | да |
| кнопка **Run workflow** на вкладке Actions | да |
| push `main` | нет — туда приходят уже проверенные коммиты |
| push ветки `ci` | нет — это [полная проверка](ci.md) |
| push тега `v*` | нет — это [выпуск](release.md) |

Push ветки и ее PR — два события на один код: прогон один (группа `concurrency` по имени ветки),
новый push отменяет недоделанный старый.

## Какие проверки идут

1. `dotnet test Tests/Unit --configuration Release`.
2. `bash Tests/run-extensions.sh --configuration Release` — по проекту на расширение.

Культура — `LANG=ru_RU.UTF-8`, как у пользователей: тесты форматирования ждут запятую в числах.

Не входят: интеграционные тесты с PostgreSQL, другие ОС, стенды интерфейса — это
[полная проверка](ci.md) и `./Tests/run-all.sh` локально.

## Сколько это стоит

Около пяти минут на Linux. Публичный репозиторий — бесплатно; для приватного — минуты бесплатного
тарифа (2000 в месяц, множитель Linux ×1).

## Если прогон покраснел

1. **Actions** → **Agent tests** → красная строка → шаг: в логе имена упавших тестов.
2. Повторить локально той же командой.
3. Агент красное в `main` не отправляет — чинит в своей ветке и отправляет ветку снова.

## Как удалить

```bash
rm .github/workflows/agent-tests.yml docs/developer/guides/agent-tests.md
```

и убрать строку из [docs/README.md](../../README.md) и упоминание в AGENTS.md. Полная проверка и
выпуск не задеваются: общих файлов и триггеров нет.
