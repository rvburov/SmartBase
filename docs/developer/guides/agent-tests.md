# Быстрая проверка веток агентов

Unit и тесты расширений на Linux выполняются в общем workflow **«Проверки»**, файл
[build.yml](../../../.github/workflows/build.yml), job `agent-tests` (**«Unit и расширения (Linux)»**).
Отдельный workflow `agent-tests.yml` удален: быстрый и полный профили используют один итоговый гейт.

## Перед переносом в main

После push своей ветки агент дожидается успешного прогона **«Проверки» именно для полного SHA
последнего коммита**. Зеленый старый коммит или только успешный Unit-шаг этого не заменяют.
Правила коммита и переноса находятся в [AGENTS.md](../../../AGENTS.md).

Push любой ветки, кроме `main`, запускает общий workflow. Агентская ветка получает быстрый
профиль; `ci` — полный. PR в `main` также получает быстрый профиль. Обычный push `main` не запускает
проверку повторно. Push тега обрабатывает Release, вызывая полный профиль для проверенного SHA тега.

## Что выполняется

1. `dotnet test Tests/Unit --configuration Release`.
2. `bash Tests/run-extensions.sh --configuration Release` — все наборы `Tests/Extensions/*`.
3. **«Итог проверок»** — обязательные jobs должны завершиться успешно.

Культура — `LANG=ru_RU.UTF-8`, как в пользовательских проверках форматирования. Новый push
отменяет предыдущую проверку той же ветки; исходный репозиторий fork входит в ключ concurrency.

Другие ОС, Integration с живым PostgreSQL, нативные `pg_dump`/`pg_restore`, закрытые конфигурации
и стенд чтения входят в [полный профиль](ci.md). **Run workflow** запускает его вручную.

## Если проверка красная

Откройте **Actions → Проверки → нужный SHA → job → шаг**. Повторите команду локально, исправьте
причину и отправьте новый коммит своей ветки. После новой отправки требуется новый зеленый итог;
красный или отмененный прогон не разрешает отправку в `main`.
