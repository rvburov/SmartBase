# Автообновление приложения (план / ТЗ)

Статус: **готово для Windows, Linux и macOS** (этапы 1–6). Проверка версии/даты, загрузка
с прогрессом, самозамена (`--apply-update`), установщик install/uninstall (вариант A — та же
раздача под именем `SmartBase-Setup[.exe|.app]`). macOS реализован, но **не протестирован на
устройстве** (собираю/проверяю не на Mac).

## Цель

Пользователь, которому раздали приложение, может из раздела **«О программе» →
«Обновления»** проверить наличие новой версии и обновиться: приложение закрывается,
`.exe` перезаписывается новым и приложение снова открывается. Плюс единый
установщик/удалятор.

## Принятые решения

| Вопрос              | Решение                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Источник обновлений | **Сетевая/файловая папка** (`\\server\share\…` или диск `Z:\`). Версию читаем прямо из удалённого `.exe` (`FileVersionInfo`) — без скачивания.                                                           |
| Модель установки    | **Установленное приложение, вариант A**: тот же бинарь под именем `SmartBase-Setup.exe` ставит в `%LOCALAPPDATA%\SmartBase` (+ ярлыки, запись в «Приложения и возможности»), умеет install/update/uninstall. Раздаётся одним файлом, +0 МБ. |
| Путь к обновлению   | Хранится в `app.db` (ключ `UpdatePath`), **пустой по умолчанию** — пользователь вводит сам, сохраняется.                                                                                                 |
| Имя файла в папке   | `SmartBase-Setup.exe` (один файл на сервере — и установщик, и обновление); если его нет — берётся `SmartBase.exe`. Обновляешь новой сборкой.                                                                 |
| Права               | Установка в `%LOCALAPPDATA%` → **UAC не нужен**.                                                                                                                                                         |

## Установщик лежит рядом с приложением

С 1.0.5 установка кладёт установщик **в ту же папку**, что и приложение: `SmartBase.app`
и `SmartBase-Setup.app` (на Windows/Linux — `SmartBase[.exe]` и `SmartBase-Setup[.exe]`).
Это одна и та же программа: режим выбирается по имени, см. `Program.ResolveMode`.

Зачем: одна точка входа на установку, обновление и удаление. Отдельного деинсталлятора
больше нет — на macOS исчез `Uninstall SmartBase.command`, который открывался через
Terminal и выглядел чужеродно рядом с приложением.

Цена — вторая копия бинаря: на macOS это примерно +145 МБ к установке. Решение осознанное,
принято владельцем: одна понятная программа важнее места на диске.

Окно установщика само ищет установленные копии, поэтому путь не надо помнить —
см. [InstallService.Discovery.cs](../../../Setup/InstallService.Discovery.cs). Источники по
убыванию надёжности: `installs.json` в папке данных (пишется при установке), затем штатные
записи ОС (реестр Windows, `.desktop` на Linux, Spotlight по `CFBundleIdentifier` на macOS),
затем обычные места. Полного обхода диска нет: на большом томе это минуты. Результаты
Spotlight фильтруются — бандл в `dist/`, в Корзине и на смонтированном образе установкой
не является.

Удаление снимает: приложение, установщик, автозапуск (`Autostart.Disable`), регистрацию в
ОС, запись в `installs.json` и — только по галочке — папку данных. Базы вне папки данных
и на сервере PostgreSQL не трогаются никогда.

**Сохранность чужих файлов** — под тестами. `RemoveOwnedFilesAndPrune` удаляет строго
перечисленное в `OwnedInstallFiles` и сносит саму папку, лишь если после этого она пуста.
[Tests/Unit/InstallServiceTests.cs](../../../Tests/Unit/InstallServiceTests.cs) проверяет
сценарий «поставили в общую папку»: рядом кладутся посторонний документ, вложенная папка с
файлом и файл с похожим именем — после удаления они на месте, а папка цела. Отдельно
проверено, что список своих файлов не выходит за пределы папки установки. Тесты бьют по
`RemoveOwnedFilesAndPrune`, а не по `Uninstall` целиком: последний снимает автозапуск и
удаляет ярлыки меню, то есть вызов из теста испортил бы машину, на которой он идёт.

## Архитектура: две программы

1. **`SmartBase.exe`** — приложение. В «О программе» раздел «Обновления»: поле пути +
   кнопка «Проверить». **Самозамену делает само приложение**: новый `.exe` запускается
   в режиме `--apply-update` (ждёт выхода старого процесса, копирует себя поверх,
   перезапускает) — отдельный процесс-помощник для апдейта не нужен.
2. **`SmartBase-Setup.exe`** — **тот же бинарь** под именем `…-Setup` (по имени файла
   включается режим установщика). GUI на Avalonia ([Setup/InstallerWindow](../../../Setup/InstallerWindow.axaml)):
   установка/обновление в `%LOCALAPPDATA%\SmartBase`, ярлыки, `--uninstall`. Логика —
   [Setup/InstallService.cs](../../../Setup/InstallService.cs). Нужен для первичной установки и
   удаления; обновление работает и без него.

## Потоки

### Установка (первый раз)
1. Пользователь скачивает и запускает `SmartBase-Setup.exe` (по имени `-Setup` открывается
   окно установки).
2. Выбор папки (по умолчанию `%LOCALAPPDATA%\SmartBase`) → бинарь **копирует себя** туда
   под именем `SmartBase.exe`, создаёт ярлыки (рабочий стол + Пуск + папка установки,
   включая «Uninstall SmartBase»), регистрирует в «Параметры → Приложения».
   Любой выбранный путь — и через «Обзор», и **вписанный руками** — приводится к
   «выделенной» подпапке `…\SmartBase` (`EnsureDedicatedDir`), если её ещё нет. Иначе бинарь
   лёг бы прямо в «Документы», а удаление потом искало бы свои файлы посреди чужих. До 1.0.5
   правило действовало только на «Обзор», и вписанный вручную путь его обходил. Когда путь
   будет изменён, окно показывает это заранее строкой «Будет установлено в: …».
   На macOS не применяется: единица — `.app`-бандл в `~/Applications`.

   Правило не срабатывает, если папка уже называется по имени приложения или уже содержит
   установленную копию, — иначе обновление уводило бы установку на уровень глубже и рядом
   появлялась бы вторая копия.

### Проверить обновление
1. В «Обновления» введён путь к папке (напр. `\\server\share\SmartBase`), сохранён в `app.db`.
2. Кнопка «Проверить» → берём `<UpdatePath>\SmartBase-Setup.exe` (или `SmartBase.exe`, если Setup нет).
3. Проверяем доступность папки/файла **в фоне**; если недоступно — красное уведомление (без таймаута).
4. `FileVersionInfo.GetVersionInfo(remote).FileVersion` → сравниваем с текущей
   (`Assembly.GetExecutingAssembly().GetName().Version`). **При равной версии** (можно
   раздавать сборки без смены версии) — сравниваем сам файл: другой **размер** = новая сборка
   (дёшево, надёжнее даты), иначе — **дата изменения** новее на сервере (допуск 2 с).
5. Новее → модалка: «Доступна версия X.Y.Z…» (или «Доступна новая сборка приложения…» при
   равной версии). [Отмена] [Обновить]. Иначе → «У вас актуальная версия».

Тумблер **«Автообновление»** (там же, ключ `autoUpdate` в `app.db`, по умолчанию выключен):
при запуске приложения та же проверка выполняется автоматически (после открытия окна, в фоне).
Есть обновление → та же модалка [Отмена] [Обновить]; путь пуст / папка недоступна / версия
актуальна → **тихо**, без окон и уведомлений (результат виден в строке статуса, если открыть
настройки).

#### Автопроверка и тихий старт из автозапуска (`--background`)

Модалке «Обновить/Отмена» нужен **видимый** владелец: `ShowDialog(owner)` со скрытым окном
бросает `InvalidOperationException: Cannot show window with non-visible owner`. При тихом старте
([[../features/autostart-background]]) окно скрывается сразу после `Show()`, а автопроверка уходит
в сеть и возвращается на UI-поток уже к скрытому окну — раньше это валило приложение крэш-окном
при входе в систему (у тех, у кого совпали автозапуск + фоновый режим + доступное обновление).
Сейчас:

- **Обычный старт** — проверка сразу в `MainWindow.Opened`, как и была.
- **Тихий старт** (`Program.LaunchBackground`) — `MainWindow.CheckUpdatesWhenShown()` подписывается
  на `IsVisible` и запускает проверку **один раз**, когда окно реально показали (трей «Открыть»,
  клик по значку/уведомлению, повторный запуск). Пока приложение живёт в трее, обновление не
  предлагается — перезапуск подтверждают, когда человек сам открыл окно.
- **Страховка** — `StartUpdateAsync` перед модалкой поднимает окно, если оно невидимо
  (`Show()` + `Activate()`): окно могли убрать в трей, пока шла проверка сетевой папки.
- `CheckForUpdatesOnStartupAsync` **не бросает** — тело в `try/catch` с `Log.Error` и красной
  строкой статуса. Вызов идёт из `async void`-обработчика `Opened`, откуда исключение уходит
  прямо в диспетчер и превращается в крэш вместо тихого старта.

### Обновить
1. Подтверждение в модалке: «Доступна версия X… [Обновить] [Отмена]».
2. Приложение копирует найденный файл (`SmartBase-Setup.exe`/`SmartBase.exe`) во временный файл
   (`%TEMP%\SmartBase.update.exe`) — **в отдельном окне загрузки с процентами**
   (`ProgressDialog`, как при импорте; закрыть его вручную нельзя, тяжёлая часть:
   122 МБ по сети). Проверка: скопировано целиком (размер совпал), а на Windows — ещё и версия
   скачанного файла **не старее** текущей (файл в папке мог смениться между проверкой и
   загрузкой); иначе обновление отменяется с красным уведомлением.
3. Запуск нового `.exe`: `SmartBase.update.exe --apply-update --target <текущий .exe> --pid <pid>`.
4. Приложение **закрывается**.
5. Новый `.exe` ждёт выхода старого (по `--pid`) → копирует себя поверх `--target`
   → **приводит окружение в соответствие** (`InstallService.RefreshAfterUpdate`: ярлыки,
   установщик рядом, запись в списке приложений, кеш иконок оболочки — см. ниже)
   (с повторами при блокировке) → запускает обновлённое приложение → выходит. Если замена так
   и не удалась (файл всё время занят), новый `.exe` перезапускает **старую** версию с флагом
   `--update-failed` → приложение показывает разовое уведомление «Обновление не удалось
   применить…», а не молчит, оставив пользователя в неведении.

> Залежавшийся `%TEMP%\SmartBase.update.exe` (≈122 МБ) убирается при следующем обычном старте
> приложения (`InstallService.CleanStaleUpdateArtifacts`, фоном).

> Прогресс-индикатор показывает **копирование из сети в temp** (в приложении). Сама
> замена локальным `File.Copy` — быстрая; её делает уже новый `.exe` без окна, пока
> старый закрыт.

### Удаление
Ярлык «Удалить SmartBase» (= `SmartBase.exe --uninstall`) → окно подтверждения → удаляет
ярлыки и **свои файлы** в папке установки, затем убирает саму папку **только если она
осталась пустой** (`rmdir` без `/S` / `RemoveOwnedFilesAndPrune`) — если приложение
поставили в общую папку с чужим содержимым, оно не пострадает. На Windows папку запущенного
`.exe` чистит **отложенный bat**: ждёт освобождения `.exe` → удаляет свои файлы →
`rmdir` пустой папки → удаляет себя. Данные в `%APPDATA%` — по галочке «удалить и данные»
(по умолчанию **сохранить**).

## Обновление меняет не только бинарь

До 1.0.5 обновление заменяло ровно один файл — сам `SmartBase[.exe]`. Всё, что установщик
создал вокруг него, оставалось от прежней сборки, и это вылезало как **«иконка не
поменялась»**: ярлык `.lnk` не менялся ни байтом, поэтому Проводник продолжал отдавать
запомненный значок, а `SmartBase-Setup.exe` рядом, `icon.png` на Linux и версия в «Параметры →
Приложения» устаревали по-настоящему, уже без всякого кеша.

Теперь после удачной замены вызывается `InstallService.RefreshAfterUpdate`
([InstallService.ShellIcons.cs](../../../Setup/InstallService.ShellIcons.cs)). Она **ничего не
создаёт заново** — обновляет только то, что уже есть на месте: обновление не должно возвращать
ярлык, который человек удалил, и не должно записывать в список приложений портативную копию.

| Что делает | Windows | Linux | macOS |
| --- | --- | --- | --- |
| Установщик рядом | перезапись `SmartBase-Setup.exe`, если он там был | то же | копия бандла |
| Ярлыки | перезапись всех `.lnk`, ведущих на наш `.exe`, — Пуск, рабочий стол, папка установки и **закреплённые на панели задач** | перезапись существующих `.desktop` + новый `icon.png` | — |
| Регистрация | `DisplayVersion`/`DisplayIcon`, но только если запись уже есть | `update-desktop-database` | `lsregister -f` |
| Кеш иконок | `SHChangeNotify` + `ie4uinit -show`/`-ClearIconCache` | — | перерегистрация бандла |

Вызов идёт из режима `--apply-update`, то есть кодом уже **новой** сборки — правка работает на
том самом обновлении, которым приезжает, и чинить установленные копии отдельным выпуском не
нужно. Что делать на машине, которая обновилась раньше, — в
[icons.md](../features/icons.md#если-иконка-уже-застряла).

## Нюансы и их решения

| Нюанс                                       | Решение                                                                             |
| ------------------------------------------- | ----------------------------------------------------------------------------------- |
| Запущенный `.exe` нельзя перезаписать собой | Замену делает **новый** `.exe` в режиме `--apply-update`, пока старый закрыт |
| После обновления оболочка показывает старую иконку | Ярлык не менялся → Проводник отдаёт значок из кеша. `RefreshAfterUpdate` перезаписывает ярлыки (включая закреплённые) и сбрасывает кеш через `SHChangeNotify` + `ie4uinit`. Сноса `iconcache_*.db` с перезапуском `explorer.exe` в коде нет намеренно: это закрыло бы окна Проводника |
| Обход ярлыков упирается в недоступную сеть  | Чтение цели ярлыка на отключённую шару ждёт таймаута SMB → обход идёт с ограничением 30 с (`RunHidden(..., timeoutMs)`), иначе приложение не перезапустилось бы после обновления |
| UAC                                         | Не нужен — установка в `%LOCALAPPDATA%`                                             |
| Защищённая папка (Program Files, корень)    | Проверка прав на запись (`CanCreateOrWrite`): при установке — жёлтая плашка «нет прав на запись…» + кнопка «Установить» заблокирована; при обновлении — красная строка «Обновление невозможно: нет прав…», приложение не закрывается (иначе самозамена молча не срабатывала) |
| Спецсимволы в пути (`'`, `%`, `$`, `` ` ``) | Путь/имя пользователя подставляются в скрипты с экранированием под каждую «границу»: PowerShell `'`→`''` (`PsQuote` — ярлыки `.lnk` и реестр), `.bat` `%`→`%%` (`BatEscape` — удаление), bash `ShQuote` и `.desktop` `Exec` (`DesktopExecQuote`) на Linux/macOS. Логин вида `O'Brien` больше не ломает ярлыки |
| Битая копия при обрыве сети                 | Сначала в temp → проверка **размера** (скопировано целиком) + на Windows версия не старее текущей → только потом замена |
| Самозамена не удалась (файл занят/AV)       | `ReplaceArtifact` возвращает `false` после всех попыток → апдейтер перезапускает старую версию с `--update-failed` → разовое окно-уведомление «Обновление не удалось применить…» (версия осталась прежней) |
| Как узнать версию в папке без скачивания    | `FileVersionInfo` удалённого `.exe` (работает по SMB/диску)                         |
| Путь недоступен (нет VPN/сервера)           | Красное уведомление (как «файл недоступен» в «Управлении БД»); проверка в фоне, без таймаута |
| Окно скрыто, а модалке нужен владелец       | При тихом старте (`--background`) автопроверка ждёт первого показа окна (`CheckUpdatesWhenShown`, один раз за сессию); `StartUpdateAsync` перед модалкой поднимает скрытое окно; `CheckForUpdatesOnStartupAsync` не бросает. Иначе — `Cannot show window with non-visible owner` при входе в систему |
| Антивирус/SmartScreen                       | Неподписанный `.exe` → предупреждение; подпись кода — опц. на будущее               |
| Критерий «новее»                            | Версия больше → обновить; при **равной версии** — другой размер файла (надёжно, без смены версии) ИЛИ дата изменения новее (допуск 2 с). После штатного обновления размер == серверному, а дата = времени загрузки → ложных срабатываний нет |
| Версия файла на Linux/macOS                 | `FileVersionInfo` не читает версию из нативного бинаря → на Linux/macOS сравнение **только по дате изменения** (на Windows — версия из PE, дата как запасной критерий) |
| macOS: бандл, а не файл                      | publish под mac **не** single-file → установка/обновление работают с `.app`-бандлом целиком (рекурсивное копирование), а не подменой одного файла |
| Кроссплатформенность                        | Все три ОС разведены в [InstallService](../../../Setup/InstallService.cs) (`OperatingSystem.IsWindows()/IsLinux()/IsMacOS()`) |

## Упаковка установщика (решено: вариант A)

Выбран **вариант A — тот же `.exe`**: бинарь `SmartBase-Setup.exe` (копия `SmartBase.exe`)
включает режим установщика по имени файла. Один файл раздачи, +0 МБ, GUI на Avalonia
в едином стиле, обычный запуск приложения не меняется. Альтернатива (отдельный
self-contained установщик ~120 МБ) отклонена из-за удвоения размера раздачи.

## Этапы реализации (по частям)

1. ✅ **Настройка пути.** Ключ `UpdatePath` в `app.db`; раздел «Обновления» в «О программе».
2. ✅ **Проверка версии.** `FileVersionInfo` по пути, сравнение, уведомления (фон, без таймаута).
3. ✅ **Загрузка + самозамена.** Сеть → temp с прогрессом, проверка целостности (размер),
   модалка «Обновить/Отмена», `--apply-update` (новый `.exe` заменяет старый и перезапускает).
4. ✅ **Установщик (вариант A).** Тот же `.exe` в режиме install/uninstall: окно на
   Avalonia, копия в `%LOCALAPPDATA%\SmartBase`, ярлыки (рабочий стол + Пуск + папка),
   регистрация в «Параметры → Приложения» (HKCU\…\Uninstall), самоудаление через отложенный bat.
5. ✅ **Сборка установщика.** `windows-build.sh` / `linux-build.sh` кладут `SmartBase-Setup[.exe]` рядом с приложением.
   Плюс ✅ **автопроверка при запуске**: тумблер «Автообновление» в «О программе → Обновления»
   (ключ `autoUpdate` в `app.db`, выключен по умолчанию) — при старте тихая проверка папки,
   при наличии обновления та же модалка «Обновить/Отмена».
6. **Кроссплатформенность.**
   - ✅ **6a — Linux.** Ярлыки `.desktop` в `~/.local/share/applications` (меню = регистрация,
     реестра нет), иконка из вшитого ресурса в папку установки, бит `+x` (`chmod`/`SetUnixFileMode`),
     самозамена и удаление каталога **сразу** (на Unix файл запущенного бинаря можно unlink на ходу —
     отложенный `.bat` не нужен). Версия файла — по дате изменения (`FileVersionInfo` для ELF не работает).
     Установка в `~/.local/share/SmartBase`, данные — в `~/.config/SmartBase`.
   - ✅ **6b — macOS** (реализовано, не протестировано на устройстве). Единица — `.app`-бандл:
     установщик `SmartBase-Setup.app` (режим по имени бандла, внутренний бинарь остаётся `SmartBase`)
     копирует бандл в `~/Applications/SmartBase.app`, регистрирует в Launchpad/Finder (`lsregister`),
     кладёт рядом второй бандл `SmartBase-Setup.app` (см. ниже). Обновление/самозамена работают **с бандлом целиком**
     (publish не single-file): загрузка дерева в `/tmp/SmartBase.update.app`, замена установленного
     бандла, перезапуск через `open`. Сравнение версий — по дате внутреннего бинаря.
     Данные — `~/.config/SmartBase`. Каверзы: Gatekeeper/quarantine при ручном скачивании из браузера
     (копии по SMB/File API без quarantine — ок); ad-hoc подпись `dotnet publish` при подмене сохраняется;
     нотаризация/полноценная подпись — на будущее.
