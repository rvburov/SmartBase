# PostgreSQL: установка сервера и подключение базы

Пошаговое руководство администратора: поднять сервер PostgreSQL, создать пустую
базу и подключить ее в приложении. Как PG-ветка устроена внутри —
[../architecture/database/storage-and-migrations.md](../architecture/database/storage-and-migrations.md),
раздел «Провайдеры». Человеческая версия для пользователей без опыта
администрирования — [../../user/postgresql-server.md](../../user/postgresql-server.md):
она поставляется внутри приложения (раздел «Руководство») и канонична для
установки по ОС и раздачи доступов; здесь остаются докер, стенд и специфика
крупных развертываний.

> **Порты: 5432 и 5455.** Все примеры этого гайда — про боевой сервер на штатном
> порту **5432**. Тестовый стенд `sb-pg` из [../testing/automated-tests.md](../testing/automated-tests.md)
> нарочно живет на **5455**, чтобы не конфликтовать с настоящим PostgreSQL на
> машине разработчика; CI пробрасывает сервис-контейнер на тот же 5455 — тесты
> не знают разницы.

## Когда нужен PostgreSQL

Файловой SQLite-базы (в том числе общей в сетевой папке) хватает небольшой команде.
PostgreSQL нужен, когда одновременно пишущих пользователей много (конкурентную
запись сериализует MVCC сервера, а не блокировка файла), когда общей сетевой папки
нет или база должна жить на выделенном/виртуальном сервере. Оба вида баз работают
в приложении одновременно и на равных: сайдбар, календарь, переносы коллекций
между базами (в том числе SQLite ↔ PostgreSQL).

Подойдет PostgreSQL 14 или новее (проверено на 16).

## Шаг 1 — установить сервер

Выберите один вариант. Во всех вариантах сервер работает **в фоне** (служба, окно
держать не нужно) и **стартует сам при включении компьютера** — команды для этого
приведены в каждом варианте.

**Docker (любая ОС):**

```bash
docker run --name smartbase-pg \
  -e POSTGRES_PASSWORD=strong-password \
  -p 5432:5432 \
  -v smartbase-pg-data:/var/lib/postgresql/data \
  --restart unless-stopped \
  -d postgres:16
```

- `-d` — контейнер работает в фоне; `--restart unless-stopped` — поднимается сам
  вместе с Docker после перезагрузки (для уже созданного контейнера:
  `docker update --restart unless-stopped smartbase-pg`).
- Автозапуск самого Docker: Docker Desktop — галочка «Start Docker Desktop when
  you sign in» в настройках; colima на macOS — `brew services start colima`.
- Управление: `docker stop smartbase-pg` / `docker start smartbase-pg`; статус —
  `docker ps`; консоль — `docker exec -it smartbase-pg psql -U postgres`.
- `-v` сохраняет данные при пересоздании контейнера.

**Обычная установка (Windows / macOS / Linux)** — пошагово в
[../../user/postgresql-server.md](../../user/postgresql-server.md) (канонический
текст, поставляется в приложении). Коротко: Windows — установщик EDB или
`winget install PostgreSQL.PostgreSQL.16` (PowerShell от имени администратора;
для тихой установки — `--override "--mode unattended --superpassword …"`), служба
`postgresql-x64-16`; macOS — `brew install postgresql@16` +
`brew services start postgresql@16` или Postgres.app; Linux — `apt`/`dnf` +
`sudo systemctl enable --now postgresql`.

В самом приложении есть окно-помощник (ссылка «Нет сервера? Установка…» в окнах
подключения и создания базы): TCP-проба порта + инструкция для текущей ОС
(`Utils/PgServerProbe`, `Controls/Dialogs/PgServerHelpDialog`) и кнопки
«Запустить/Остановить сервер» для найденной локальной установки
(`Utils/PgServerControl`: brew services / net start под UAC / systemctl через
polkit; фолбэк — копия команды в буфер).

## Шаг 2 — создать пользователя и пустую базу

Два равнозначных пути; схему (таблицы, индексы) внутри пустой базы приложение в
обоих случаях построит само при первом подключении.

**Из приложения (основной путь):** Настройки → «Управление базой данных» →
«Добавить базу данных» → **«Создать базу данных PostgreSQL»**. Окно подключается
администратором к служебной базе `postgres`, создает роль-владельца и базу
(`Database/PgDatabaseCreator`: DDL квотирует сам сервер через
`format('%I'/'%L')`), проверяет вход новой ролью и регистрирует базу в реестре.
Существующая роль переиспользуется (пароль не меняется), роль-сирота после
неудачного `CREATE DATABASE` подчищается.

**В psql (ручной путь администратора):** под суперпользователем `postgres`:

```sql
CREATE ROLE smartbase LOGIN PASSWORD 'сильный-пароль';
CREATE DATABASE smartbase OWNER smartbase;
```

- Имена `smartbase` здесь — примеры, назовите как удобно.
- `OWNER` обязателен: схему может строить владелец базы. Начиная с PostgreSQL 15
  писать в схему `public` по умолчанию может только владелец, поэтому роль без
  владения схему создать не сможет. Окно создания делает то же самое.
- Одна такая база = одна строка в списке баз приложения. Нужна вторая независимая
  база — еще один `CREATE DATABASE` на том же сервере.

## Шаг 3 — открыть доступ по сети

Пропустите, если сервер на том же компьютере, что и приложение (подключение по
`localhost`). Docker с `-p 5432:5432` сетевые подключения уже принимает — останется
только файрвол.

Полная пошаговая версия с командами по ОС — [../../user/postgresql-server.md](../../user/postgresql-server.md),
раздел «Дать доступ коллегам». Суть (пути к файлам покажут `SHOW config_file;` и
`SHOW hba_file;` в psql): `listen_addresses = '*'` в `postgresql.conf`,
разрешающая строка `host all all <подсеть> scram-sha-256` в `pg_hba.conf`
(правку только hba применяет `SELECT pg_reload_conf();` без перезапуска),
открытый входящий TCP 5432 в файрволе. Для сервера в интернете — VPN либо SSL
(`ssl = on` + сертификат) и режим шифрования «Обязательно» в приложении.

## Шаг 4 — подключить базу в приложении

Настройки → **Управление базой данных** → «Добавить базу данных» →
**«Подключить сервер PostgreSQL»**. Поля окна:

| Поле                         | Что вводить                                                                                           | Пример              |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------- |
| Сервер и порт         | адрес машины с сервером и порт                                                         | `localhost` · `5432` |
| База данных            | имя базы из`CREATE DATABASE`                                                                         | `smartbase`             |
| Пользователь         | роль из`CREATE ROLE`                                                                                    | `smartbase`             |
| Пароль                     | пароль этой роли                                                                                  |                           |
| Шифрование (SSL)       | «Если доступно» — обычно; «Обязательно» — сервер в интернете |                           |
| Название в списке | имя базы в приложении; пусто = имя базы на сервере                       |                           |

Адрес сервера: тот же компьютер — `localhost`; сервер в локальной сети — его IP
(например `192.168.1.50`) или имя хоста; удаленный сервер — публичный адрес или
домен.

Нажмите **«Проверить соединение»** — приложение откроет пробное подключение
(таймаут 5 с) и покажет версию сервера («Соединение установлено (PostgreSQL 16.3)»).
«Подключить» прогоняет ту же пробу — с нерабочими параметрами база в список не
попадет. Пара сервер+порт+база, уже существующая в списке, дает «уже подключена».

Дальше база монтируется в фоне, как и файловые: при первом монтировании создается
схема и текущий участник регистрируется в справочнике имен базы
([../architecture/users-permissions.md](../architecture/users-permissions.md)).
В списке баз у серверных строк бейдж «PostgreSQL», второй строкой — адрес
`postgres://сервер:порт/база`.

## Если подключиться не удалось

Окно показывает русское описание типовых ошибок:

| Сообщение                                                                                                             | Причина и что делать                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| «Неверный пароль или пользователь»                                                              | опечатка в пароле или имени роли; сверьте с`CREATE ROLE … LOGIN PASSWORD`                                    |
| «База данных не найдена на сервере»                                                              | базы нет или опечатка в имени — создайте ее пунктом меню «Создать базу данных PostgreSQL»                                                            |
| «Сервер отклонил подключение — проверьте настройки доступа (pg_hba.conf)» | нет разрешающей строки для вашего адреса — шаг 3, п. 2                                                     |
| «Сервер недоступен — проверьте адрес, порт и сеть»                                   | сервер не запущен, неверный адрес/порт, закрыт файрвол или`listen_addresses` не менялся |
| «Не удалось установить защищенное соединение»                                         | режим SSL не совпадает с настройкой сервера — попробуйте другой режим                      |

## Совместная работа

Все пользователи вводят одни и те же сервер/порт/базу (роль PostgreSQL может быть
общей; сервер применяет права подключенной роли PostgreSQL).
Чужие изменения видны без перезапуска: журнал изменений опрашивается раз в ~3 с.
Внутренних допусков, ролей и пароля SmartBase больше нет. Пользователи регистрируются
для авторства и задач; ограничения задает подключенная роль PostgreSQL на сервере.

Если сервер пропал (сеть, перезагрузка), строка базы краснеет «недоступна…», узел
в сайдбаре сменяется заглушкой, а после восстановления база оживает сама.
Отключение базы в настройках **не удаляет данные на сервере**.

## Крупные развертывания: PgBouncer

Каждое приложение держит до 16 подключений (простаивающие закрываются сами), у
сервера же есть потолок `max_connections` (по умолчанию 100). Десятки одновременных
приложений стандартный сервер обслуживает спокойно; при переполнении новые клиенты
получают отказ «too many clients» — приложение покажет такую базу как недоступную
и будет само переподключаться с нарастающей паузой. Когда одновременных приложений
сотни, между ними и сервером ставят пул подключений **PgBouncer** (на той же
машине, что и сервер):

```bash
sudo apt install pgbouncer
```

`/etc/pgbouncer/pgbouncer.ini`:

```ini
[databases]
smartbase = host=127.0.0.1 port=5432 dbname=smartbase

[pgbouncer]
listen_addr = *
listen_port = 6432
auth_type = scram-sha-256
auth_file = /etc/pgbouncer/userlist.txt
pool_mode = session
default_pool_size = 50
max_client_conn = 1000
```

Важно: `pool_mode = session`, **не** `transaction` — приложение использует
подготовленные команды, транзакционный пул их ломает.

`/etc/pgbouncer/userlist.txt` — строка `"роль" "SCRAM-верификатор"`; верификатор
покажет сервер:

```sql
SELECT usename, passwd FROM pg_shadow WHERE usename = 'smartbase';
```

Запуск: `sudo systemctl enable --now pgbouncer`. В приложении при подключении
меняется только **порт**: 6432 вместо 5432 — все остальное (база, роль, пароль)
как раньше.

## Безопасность и ограничения

- Пароль подключения хранится защищенно: на macOS — в Связке ключей (в app.db
  лежит только ссылка на элемент), на Windows — через DPAPI (расшифровать может
  только ваш пользователь Windows). На Linux пароль пока хранится открытым текстом
  в app.db. Пароли, сохраненные старыми версиями приложения, переводятся в
  защищенное хранилище автоматически при первом запуске.
- Все равно не подключайтесь суперпользователем `postgres` — работайте
  ролью-владельцем (шаг 2): у нее меньше прав на сервере. Администратор нужен
  только окну создания базы, его пароль в реестр не попадает.
- Резервные копии серверных баз делает раздел «Настройки → Резервное копирование» —
  тем же `pg_dump`, по расписанию или вручную (см. [../features/backup.md](../features/backup.md);
  ручные команды — [../../user/postgresql-server.md](../../user/postgresql-server.md),
  раздел «Резервная копия»).
- База по умолчанию остается локальным SQLite-файлом.
