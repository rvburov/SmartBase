# Чеклист: изменения видны во всех разделах сразу

Проверка шины своих изменений (`ChangeBus`, см.
[multi-database.md](../architecture/database/multi-database.md), «Свои правки»): правка в
одном разделе, панели записи или окне расширения отражается в остальных без переключения
галочек и без выхода из раздела. Ожидаемая задержка — доли секунды (300 мс после последнего
коммита); «в моменте» здесь значит «пока рука идет к следующему действию».

## Подготовка стенда

- Одна база с коллекцией, у которой включен раздел задач (user-поле с тумблером «Добавить в
  раздел задач») и есть поле-дата, включенное в календарь; в ней 5–10 записей со сроками.
- Открыть «Настройки → Диагностика» на втором экране не нужно: шина в журнал не пишет, кроме
  отказа своего обработчика (одна запись в минуту).

## 1. Конструктор → задачи

- [ ] В конструкторе поменяли **статус** задачи в ячейке, перешли в «Задачи» — карточка уже с
      новым статусом, галочки в сайдбаре не трогали, оверлея «Загрузка…» не было.
- [ ] То же со **сроком** и **исполнителем**: карточка встала на новое место, значение верное.
- [ ] То же с **названием**, введенным в панели записи (справа): вернулись в «Задачи» —
      название новое.
- [ ] Добавили запись в коллекцию задач через «+» таблицы — в «Задачах» появилась карточка.
- [ ] Удалили запись из таблицы — карточка исчезла.

## 2. Календарь → задачи и конструктор

- [ ] В «Месяце» перетащили событие-задачу на другой день, перешли в «Задачи» — срок новый.
- [ ] Из календаря открыли событие и сменили название — в «Задачах» и в таблице конструктора
      название новое, без переключения галочек.
- [ ] Удалили событие из календаря — в «Задачах» карточки нет, в таблице строки нет.

## 3. Задачи → календарь и конструктор

- [ ] Быстрое добавление задачи со сроком — в календаре событие есть, в таблице строка есть
      (как и раньше: этот путь шел через `CollectionsMayHaveChanged`).

## 4. Окно расширения при открытом конструкторе

- [ ] Открыли «Регистрация КД», **не закрывая окно** перешли в конструктор на коллекцию-журнал,
      нажали «Зарегистрировать» — новая строка появилась в таблице сама, без клика по
      коллекции и без смены раздела.
- [ ] То же с открытой панелью записи (справа) на любой записи этой коллекции — панель не
      сломалась, таблица обновилась.
- [ ] «Документы в коллекцию» / «Сводная трудоемкость» создали коллекцию — она появилась в
      сайдбаре конструктора (и в сайдбарах календаря/задач) по завершении, без перезахода.

## 5. Своя правка не перечитывает сама себя

- [ ] Печатаем название записи в панели справа (запись на каждую букву): таблица обновляет
      строку по буквам, панель не мигает, каретка на месте.
- [ ] Печатаем описание в нижнем блоке панели — то же: ни мигания, ни потери каретки.
- [ ] Правим ячейку в таблице и сразу переходим Tab'ом к следующей: редактор следующей ячейки
      открывается и не сбрасывается через полсекунды.
- [ ] Перенос события в «Неделе» — сетка правится на месте, полной перезагрузки нет.

## 6. Ввод не затирается чужой правкой

- [ ] Открыли редактор ячейки в таблице и, не закрывая его, зарегистрировали документ в окне
      расширения: редактор не закрылся; после Enter/Esc строка расширения появилась (повтор
      через 2 с).
- [ ] Фокус в поле панели записи, регистрация из окна расширения: панель не перестроилась,
      пока фокус в ней; ушли из панели — перечиталась.

## 7. Массовые операции

- [ ] Удалили 500+ записей из календаря (фоновый путь с прогрессом): в конструкторе таблица
      обновилась один раз по завершении, а не мигала по ходу.
- [ ] Импорт таблицы из файла — новая коллекция в сайдбарах после завершения.

## 8. Чужие правки (вторая копия приложения или `--writer`, см. testing/multi-process.md)

- [ ] Сосед поправил задачу, у нас открыт конструктор; перешли в «Задачи» — карточка новая,
      галочки не трогали (раньше требовалось переключить галочку).
- [ ] Сосед правит задачу, у нас открыты «Задачи» — карточка обновилась через ~3 с сама.
