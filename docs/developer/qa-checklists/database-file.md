# Чеклист: файл базы — сведения, сжатие, резервная копия

«Настройки → Управление базой данных», строка каждой SQLite-базы. Что проверяется: строка
«файл · свободно», автосжатие локальной базы при монтировании, «Сжать файл» у общей базы,
«Резервная копия…», пустые значения, WAL. Как устроено —
[storage-and-migrations.md → «Свободное место, сжатие, WAL»](../architecture/database/storage-and-migrations.md#свободное-место-сжатие-wal),
для пользователя — [settings.md](../../user/settings.md).

## Подготовка

Раздутая база — при **закрытой** программе (файл не должен быть смонтирован):

```bash
sqlite3 путь/база.db "CREATE TABLE junk(b); WITH RECURSIVE c(x) AS (SELECT 1 UNION ALL SELECT x+1 FROM c WHERE x<200000) INSERT INTO junk SELECT randomblob(1000) FROM c; DROP TABLE junk; PRAGMA freelist_count;"
```

Файл вырастет примерно на 200 МБ, и почти все они окажутся в свободных страницах
(`freelist_count` ≈ 50 000 при странице 4 КБ) — это выше порога сжатия. Размер и свободное
место в любой момент:

```bash
dotnet run -c Release --project Tests/Benchmarks -- dbsize --db путь/база.db --fast   # только чтение
sqlite3 путь/база.db "PRAGMA page_size; PRAGMA page_count; PRAGMA freelist_count;"
```

«Общая» база — файл на сетевом диске или по UNC-пути (`\\сервер\папка\база.db`), «локальная» —
на своем диске. Для сценариев с занятым файлом нужна вторая копия программы (лучше на другой
машине) или стенд `Tests/MultiProcess`. Размер файла проверять **на диске** (Проводник,
`dir`), а не только по `page_count`: сжатие обязано уменьшать сам файл.

## 1. Сведения о файле

- [ ] У каждой смонтированной SQLite-базы под путем — серая строка «файл X · свободно Y (Z %)»;
      у PostgreSQL, у баз в очереди и у недоступных строки нет.
- [ ] У раздутой базы (свободно > 64 МБ и ≥ 25 % файла, либо > 512 МБ) строка красная с
      пометкой «— стоит сжать»; у здоровой — серая без пометки.
- [ ] Числа сходятся с `dbsize` / `PRAGMA` (размер файла, свободно, процент).
- [ ] Строка снимается при монтировании: после удаления большой коллекции «свободно» вырастет
      после перемонтирования базы (Отключить → Подключить или перезапуск), не мгновенно.

## 2. Локальная база — сжимается сама

- [ ] Раздуть локальную базу (подготовка), запустить программу: в заглушке/на сплэше фаза
      сжатия с процентом, после монтирования строка серая, файл на диске уменьшился примерно
      на объем свободных страниц, `freelist_count` = 0.
- [ ] База ниже порога (свободно < 64 МБ, или < 25 % файла и < 512 МБ) при запуске **не**
      сжимается: фазы сжатия нет, размер прежний.
- [ ] Кнопки «Сжать файл» у локальной базы нет даже при красной строке — она сжимается сама
      при следующем запуске; у базы по умолчанию тоже. «Резервная копия…» у них есть
      (администратору).

## 3. Общая база — только по кнопке

- [ ] Раздутая общая база при запуске **не** сжимается: фазы сжатия нет, строка красная
      «— стоит сжать», файл прежний.
- [ ] «Сжать файл» видна только администратору базы и только при красной строке; у
      остальных пользователей и у здоровой базы кнопки нет.
- [ ] Клик → окно «Сжать файл базы данных «X»?» с размером файла и предупреждением, что другие
      пользователи не смогут сохранять изменения; «Отмена» ничего не делает.
- [ ] «Сжать»: база отцепляется (пропадает из сайдбаров, открытая коллекция закрывается), под
      ее именем — «сжимаю файл · 45 % · ≈ 2 мин» и здесь, и в левой панели; по завершении база
      подключается сама, карточка в правом верхнем углу «Файл базы «X» сжат: A → B», строка
      стала серой, файл на диске уменьшился.
- [ ] Файл занят: на другой машине (или в другом окне) держать блокировку записи —
      `dotnet run --project Tests/MultiProcess -- --hold-write-lock "путь\база.db" 120` —
      и нажать «Сжать файл». Через таймаут — красная карточка «Сжать файл базы «X» не удалось:
      файл занят другими пользователями — попробуйте позже», база монтируется обратно, файл
      цел (`PRAGMA integrity_check` = ok), размер прежний.
- [ ] Во время сжатия другая копия программы на той же базе при попытке сохранить получает
      карточку «база занята», а не зависает; после сжатия ее данные на месте, чужие правки
      подхватываются.

## 4. Резервная копия

- [ ] «Резервная копия…» есть у администратора любой смонтированной SQLite-базы (у
      PostgreSQL нет); окно сохранения предлагает имя «X (копия ГГГГ-ММ-ДД_ЧЧ-ММ).db».
- [ ] Выбрать путь самой базы → карточка «Резервную копию нельзя сохранить поверх самой базы»,
      файл не тронут.
- [ ] Копия раздутой базы: окно «Резервная копия» с процентами, затем фаза «Проверяю копию»;
      результат — файл без свободных страниц (`freelist_count` = 0) размером ≈ живые данные,
      `integrity_check` = ok; карточка «Резервная копия базы «X» сохранена: путь (размер)».
- [ ] Исходная база во время копирования работает: в другой копии программы правки сохраняются,
      база не отцепляется.
- [ ] Копию можно «Подключить базу данных SQLite» — те же коллекции и записи.
- [ ] Сбой (папка только для чтения, диск заполнен) → красная карточка «Резервная копия базы
      «X» не создана: …», недописанный файл удален.

## 5. Пустые значения не хранятся

- [ ] Импортировать CSV с пустыми ячейками; после импорта
      `sqlite3 база.db "SELECT COUNT(*) FROM db_field_values WHERE Value = ''"` = 0, а ячейки в
      таблице пустые.
- [ ] В таблице очистить заполненную ячейку (стереть текст, Enter): та же выборка по-прежнему 0,
      после перезапуска ячейка пустая, фильтр колонки считает ее в «(пусто)».
- [ ] Свод трудоемкости с выгрузкой в базу: каждый прогон — новая коллекция «Трудоемкость
      (дата_время)»; после удаления старой и перемонтирования «свободно» в строке файла
      выросло примерно на ее объем.

## 6. WAL локальной базы

- [ ] После импорта на 300 тыс.+ строк рядом с локальной базой файл `-wal` не больше ≈ 64 МБ
      (усечение — при чекпоинте в конце операции); после закрытия программы `-wal` и `-shm`
      исчезают.
- [ ] У общей базы `-wal` не появляется вовсе (журнал DELETE): рядом с файлом только временный
      `-journal` в момент записи.
