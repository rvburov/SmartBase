# Чеклист: резервное копирование

«Настройки → Резервное копирование». Что проверяется: общие настройки (папка, ротация),
расписания на базу, ручная копия, догон пропущенного, PostgreSQL через pg_dump, следы в
«Диагностике», отсутствие старой кнопки. Как устроено —
[features/backup.md](../features/backup.md), для пользователя —
[settings.md](../../user/settings.md).

## Подготовка

- Хотя бы две базы: локальная SQLite (можно дефолтная) и, для раздела PG, база на стенде
  (`docker run --name sb-pg -e POSTGRES_PASSWORD=postgres -p 5455:5432 -d postgres:16`).
- Часы под рукой: расписание удобно ставить на ближайшую минуту.

## 1. Общие настройки

- [ ] В левой панели настроек раздел «Резервное копирование» стоит сразу под
      «Управлением базой данных», с собственной иконкой.
- [ ] «Папка резервных копий» показывает стандартный путь (`…/Backups`); «Сбросить» не видна.
- [ ] «Выбрать…» → указать свою папку → путь обновился, появилась «Сбросить»; после
      перезапуска программы выбор сохранен. «Сбросить» возвращает стандартный путь.
- [ ] «Хранить последних копий» — стандарт 10; выбранное значение переживает перезапуск.

## 2. Ручная копия SQLite

- [ ] «Копировать сейчас» у SQLite-базы: в строке ход («Копирую… · N %» на большой базе),
      затем «Последняя копия: дата время»; в папке — файл «Имя (копия ГГГГ-ММ-ДД_ЧЧ-ММ).db».
- [ ] Копию можно «Подключить базу данных SQLite» — те же коллекции и записи;
      `PRAGMA integrity_check` = ok, свободных страниц нет.
- [ ] Исходная база во время копирования работает: правки сохраняются, база не отцепляется.
- [ ] Повторный «Копировать сейчас» при выключенном тумблере тоже работает — расписание
      для ручной копии не требуется.
- [ ] Сбой (папка только для чтения) → в строке красная «Ошибка: …», недописанного файла
      нет, отметка «Последняя копия» не сдвинулась.
- [ ] Во время копии в папке лежит только «Имя (копия …).db.part»; своим именем файл
      появляется после фазы «Проверяю копию». Закрыть программу посреди копии большой базы →
      остался `.part`; следующая копия этой базы его убирает.
- [ ] База на сетевом диске: в строке сперва «Читаю «Имя»», потом «Копирую», «Проверяю
      копию». Сравнить время с копированием файла базы проводником в ту же папку копий и
      записать оба числа (стенд сетевой диск не воспроизводит).
- [ ] Папка копий на сетевом диске: перед концом — фаза «Сохраняю копию»; в папке не бывает
      файла копии без `.part` раньше конца.

## 3. Расписание и догон

- [ ] Тумблер включает редакторы расписания; состав меняется по периодичности: «Каждую
      неделю» — выпадающий список дней (последний отмеченный день снять нельзя), «Каждый
      месяц» — число, «Каждый год» — день и месяц; время — у всех.
- [ ] «Каждый год»: список дней следует за месяцем — «февраля» дает максимум 29,
      «апреля» — 30; при 31 + смене месяца на февраль день поджимается до 29, обратная
      смена на март возвращает список 1–31 (выбранный день сохраняется, когда влезает).
- [ ] При включенном тумблере в строке видна «Следующая копия: дата время», и она
      пересчитывается сразу при смене периодичности/дня/времени; «Каждый месяц 31-го» в
      сентябре показывает 30.09, годовое «29 февраля» в невисокосный год — 28.02.
      При выключенном тумблере «Следующая копия» не показывается.
- [ ] Поставить «Каждый день» на ближайшую минуту → в течение следующей минуты копия
      снялась сама, строка обновилась (свежие «Последняя» и «Следующая»), файл появился.
- [ ] Сразу после срабатывания копия не дублируется (следующая — завтра).
- [ ] Догон: при включенном расписании закрыть программу до назначенного времени,
      подождать его, запустить → в первую минуту снялась пропущенная копия.
- [ ] Включение тумблера днем НЕ снимает копию немедленно — первая идет по ближайшему
      расписанию.
- [ ] Расписания и тумблеры у разных баз независимы; выключенная база тиком не копируется.

## 4. Ротация

- [ ] «Хранить последних копий» = 1, два раза «Копировать сейчас» (в разные минуты) → в
      папке осталась одна, свежая копия этой базы.
- [ ] Копии другой базы и посторонние файлы в папке не тронуты (положить руками файл
      «Имя (копия 2020-01-01_03-00).db» другой базы и «заметки.txt»).
- [ ] В «Диагностике» строка «удалено старых копий базы «X»: N».

## 5. PostgreSQL

- [ ] У PG-базы «Копировать сейчас» создает «Имя (копия …).dump»; файл начинается с
      магии `PGDMP` (`head -c 5 файл`); в журнале — «Резервная копия базы «X» сохранена».
- [ ] `pg_restore -h localhost -p 5455 -U postgres -d пустая_база файл.dump` — данные на месте.
- [ ] Неверный пароль в реестре / сервер остановлен → красная «Ошибка: …», файла нет.
- [ ] Без клиента pg_dump (переименовать/убрать из PATH на тестовой машине) → честная
      ошибка «Клиент PostgreSQL (pg_dump) не найден…», а не тихий пропуск.
- [ ] Windows, сервер стоит не в «Program Files» (например, `C:\Programs\PostgreSQL\18`), pg_dump
      не в PATH → копия делается: клиент берется из папки сервера.

## 6. Диагностика и жизненный цикл

- [ ] После запуска программы в «Диагностике» есть «Резервное копирование: служба
      запущена, расписаний включено: N» (N совпадает с числом включенных тумблеров).
- [ ] Каждая копия дает пару записей: «…начата (вручную/по расписанию)» и
      «…сохранена: путь (размер) за N мс»; ошибки — уровнем «Ошибка».
- [ ] В фоновом режиме (окно скрыто в трей) плановая копия все равно снимается.
- [ ] Отключить базу из реестра → после перезапуска ее ключи `backup.<id>.*` убраны из
      app.db (запись «Настройки резервного копирования отключенных баз убраны…»).

## 7. Старой кнопки нет

- [ ] В окне «Настройки базы данных» (шестеренка строки) кнопки «Резервная копия…» нет
      ни у SQLite, ни у PG; «Сжать файл» работает как раньше.
