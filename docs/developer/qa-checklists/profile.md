# Чеклист: модуль «Профиль»

Проверка пользователей, прав, пароля базы, журнала изменений и типа свойства
«Пользователь». Как устроено — [architecture/users-permissions.md](../architecture/users-permissions.md),
описание модуля — [features/profile.md](../features/profile.md).

Разделы 1–5 проверяются на своей личной базе, для 6–7 нужно «сыграть» второго
пользователя (команды имитации — по месту). Раздел 8 — совместимость со старыми базами.

## 1. Каркас модуля

- [ ] В Activity bar есть иконка пользователя **над** шестерёнкой настроек; тултип «Профиль».
- [ ] Клик открывает модуль: слева сайдбар «Профиль» с тремя разделами (Общие данные /
      Панель администратора / История изменений), справа контент.
- [ ] Переключение разделов меняет заголовок навбара; кнопка сворачивания сайдбара
      работает как в Настройках.
- [ ] Зум приложения (Настройки → масштаб) применяется и к этому модулю.

## 2. Общие данные

- [ ] «Имя компьютера» и идентификатор `учётка@компьютер` заполнены автоматически,
      не редактируются.
- [ ] Ввели Фамилию/Имя/Отчество, ушли с поля — «Отображаемое имя» сразу обновилось.
- [ ] Перезапустили приложение — ФИО на месте.
- [ ] Стёрли все три поля — отображаемое имя вернулось к идентификатору.
- [ ] «Подразделение» и «Должность» заполняются по желанию: ввели — после перезапуска
      на месте; стёрли — поле пустое с подсказкой «Не указано»/«Не указана».
- [ ] Заполненные подразделение и должность НЕ меняют «Отображаемое имя» и не появляются
      в панели администратора, истории изменений и выпадашках свойства «Пользователь»
      (это личные справочные поля).

## 3. Панель администратора (на своей базе)

- [ ] Вы администратор своей базы: раздел показывает выпадающий список баз, где вы
      админ (не заглушку «Нет прав администратора»).
- [ ] «Пользователи» → «Открыть»: вместо панели администратора открылась таблица
      пользователей на всю ширину — своя шапка с заголовком «Пользователи», выбором
      области («Вся база данных» + коллекции) и крестиком; заголовок один, навбар
      модуля не дублируется.
- [ ] Крестик возвращает панель администратора; повторный выбор «Панели администратора»
      в сайдбаре — тоже; уход в «Общие данные»/«Историю» и возврат не оставляют
      таблицу открытой.
- [ ] В таблице — вы, с пометкой «(вы)», ролью «Администратор», отмеченным допуском
      и всеми отмеченными галками действий; **все ячейки вашей строки недоступны**.
- [ ] Таблица занимает всю ширину раздела; горизонтальная полоса прокрутки идёт
      от края до края (не обрезана под первой колонкой), а сама колонка с именем
      при прокрутке остаётся на месте.
- [ ] Шапка таблицы как в конструкторе: иконка типа, подпись, шеврон; клик по шеврону
      открывает то же окно фильтра и сортировки, что в «Диагностике» (значения
      с количеством, поиск, «Готово»), активная колонка помечается синей воронкой.
- [ ] Заголовки колонок действий названы полностью — «Удаление записи», «Дублирование
      коллекции», «Изменение свойства», а не одним словом; подписи не обрезаны «…».
- [ ] Наведение на заголовок любой колонки (включая «Пользователь», «Роль», «Доступ к базе данных»,
      «Удаление пользователя») показывает плашку: жирная строка сверху, ниже описание
      в несколько строк (у «Удаления записи» — про удаление по одной и пакетно
      и про отдачу записей при переносе). Плашка переносит текст, а не растягивается
      в одну линию за край окна.
- [ ] Закрыли и снова открыли панель — фильтры и сортировка сброшены.
- [ ] Крестик закрывает панель; уход в другой раздел профиля и смена базы в списке —
      тоже (панель не «висит» поверх других разделов).
- [ ] «Установить пароль»: подпись кнопки целиком; диалог с двумя полями; несовпадение
      паролей и пустой пароль дают баннер ошибки, окно не «прыгает».
- [ ] После установки: текст «Пароль установлен», кнопка стала «Сменить пароль»,
      появилась «Убрать».
- [ ] «Убрать» спрашивает подтверждение и возвращает состояние «Пароль не установлен».

## 4. История изменений

- [ ] Раздел — таблица (Пользователь/Действие/Тип/Объект/Коллекция/Дата и время),
      выбор базы — справа в навбаре; вид таблицы как в конструкторе (линии, шапка).
- [ ] В шапке каждой колонки слева от подписи — иконка типа (человечек, карандаш,
      блоки, текст, коллекция, часы), как в «Диагностике»; подписи не съехали.
- [ ] Создайте коллекцию, переименуйте её, добавьте свойство, создайте запись, поправьте
      ячейку, удалите запись — в Истории появились строки с вашим именем,
      новые сверху, время локальное.
- [ ] Повторное сохранение записи **без изменений** новых строк не добавляет.
- [ ] Перетаскивание коллекций/сортировка записей (перестановки) журнал не засоряют.
- [ ] Импортируйте файл на несколько тысяч строк — в журнале **одна** строка
      (Действие «Импорт», Объект «… (N записей)»), импорт не замедлился.
- [ ] Удалите коллекцию целиком — одна строка с количеством записей.
- [ ] Напечатайте в заголовке записи несколько букв подряд — в журнале ОДНА строка
      «исходное → конечное», без промежуточных «П», «Пр», «Про»…; стёрли обратно
      до исходного — строка исчезла. То же для ячейки и описания.
- [ ] Переименуйте коллекцию и поправьте ячейку — в «Объекте» видно «до → после»:
      «Старое» → «Новое» и «Запись (Свойство: «до» → «после»)»; длинный текст свёрнут
      с «…», полный — в тултипе при наведении.
- [ ] Шеврон в шапке любой колонки открывает окно фильтра/сортировки (как в таблице
      конструктора): галки значений с количеством, поиск, «От А до Я»/«От Я до А»
      (у даты — «Сначала старые/новые»), применение по «Готово»; активная колонка
      помечается синей воронкой.
- [ ] Фильтр по «Тип» = Записи + сортировка по «Пользователь» работают вместе;
      смена базы в навбаре сбрасывает фильтры.
- [ ] Если строк больше 200 — прокрутка к концу догружает следующую страницу без фриза.

### Выгрузка в CSV

- [ ] В правом краю навбара (правее выбора базы) есть кнопка со стрелкой, тултип
      «Выгрузить в CSV»; в других разделах профиля её нет.
- [ ] Клик → окно: что выгружается, число строк, формат (CSV, UTF-8, «;»), упоминание
      фильтров; «Отмена» ничего не делает, «Подтвердить» открывает выбор файла.
- [ ] Отказ от выбора файла (закрыли диалог) — ничего не создаётся, окон больше нет.
- [ ] Во время выгрузки видно окно прогресса: проценты, «N из M», после пары секунд —
      «осталось ≈ … мин»; по завершении — сообщение с числом строк и путём.
- [ ] Файл открывается в Excel/Numbers без настроек: кириллица целая, колонки разделены,
      значения человеческие («Изменение», «Запись», «до → после», локальное время).
- [ ] Наложите фильтр (например Действие = Создание) и выгрузите — в файле только
      отфильтрованные строки, число совпадает с окном подтверждения.
- [ ] Смените сортировку колонки — порядок строк в файле такой же, как на экране.
- [ ] «Отмена» в прогрессе прекращает выгрузку, недописанный файл НЕ остаётся на диске.
- [ ] Большой журнал (сотни тысяч строк): окно прогресса двигается, приложение не зависает,
      память не растёт лавинообразно.
- [ ] Отсортируйте таблицу по «Пользователь» и выгрузите — файл в том же порядке,
      время выгрузки сопоставимо с обычной (не «висит» минутами).
- [ ] Пока идёт подсчёт строк, повторный клик по кнопке НЕ открывает второе окно.
- [ ] Смените базу в навбаре сразу после клика — вместо чужой выгрузки появится
      сообщение «Список изменился… откройте выгрузку заново».
- [ ] База с «/» или «:» в имени: предложенное имя файла без этих символов, диалог
      сохранения открывается в обычной папке.

### Детали строки (как в «Диагностике»)

- [ ] Клик по строке открывает справа панель «Детали» во всю высоту: её заголовок
      вровень с навбаром профиля, в списке карточка на каждое поле строки с теми же
      подписями и иконками, что у колонок.
- [ ] Клик по карточке подсвечивает её (голубой фон, синие подпись и иконка) и
      показывает полное значение снизу; крошка «Поле › …» называет выбранное поле,
      кнопка справа копирует текст в буфер.
- [ ] Выбранное поле помнится: клик по другой строке открывает то же поле.
- [ ] Ручки работают: пилюля у левого края тянет ширину панели, пилюля над линией —
      границу карточек и текста, ⋮ в карточке — общую ширину колонки названий.
- [ ] Крестик закрывает панель и снимает выделение строки; повторный клик по той же
      строке снова открывает детали.
- [ ] Смена базы, применение фильтра и уход в другой раздел профиля закрывают панель
      (она не «висит» поверх «Общих данных» и панели администратора).
- [ ] При зуме ≠ 1 разметка панели не ломается, ручки тянут корректно.
- [ ] Панель администратора → «Очистить журнал»: выбор периода (старше 1/3/6/12 мес.
      или весь), подтверждение, после — сообщение о числе удалённых; открытая история
      этой базы обновилась.
- [ ] «Автоочистка журнала»: тумблер + срок (3/6/12/24 мес.) сохраняются; при
      переоткрытии базы записи старше срока исчезают, свежие остаются. Настройка
      действует на всех машинах, открывающих файл (хранится в базе).

## 5. Тип свойства «Пользователь»

- [ ] В диалоге создания свойства есть тип «Пользователь» с иконкой.
- [ ] Создайте свойство «Ответственный»: новая запись автоматически получает **вас**;
      в выпадашке (таблица, окно записи, панель записи) — только допущенные пользователи
      (в личной базе — только вы).
- [ ] Фильтр и сортировка колонки работают по имени.
- [ ] Смена типа поля user → text и обратно не роняет данные (имя остаётся текстом).

### Живой состав пользователей (нужен «второй пользователь», см. имитацию в п. 6)

- [ ] Допустите второго пользователя в панели администратора — **без перезапуска**
      он появился в выпадашках: раздел «Задачи» (диалог задачи, «Исполнитель»
      и «Назначил», строка быстрого добавления), таблица конструктора (правка
      ячейки user-колонки), панель записи, диалог записи календаря.
- [ ] Отозвали допуск — из тех же выпадашек он исчез, тоже без перезапуска.
- [ ] Запись, где он был указан исполнителем, **сохранила его имя**: видно в ячейке
      таблицы, в панели записи и на карточке задачи; при входе в правку ячейки имя
      остаётся выбранным в списке (не пустой ComboBox) и не затирается.
- [ ] Второй пользователь сменил ФИО у себя — в выпадашках новое имя, старое ушло.
- [ ] Ожидающий допуска (`IsApproved=0`) в выпадашках НЕ появляется, но виден
      в панели администратора со статусом «Ожидает допуска».
- [ ] Допуск, выданный с другой машины, снимает замок сам (тост «Администратор
      подтвердил доступ…»), а панель администратора показывает актуальный статус
      без перезахода.

## 6. Допуск и замок (нужен «второй пользователь»)

Имитация чужой базы: закройте приложение и выполните для ТЕСТОВОЙ базы (не жалко):

```bash
sqlite3 путь/к/base.db "UPDATE db_users SET IsAdmin=0, IsApproved=0; \
  INSERT INTO db_users (UserKey, DisplayName, IsAdmin, IsApproved, CreatedAt) \
  VALUES ('boss@other-pc', 'Чужой Админ', 1, 1, '2026-07-06T00:00:00Z');"
```

- [ ] После запуска база в сайдбаре конструктора показана **замком**, без коллекций;
      контекстного меню у неё нет.
- [ ] Календарь события этой базы не показывает; в диалогах «Расположение»/создания
      она не предлагается как цель.
- [ ] Без пароля: клик по замку → пояснение «ожидает подтверждения администратора».
- [ ] С паролем (поставьте его до имитации): клик → диалог; неверный пароль — баннер,
      окно живо; верный — база сразу открывается, после перезапуска доступ сохранён.
- [ ] Путь через админа: верните себе `IsAdmin=1` в sqlite3 — «Чужой Админ» виден
      в таблице панели; галка «Доступ к базе данных» меняет статус.

### Роли, права и удаление (та же имитация)

- [ ] У соседа без допуска — красное «ждёт допуска», галки действий недоступны;
      поставили «Доступ к базе данных» — ожили, строка осталась на месте (не прыгнула вверх).
- [ ] Сменили ему роль на «Администратор»: все 13 галок отметились и **погасли**,
      доступ встал сам; вернули «Пользователя» — прежние галки на месте.
- [ ] Свою строку изменить нельзя: роль, допуск, галки и корзина недоступны.
- [ ] Выбрали в шапке коллекцию: галки показывают её права, «Создавать коллекции»
      недоступно; снятая галка действует только в этой коллекции (в «Вся база данных»
      значение прежнее).
- [ ] Корзина спрашивает подтверждение и убирает пользователя; в «Истории изменений»
      появилась строка «Удаление пользователя», в `db_permissions` его строк нет.
- [ ] Пользователь открывает базу снова — он опять в таблице со статусом «ждёт допуска».
- [ ] «Последняя активность» обновилась после переоткрытия базы, а новых строк
      в «Истории изменений» от этого **не появилось**.
- [ ] Вторая копия программы (или другая машина) видит смену роли и допуска
      без перезапуска; если понизили вас — открытая панель закрылась, раздел показал
      заглушку «Нет прав администратора».

## 7. Права (жёсткая блокировка)

Оставаясь «не админом» (IsAdmin=0, IsApproved=1), снимите себе права — через панель
«чужого админа» или прямо в sqlite3:

```bash
# всё, кроме удаления записей (маска All=8191 минус DeleteRecord=128)
sqlite3 путь/к/base.db "INSERT INTO db_permissions (UserId, CollectionId, ActionsMask) \
  VALUES ((SELECT Id FROM db_users WHERE IsAdmin=0 LIMIT 1), NULL, 8063);"
```

- [ ] «Удалить» в меню записи кликается, но показывает окно «Недостаточно прав:
      удаление записей запрещено администратором базы данных»; запись остаётся.
      То же для запрещённых пунктов меню коллекции/группы в сайдбаре, «+» записи
      и «+» свойства, а также при попытке отредактировать ячейку без права изменения.
- [ ] Снимите «Просматривать коллекцию» у одной коллекции: в сайдбаре конструктора
      она стала **замком** (как база без допуска), контекстного меню у неё нет,
      клик показывает «Нет доступа к коллекции «…»». Вернули право — замок исчез
      без перезапуска, коллекция открывается.
- [ ] Снимите «Изменять записи» (маска 8127) — таблица только на чтение: ячейки не
      редактируются, add-row и «+» свойства по правам.
- [ ] Права на уровне отдельной коллекции перекрывают права базы (запрет в базе +
      разрешение в коллекции → в этой коллекции действие доступно).
- [ ] Администратору ничего не блокируется никогда.

Биты маски — enum `PermAction` в [Core/Models/Permissions.cs](../../../Core/Models/Permissions.cs)
(ViewCollection=1 … DeleteField=2048, DuplicateField=4096, All=8191).

## 8. Старые базы и миграция

- [ ] Копия базы, созданной **до** обновления, подключается без ошибок, вы стали её
      администратором, все старые данные на месте.
- [ ] В файле появились 4 таблицы: `sqlite3 base.db ".tables"` →
      `db_users`, `db_permissions`, `db_meta`, `change_log`.
- [ ] В `db_users` есть колонка `LastSeenAt`: у старых строк она равна `CreatedAt`
      (бэкфилл миграции), после открытия базы — обновилась.
