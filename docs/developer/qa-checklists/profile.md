# Чеклист: модуль «Профиль»

Проверка пользователей, прав, пароля базы, журнала изменений и типа свойства
«Пользователь». Как устроено — [architecture/users-permissions.md](../architecture/users-permissions.md),
описание модуля — [features/profile.md](../features/profile.md).

Разделы 1–5 проверяются на своей личной базе, для 6–7 нужно «сыграть» второго
пользователя (команды имитации — по месту). Раздел 8 — совместимость со старыми базами.

## 1. Каркас модуля

- [ ] В Activity bar есть иконка пользователя **над** шестеренкой настроек; тултип «Профиль».
- [ ] Клик открывает модуль: слева сайдбар «Профиль» с пятью разделами (Общие данные /
      Панель администратора / Безопасность / Менеджер паролей / История изменений),
      справа контент.
- [ ] Переключение разделов меняет заголовок навбара; кнопка сворачивания сайдбара
      работает как в Настройках.
- [ ] Зум приложения (Настройки → масштаб) применяется и к этому модулю.

## 2. Общие данные

- [ ] «Имя компьютера» и идентификатор `учетка@компьютер` заполнены автоматически,
      не редактируются.
- [ ] Ввели Фамилию/Имя/Отчество, ушли с поля — «Отображаемое имя» сразу обновилось.
- [ ] Перезапустили приложение — ФИО на месте.
- [ ] Стерли все три поля — отображаемое имя вернулось к идентификатору.
- [ ] «Подразделение» и «Должность» заполняются по желанию: ввели — после перезапуска
      на месте; стерли — поле пустое с подсказкой «Не указано»/«Не указана».
- [ ] Заполненные подразделение и должность НЕ меняют «Отображаемое имя» и не появляются
      в панели администратора, истории изменений и выпадашках свойства «Пользователь»
      (это личные справочные поля).

## 3. Панель администратора (на своей базе)

- [ ] Вы администратор своей базы: раздел показывает выпадающий список баз, где вы
      админ (не заглушку «Нет прав администратора»).
- [ ] «Пользователи» → «Открыть»: вместо панели администратора открылась таблица
      пользователей на всю ширину — своя шапка с заголовком «Пользователи», выбором
      области («Вся база данных» + коллекции) и крестиком; заголовок один, навбар
      модуля не дублируется.
- [ ] Крестик возвращает панель администратора; повторный выбор «Панели администратора»
      в сайдбаре — тоже; уход в «Общие данные»/«Историю» и возврат не оставляют
      таблицу открытой.
- [ ] В таблице — вы, с пометкой «(вы)», ролью «Администратор», отмеченным допуском
      и всеми отмеченными галками действий; **все ячейки вашей строки недоступны**.
- [ ] Таблица занимает всю ширину раздела; горизонтальная полоса прокрутки идет
      от края до края (не обрезана под первой колонкой), а сама колонка с именем
      при прокрутке остается на месте.
- [ ] Шапка таблицы как в конструкторе: иконка типа, подпись, шеврон; клик по шеврону
      открывает то же окно фильтра и сортировки, что в «Диагностике» (значения
      с количеством, поиск, «Готово»), активная колонка помечается синей воронкой.
- [ ] Заголовки колонок действий названы полностью — «Удаление записи», «Дублирование
      коллекции», «Изменение свойства», а не одним словом; подписи не обрезаны «…».
- [ ] Наведение на заголовок любой колонки (включая «Пользователь», «Роль», «Доступ к базе данных»,
      «Удаление пользователя») показывает плашку: жирная строка сверху, ниже описание
      в несколько строк (у «Удаления записи» — про удаление по одной и пакетно
      и про отдачу записей при переносе). Плашка переносит текст, а не растягивается
      в одну линию за край окна.
- [ ] Фильтр ведет себя как в конструкторе (прогон — [filter-column.md](filter-column.md),
      п. 6): отобрали «Роль» = Пользователь, открыли «Доступ к базе данных» — в списке
      только значения этих людей; поиск сам отмечает найденное, Enter применяет.
- [ ] «Подключен» и «Последняя активность» — дерево дат (год → месяц → день), как у
      колонки даты в конструкторе; «Сначала новые» сортирует по времени, а не по строке.
- [ ] Закрыли и снова открыли панель — фильтры и сортировка сброшены.
- [ ] Крестик закрывает панель; уход в другой раздел профиля и смена базы в списке —
      тоже (панель не «висит» поверх других разделов).
- [ ] Строка «Доступ других пользователей по паролю» стоит над строкой пароля. У базы
      без пароля тумблер выключен; включили — открылось окно установки пароля; «Отмена»
      вернула тумблер в выключенное, подтверждение поставило пароль и оставило тумблер
      включенным.
- [ ] У базы с паролем, поставленным раньше, тумблер включен. Выключили — текст «Пароль
      установлен» остался, «Убрать» и «Сменить пароль» на месте; включили обратно —
      окна пароля нет, пароль прежний.
- [ ] То же на базе PostgreSQL: тумблер переключается, после перезапуска состояние
      сохранено.
- [ ] «Установить пароль»: подпись кнопки целиком; диалог с двумя полями; несовпадение
      паролей и пустой пароль дают баннер ошибки, окно не «прыгает».
- [ ] В заголовке окна названа база: «Установить пароль базы «Вторая»» или «Сменить пароль
      базы «Вторая»». Пояснения над полями нет — сразу «Новый пароль». В окне разблокировки
      запертой базы пояснение, наоборот, на месте.
- [ ] В обоих полях окна пароля набранное закрыто точками, справа в поле стоит закрытый
      глаз с отступом от рамки. Нажали — точки сменились буквами, иконка стала открытым
      глазом и посинела, подсказка сменилась на «Скрыть набранное»; нажали еще раз —
      вернулось. Курсор из поля при нажатии не пропадает, Tab ведет в следующее поле,
      а не на глаз. Закрыли и снова открыли окно — глаз опять закрыт.
- [ ] После установки: текст «Пароль установлен», кнопка стала «Сменить пароль»,
      появилась «Убрать».
- [ ] «Убрать» спрашивает подтверждение и возвращает состояние «Пароль не установлен»;
      тумблер доступа по паролю при этом гаснет.

### Область «Все базы данных» (нужны две базы, где вы администратор)

- [ ] В шапке таблицы есть пункт «Все базы данных»; при одной админской базе его нет.
- [ ] Под шапкой сразу таблица — строки «Правки уходят…» над ней нет.
- [ ] В таблице только люди базы, выбранной в панели администратора: пользователь,
      подключавшийся лишь к другой вашей базе, не показан ни в строках, ни в списке
      фильтра «Пользователь».
- [ ] Галка у человека, который есть в обеих базах с разными правами, закрашена
      наполовину; щелчок ставит право в обеих, повторный — снимает в обеих.
- [ ] Закрыли одну из баз, щелкнули галку — окно с именем закрытой базы и причиной,
      в открытой право изменилось.

## 3а. Менеджер паролей

Раздел «Менеджер паролей» — опись мест, где на этой машине бывает пароль. Как устроено —
[features/profile.md](../features/profile.md), правила видимости и строк —
[SecretsInventory](../../../Database/SecretsInventory.cs).

### Кто что видит

- [ ] Вы администратор открытой базы и вам разрешена настройка интеграций: в списке есть
      строка пароля этой базы, у базы PostgreSQL — еще и строка пароля сервера, а также
      соединения, токены ваших баз и мастер-пароль организации.
- [ ] Открыли базу, где вы обычный пользователь: ее строк в списке нет, ваши остались.
- [ ] Закрыли базу — ее строки пропали; открыли снова — вернулись.
- [ ] Играем пользователя без админства (имитация — как в п. 6): вместо списка одна строка
      **«Нет прав администратора»** с пояснением, кто и что здесь видит. Кнопки «Добавить
      пароль» в навбаре нет.
- [ ] Администратору одной базы сняли право «Интеграции» в СОСЕДНЕЙ открытой базе, где он
      обычный пользователь: соединения, токены и мастер-пароль пропали из списка, строки
      его собственных баз остались, кнопка «Добавить пароль» исчезла. Вернули право —
      вернулось все.

### Строка

- [ ] В строке четыре текста: название с родом и движком («Пароль базы SQLite «Заказы»»,
      «Пароль базы PostgreSQL «Заказы»»), состояние цветом, путь настройки, путь хранения.
- [ ] Путь настройки называет место в программе: «Профиль → Панель администратора» у пароля
      базы, «Настройки → Управление базой данных», шестеренка у базы — у пароля сервера,
      «Настройки → Интеграции → Соединения» у соединения, «Настройки → Интеграции → Доступ
      извне» у токена; у мастер-пароля — «политика организации, вне программы».
- [ ] Подсказки при наведении на строку или на название НЕТ (у кнопок свои подсказки есть).
- [ ] Слева иконка рода: база, сервер, соединение, робот, щит у мастер-пароля.
- [ ] Кнопки прижаты к правому краю, и их ровно столько, сколько у строки действий: у строки
      без ключа и корзины пустых мест не остается, кнопки соседних строк стоят у одного края.

### Цвет состояния

- [ ] «установлен» и «задан» — зеленые.
- [ ] «установлен · вход по паролю выключен» — **зеленый**: пароль задан, а что он сейчас
      никого не пускает, сказано словами.
- [ ] «выключен» у токена — **зеленый** по той же причине.
- [ ] «не установлен» и «не задан» — серые.
- [ ] «давно не нужен» — красный; такие строки стоят наверху списка, пустые места — внизу.

### Добавить пароль

- [ ] Кнопка «Добавить пароль» стоит в правом верхнем углу и только в этом разделе.
- [ ] В меню три пункта: «Соединение», «Токен», «Мастер-пароль». Подписи влезают целиком.
- [ ] «Соединение» открывает ту же карточку соединения, что «Настройки → Интеграции».
- [ ] «Токен» предлагает только базы, где вы администратор; текст токена показывается один
      раз и копируется в буфер обмена.
- [ ] «Мастер-пароль» открывает окно подсчета строки для политики.
- [ ] После любого из трех список перестроился сам, без ухода из раздела.

### Действия в строках

- [ ] Шестеренка у пароля базы открывает то же окно, что «Установить пароль» в панели
      администратора; корзина спрашивает подтверждение и меняет состояние на «не установлен».
- [ ] Шестеренка у пароля сервера PostgreSQL открывает окно настроек базы; корзины у этой
      строки нет.
- [ ] Ключ есть только у соединения с секретом. Нажали — спросили мастер-пароль, секрет
      открылся ОТДЕЛЬНЫМ окном с «Скопировать» и «Закрыть»; закрыли — значения на экране нет,
      второй показ снова стоит мастер-пароля.
- [ ] Ввели неверный мастер-пароль — отказ; в журнале безопасности («Профиль → Панель
      администратора») появилась запись и об удачном показе, и об отказе.
- [ ] Мастер-пароль политикой не задан: ключ объясняет это словами и подсказывает, где
      посчитать строку.
- [ ] Шестеренка у токена открывает окно токена с тумблером «Включен» и кнопкой «Отозвать»;
      тумблер применяется сразу, отзыв спрашивает подтверждение.
- [ ] Отозвали админство в соседнем окне, пока окно действия открыто, — программа сказала
      об этом и перестроила список, а не выполнила действие.

## 4. История изменений

- [ ] Раздел — таблица (Пользователь/Действие/Тип/Объект/Коллекция/Дата и время),
      выбор базы — справа в навбаре; вид таблицы как в конструкторе (линии, шапка).
- [ ] В шапке каждой колонки слева от подписи — иконка типа (человечек, карандаш,
      блоки, текст, коллекция, часы), как в «Диагностике»; подписи не съехали.
- [ ] Создайте коллекцию, переименуйте ее, добавьте свойство, создайте запись, поправьте
      ячейку, удалите запись — в Истории появились строки с вашим именем,
      новые сверху, время локальное.
- [ ] Повторное сохранение записи **без изменений** новых строк не добавляет.
- [ ] Перетаскивание коллекций/сортировка записей (перестановки) журнал не засоряют.
- [ ] Импортируйте файл на несколько тысяч строк — в журнале **одна** строка
      (Действие «Импорт», Объект «… (N записей)»), импорт не замедлился.
- [ ] Удалите коллекцию целиком — одна строка с количеством записей.
- [ ] Напечатайте в заголовке записи несколько букв подряд — в журнале ОДНА строка
      «исходное → конечное», без промежуточных «П», «Пр», «Про»…; стерли обратно
      до исходного — строка исчезла. То же для ячейки и описания.
- [ ] Переименуйте коллекцию и поправьте ячейку — в «Объекте» видно «до → после»:
      «Старое» → «Новое» и «Запись (Свойство: «до» → «после»)»; длинный текст свернут
      с «…», полный — в тултипе при наведении.
- [ ] Шеврон в шапке любой колонки открывает окно фильтра/сортировки (как в таблице
      конструктора): галки значений с количеством, поиск, «От А до Я»/«От Я до А»
      (у даты — «Сначала старые/новые»), применение по «Готово»; активная колонка
      помечается синей воронкой.
- [ ] Фильтр по «Тип» = Записи + сортировка по «Пользователь» работают вместе;
      смена базы в навбаре сбрасывает фильтры.
- [ ] Каскад: отобрали «Действие» = Создание, открыли «Тип» — в списке только типы, у
      которых есть создания, с их количеством; открыли снова «Действие» — список полный,
      «Создание» отмечено и стоит первым.
- [ ] «От А до Я» по «Действие» дает порядок русских подписей («Дублирование, Изменение,
      Импорт, Создание, Удаление…»), не кодов; при прокрутке через границу страницы
      строки не пропадают и не повторяются.
- [ ] В списке баз справа только базы, куда у вас есть доступ; база с замком в списке
      не показана. Единственная база без доступа — в таблице текст «Нет баз данных, к
      которым у вас есть доступ.»; пустой журнал — «Записей в журнале пока нет.»;
      фильтр без совпадений — «Нет записей, подходящих под фильтры.».
- [ ] Если строк больше 200 — прокрутка к концу догружает следующую страницу без фриза.

### Выгрузка в CSV

- [ ] В правом краю навбара (правее выбора базы) есть кнопка со стрелкой, тултип
      «Выгрузить в CSV»; в других разделах профиля ее нет.
- [ ] Клик → окно: что выгружается, число строк, формат (CSV, UTF-8, «;»), упоминание
      фильтров; «Отмена» ничего не делает, «Подтвердить» открывает выбор файла.
- [ ] Отказ от выбора файла (закрыли диалог) — ничего не создается, окон больше нет.
- [ ] Во время выгрузки видно окно прогресса: проценты, «N из M», после пары секунд —
      «осталось ≈ … мин»; по завершении — сообщение с числом строк и путем.
- [ ] Файл открывается в Excel/Numbers без настроек: кириллица целая, колонки разделены,
      значения человеческие («Изменение», «Запись», «до → после», локальное время).
- [ ] Наложите фильтр (например Действие = Создание) и выгрузите — в файле только
      отфильтрованные строки, число совпадает с окном подтверждения.
- [ ] Смените сортировку колонки — порядок строк в файле такой же, как на экране.
- [ ] «Отмена» в прогрессе прекращает выгрузку, недописанный файл НЕ остается на диске.
- [ ] Большой журнал (сотни тысяч строк): окно прогресса двигается, приложение не зависает,
      память не растет лавинообразно.
- [ ] Отсортируйте таблицу по «Пользователь» и выгрузите — файл в том же порядке,
      время выгрузки сопоставимо с обычной (не «висит» минутами).
- [ ] Пока идет подсчет строк, повторный клик по кнопке НЕ открывает второе окно.
- [ ] Смените базу в навбаре сразу после клика — вместо чужой выгрузки появится
      сообщение «Список изменился… откройте выгрузку заново».
- [ ] База с «/» или «:» в имени: предложенное имя файла без этих символов, диалог
      сохранения открывается в обычной папке.

### Детали строки (как в «Диагностике»)

- [ ] Клик по строке открывает справа панель «Детали» во всю высоту: ее заголовок
      вровень с навбаром профиля, в списке карточка на каждое поле строки с теми же
      подписями и иконками, что у колонок.
- [ ] Вид блока карточек тот же, что в «Диагностике» и «Странице записи»: серая
      подложка, белые карточки, наведение чуть темнее белого.
- [ ] Клик по карточке подсвечивает ее (голубой фон, синие подпись и иконка) и
      показывает полное значение снизу; крошка «Поле › …» называет выбранное поле,
      кнопка справа копирует текст в буфер.

## 6. Допуск и замок (нужен «второй пользователь»)

Имитация чужой базы: закройте приложение и выполните для ТЕСТОВОЙ базы (не жалко):

```bash
sqlite3 путь/к/base.db "UPDATE db_users SET IsAdmin=0, IsApproved=0; \
  INSERT INTO db_users (UserKey, DisplayName, IsAdmin, IsApproved, CreatedAt) \
  VALUES ('boss@other-pc', 'Чужой Админ', 1, 1, '2026-07-06T00:00:00Z');"
```

- [ ] После запуска база в сайдбаре конструктора показана **замком**, без коллекций;
      контекстного меню у нее нет.
- [ ] Календарь события этой базы не показывает; в диалогах «Расположение»/создания
      она не предлагается как цель.
- [ ] Без пароля: клик по замку → пояснение «ожидает подтверждения администратора».
- [ ] С паролем (поставьте его до имитации): клик → диалог; неверный пароль — баннер,
      окно живо; верный — база сразу открывается, после перезапуска доступ сохранен.
- [ ] С паролем и выключенным тумблером «Доступ других пользователей по паролю»
      (`UPDATE db_meta SET Value='0' WHERE Key='access.password.enabled'` или тумблер до
      имитации): клик по замку → то же пояснение про администратора, диалога пароля нет.
      Включили тумблер обратно — диалог вернулся, пароль прежний.
- [ ] Во второй копии программы у соседа этой базы нет в списке «Истории изменений»;
      дали допуск — база появилась в списке без перезапуска, история видна целиком.
- [ ] Путь через админа: верните себе `IsAdmin=1` в sqlite3 — «Чужой Админ» виден
      в таблице панели; галка «Доступ к базе данных» меняет статус.

### Роли, права и удаление (та же имитация)

- [ ] У соседа без допуска — красное «ждет допуска», галки действий недоступны;
      поставили «Доступ к базе данных» — ожили, строка осталась на месте (не прыгнула вверх).
- [ ] Сменили ему роль на «Администратор»: все 13 галок отметились и **погасли**,
      доступ встал сам; вернули «Пользователя» — прежние галки на месте.
- [ ] Свою строку изменить нельзя: роль, допуск, галки и корзина недоступны.
- [ ] Выбрали в шапке коллекцию: галки показывают ее права, «Создавать коллекции»
      недоступно; снятая галка действует только в этой коллекции (в «Вся база данных»
      значение прежнее).
- [ ] Корзина спрашивает подтверждение и убирает пользователя; в «Истории изменений»
      появилась строка «Удаление пользователя», в `db_permissions` его строк нет.
- [ ] Пользователь открывает базу снова — он опять в таблице со статусом «ждет допуска».
- [ ] Удалили пользователя, у которого база открыта: у него база стала замком, история
      этой базы пропала из его списка; щелчок по замку — он снова в таблице «ждет
      допуска» (в «Истории» строка «Присоединение»), прежних галок нет.
      С паролем и включенным доступом по паролю верный пароль сразу возвращает базу.
- [ ] «Последняя активность» обновилась после переоткрытия базы, а новых строк
      в «Истории изменений» от этого **не появилось**.
- [ ] Вторая копия программы (или другая машина) видит смену роли и допуска
      без перезапуска; если понизили вас — открытая панель закрылась, раздел показал
      заглушку «Нет прав администратора».

## 7. Права (жесткая блокировка)

Оставаясь «не админом» (IsAdmin=0, IsApproved=1), снимите себе права — через панель
«чужого админа» или прямо в sqlite3:

```bash
# все, кроме удаления записей (маска All=8191 минус DeleteRecord=128)
sqlite3 путь/к/base.db "INSERT INTO db_permissions (UserId, CollectionId, ActionsMask) \
  VALUES ((SELECT Id FROM db_users WHERE IsAdmin=0 LIMIT 1), NULL, 8063);"
```

- [ ] «Удалить» в меню записи кликается, но показывает окно «Недостаточно прав:
      удаление записей запрещено администратором базы данных»; запись остается.
      То же для запрещенных пунктов меню коллекции/группы в сайдбаре, «+» записи
      и «+» свойства, а также при попытке отредактировать ячейку без права изменения.
- [ ] Снимите «Просматривать коллекцию» у одной коллекции: в сайдбаре конструктора
      она стала **замком** (как база без допуска), контекстного меню у нее нет,
      клик показывает «Нет доступа к коллекции «…»». Вернули право — замок исчез
      без перезапуска, коллекция открывается.
- [ ] Снимите «Изменять записи» (маска 8127) — таблица только на чтение: ячейки не
      редактируются, add-row и «+» свойства по правам.
- [ ] Права на уровне отдельной коллекции перекрывают права базы (запрет в базе +
      разрешение в коллекции → в этой коллекции действие доступно).
- [ ] Администратору ничего не блокируется никогда.

Биты маски — enum `PermAction` в [Core/Models/Permissions.cs](../../../Core/Models/Permissions.cs)
(ViewCollection=1 … DeleteField=2048, DuplicateField=4096, All=8191).
