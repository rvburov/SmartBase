# Показ markdown

Свой рендер (Markdig → контролы Avalonia, [markdown.md](../ui/markdown.md)) обслуживает **четыре**
экрана сразу. Экранных тестов в проекте нет, дерево контролов проверяет
[MarkupRenderTests](../../../Tests/Unit/MarkupRenderTests.cs), а вид — только глаз. Поэтому после
правки рендера прогонять надо все четыре: расхождение вида — это и есть тот дефект, ради которого
движок писался свой.

Готовый образец со всеми конструкциями — «Образец разметки» в хранилище заметок.

## 1. Четыре экрана показывают одно и то же

Один и тот же текст открыть в каждом и сравнить:

- [ ] «Настройки → Инструкция пользователя»;
- [ ] «Расширения» — описание расширения;
- [ ] панель записи — просмотр описания (переключатель в футере);
- [ ] «Заметки» — режим «Просмотр».

Проверяется: размеры заголовков, просвет между блоками, вид кода, цитаты, таблицы. Различаться
ничего не должно.

## 2. Элементы

- [ ] Заголовки H1–H6: H1 крупнее всех, H2 меньше, H3 еще меньше, H4 базовым, H5 и H6 базовым
      приглушенным. Шесть уровней подряд различимы.
- [ ] `**жирный**`, `*курсив*`, `~~зачеркнутый~~`, `***жирный курсив***` — начертания
      КОМБИНИРУЮТСЯ, ни одно не теряется.
- [ ] `` `код` `` внутри строки — коробка со скруглением, моноширинный, поля по бокам равные.
- [ ] Длинный `` `путь/в/несколько/сегментов/который/не/влезает` `` переносится по строкам, а НЕ
      вылезает за край блока; коробка на переносе разваливается надвое.
- [ ] `==подсветка==` — светлая заливка, начертание не меняется.
- [ ] Блок кода: заливка во всю ширину, скругление, язык подписью в правом верхнем углу,
      кнопка «Скопировать» рядом. Нажать — текст в буфере БЕЗ ограждений.
- [ ] Длинная строка кода переносится, не обрезается.
- [ ] Цитата `> текст`: заливка, полоса слева, скругление только справа.
- [ ] Выносные блоки `> [!note]`, `> [!tip]`, `> [!warning]`, `> [!danger]` — четыре цвета, четыре
      знака, зачин жирным рядом со знаком.
- [ ] `> [!note]` без зачина — подпись «Заметка» (и так для каждого вида).
- [ ] `> [!нетакой] Текст` — обычная цитата ВМЕСТЕ с меткой: незнакомое не проглатывается.
- [ ] Горизонтальная черта — тонкая линия во всю ширину.
- [ ] Список: первый уровень залитым кружком, второй колечком, третий черточкой; вторая строка
      пункта встает под текст, а не под маркер.
- [ ] Нумерованный список: номера прижаты вправо, «9.» и «10.» стоят под одной осью.
- [ ] Список задач: `- [x]` дает залитый флажок с белой галочкой, `- [ ]` — пустой с рамкой;
      скобки на экране не видны, сделанный пункт приглушен и НЕ зачеркнут.
- [ ] Таблица: без внешней рамки и вертикальных линий, шапка серой заливкой со скруглением
      верхних углов, колонки делят ширину поровну, выравнивание из `|:---:|` работает.
- [ ] Картинка рядом с заметкой показывается со скруглением; картинка по `http` — только подпись.

## 3. Ссылки

- [ ] Наведение — подчеркивание и рука; увести — подчеркивание пропало.
- [ ] Нажатие гасит текст ссылки, отпускание на ней — переход в браузере.
- [ ] Нажать и увести мышь мимо, отпустить — перехода НЕТ.
- [ ] Длинная подпись ссылки переносится по словам, подчеркивание идет по каждой строке.
- [ ] В инструкции: ссылка на другой документ (`[[имя]]` в исходнике) прыгает к нему и
      подсвечивает строку в «Содержании», браузер не открывается.

## 4. Выделение

- [ ] Инструкция: текст выделяется мышью, Ctrl+C копирует, Ctrl+A выделяет весь абзац.
- [ ] Остальные три экрана: текст НЕ выделяется — там его только читают.
- [ ] Tab по экрану инструкции не идет по каждому абзацу.

## 5. Ритм и воздух

- [ ] Просвет между блоками равен пустым строкам исходника: одна пустая строка — один просвет,
      две — два, ни одной — блоки стоят вплотную.
- [ ] Вокруг заголовка просвет в одну строку с КАЖДОЙ стороны, даже если пустых строк в файле нет.
      С пустыми строками — столько же: второй просвет не добавляется.
- [ ] То же в «Динамическом просмотре»: заголовок, приклеенный к тексту, отбит пустой строкой,
      а уже отбитый в файле — не удваивается. Каретка через добавленную пустую строку не встает.
- [ ] Абзац, который переносится на несколько строк, показан ЦЕЛИКОМ. Последняя строка на месте.
- [ ] Под последним блоком воздуха ровно столько же, сколько по бокам (16), а не вдвое больше.
- [ ] Тот же текст в «Заметках» в режимах «Просмотр» и «Динамический просмотр» дает ОДИН и тот же
      просвет между блоками и одну и ту же высоту строк.
- [ ] Прогнать стенд: `dotnet run --project Tests/MarkupLayout -f net10.0` — все проверки должны
      пройти.

## 6. Размер, зум, ширина

- [ ] «Настройки → Оформление → Размер шрифта» — весь markdown на всех четырех экранах
      пересобрался: заголовки, код, просвет между блоками.
- [ ] Размер поменять, находясь в другом разделе, потом вернуться на экран с markdown — вид
      догнал (пересборка при возврате в дерево).
- [ ] Зум 70 / 100 / 130 %: линии таблицы и черта остаются толщиной в один пиксель, скругления не
      зубрятся, текст не мылится.
- [ ] Панель записи: тянуть ручку ширины на описании в 10+ КБ — текст не переверстывается рывками
      (ширина замораживается, см. `FreezeContentWidth`).
- [ ] Сузить окно до минимума — таблица и блок кода переносятся, горизонтальной полосы не
      появляется нигде.

## 7. Мусор на входе

- [ ] Незакрытые `**` и `` ` `` — текст показан как есть, экран не пуст.
- [ ] Битая таблица (`| одна | строка` без разделителя) — показана текстом.
- [ ] Пустое описание расширения и пустая заметка — пусто, без пустой полосы и без ошибки.
- [ ] Переключение между расширениями — прокрутка описания сбрасывается наверх.
- [ ] Заметка на 500+ КБ в «Просмотре» открывается без зависания.
