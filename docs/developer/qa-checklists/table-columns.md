# Чеклист: ширина колонок таблицы конструктора

Ручной прогон стандартной и ручной ширины столбцов: поведение соседних колонок при
перетаскивании, горизонтальная прокрутка, прижатие служебной «+» к правому краю,
зум и DPI, сохранение и перенос ширин. Как устроено —
[features/constructor/table.md](../features/constructor/table.md), раздел «Ширина колонок
в ручном режиме»; про звездную раскладку и «+» — [ui/theming.md](../ui/theming.md).

Автотестами закрыт только слой хранения (аспект `column_meta.Width`: upsert, сброс, дубль,
перенос, экспорт-импорт). Вручную проверяется то, что тестами не берется: **раскладка
DataGrid**, попадание границ на физическую пиксельную сетку и поведение жеста. Все
поведение пришпилено к Avalonia 11.2.3 — после апгрейда Avalonia чеклист прогнать целиком.

★ — пункты, где ошибка приводит к ПОТЕРЕ пользовательских настроек. Их не пропускать.

## Подготовка

- [ ] Коллекция «малая»: 4 колонки (включая «Название»), 10+ записей.
- [ ] Коллекция «средняя»: 12 колонок — умещается в окно не полностью.
- [ ] Коллекция «большая»: 60 колонок, 1000+ записей — для прокрутки и производительности.

## 1. Стандартная ширина

- [ ] «Малая» коллекция: колонки одинаковой ширины, вместе занимают всю ширину окна.
- [ ] Служебная «+» вплотную к правому краю; справа от нее НЕТ пустой полосы и лишней
  вертикальной линии.
- [ ] Колонка «№» узкая и фиксированная, у ее границы захвата нет.
- [ ] Меню заголовка → «Ручная ширина столбцов»: **вид таблицы не изменился** (колонки не
  схлопнулись в узкие). У правых границ заголовков появился курсор «↔».
- [ ] Обратно «Стандартная ширина столбцов» → вид тот же, курсор «↔» пропал.

## 2. Ручная ширина: увеличение

- [ ] Включен ручной режим. Тянуть правую границу ВТОРОЙ колонки вправо:
  - [ ] граница идет строго за курсором, без рывков и отставания;
  - [ ] колонка растет, **соседние справа НЕ меняют свою ширину**, а уезжают вправо;
  - [ ] колонки СЛЕВА не меняются вообще;
  - [ ] когда таблица перестала помещаться — внизу появилась горизонтальная прокрутка;
  - [ ] «+» ушла за правый край и доезжает прокруткой.
- [ ] Отпустить мышь: ничего не прыгнуло, ширины остались как при отпускании.
- [ ] Тянуть границу САМОЙ ПРАВОЙ движимой колонки вправо — работает (встроенный ресайз
  Avalonia это запрещал).

## 3. Ручная ширина: уменьшение

- [ ] Тянуть границу второй колонки влево:
  - [ ] колонки справа расширяются, **пустоты справа не остается**;
  - [ ] «+» остается прижатой к правому краю;
  - [ ] колонки слева не меняются.
- [ ] Вернуть границу в исходную точку в пределах ОДНОГО жеста → исходная картинка.
- [ ] Уменьшать до упора: колонка останавливается на ~48 px, заголовок не ломается,
  шеврон фильтра остается кликабельным, ячейки не наезжают друг на друга.
- [ ] Тянуть границу самой правой движимой колонки влево: упирается в точку «таблица ровно
  заполнена» и дальше не идет (пустоту справа создать нельзя).
- [ ] Клик по шеврону фильтра у правого края заголовка открывает флайаут, а не начинает
  перетаскивание (полоска-захват шириной 8 px не должна перекрывать кнопку).

## 4. Служебные колонки

- [ ] «№» не ресайзится ни в одном режиме и не меняет ширину при перетаскивании соседей.
- [ ] Изменить размер шрифта приложения (число записей стало шире) → «№» подстроилась,
  «+» осталась у края.
- [ ] Скрыть ВСЕ движимые колонки через окно «Отображение» (остались «№» и «+») → нет
  падения и зависания.

## 5. Ресайз окна и сайдбара

- [ ] После ручной настройки ширин расширить окно → место роздано колонкам пропорционально,
  пустоты справа нет.
- [ ] Сузить окно → колонки НЕ сжимаются ниже заданных ширин, появляется горизонтальная
  прокрутка.
- [ ] Развернуть окно обратно → **та же картинка**, что была до сужения (ширины не «поплыли»).
- [ ] То же перетаскиванием границы сайдбара.
- [ ] Граничный случай: подобрать ширину окна так, чтобы таблица была ровно на грани
  заполнения → нет мигания горизонтальной полосы и полоски filler'а справа от «+».

## 6. Зум и DPI

- [ ] Зум 0.7 / 1.0 / 1.3 при DPI 1x, 1.5x, 2x: вертикальные линии колонок целые (не
  размытые и не двойные), линии заголовков совпадают по X с линиями строк.
- [ ] Смена зума при заданных ручных ширинах: пропорции сохранились, границы легли на сетку.
- [ ] Перетащить окно на монитор с другим DPI → то же.
- [ ] **Обязательно на Windows** — там подсветка колонок и линии таблицы ведут себя иначе.

## 7. Операции с колонками

- [ ] Скрыть колонку (окно «Отображение») → остальные добрали место, пустоты справа нет.
- [ ] Показать обратно → ее ширина вернулась прежней.
- [ ] ★ Сохранить окно «Отображение» после перетаскивания → ручные ширины НЕ потерялись.
- [ ] ★ Сдвинуть колонку влево/вправо → ширины не потерялись, колонки не перепутали ширины.
- [ ] ★ Переименовать системную колонку «Название» → ее ширина не потерялась.
- [ ] Добавить свойство (в конец и «создать после текущего») → новая колонка получила
  стандартную ширину, соседи свои ширины сохранили.
- [ ] Удалить свойство → ширины остальных на месте; ширина удаленного не «прилипла» к
  следующему созданному полю.
- [ ] Дублировать свойство, сменить тип поля → ширины соседей не сбросились.

## 8. Сохранение и перенос

- [ ] Перезапустить приложение → ручные ширины на месте, режим тоже.
- [ ] «Стандартная ширина столбцов» → ширины стерты; при повторном включении ручного режима
  НЕ восстанавливаются (это ожидаемо).
- [ ] ★ После сброса ширин проверить, что прочие настройки колонок целы: порядок,
  скрытые колонки, цвет колонки, подпись «Названия».
- [ ] ★ Дубль коллекции → ширины всех колонок доехали, **включая «Название»**.
- [ ] ★ Перенос коллекции в другую группу той же базы (ATTACH) → то же.
- [ ] ★ Перенос коллекции в ДРУГУЮ базу → то же.
- [ ] ★ Экспорт коллекции и импорт обратно → то же.
- [ ] ★ Все перечисленное на базе **PostgreSQL** (проверить, что миграция
  `ColumnMetaWidthPg` применилась).

## 9. Крайние случаи и производительность

- [ ] «Большая» коллекция (60 колонок): перетаскивание не залипает, полоски-захваты не
  остаются за кадром при прокрутке.
- [ ] Прокрутить таблицу вправо и тянуть границу там → граница строго под курсором
  (поправка на горизонтальную прокрутку).
- [ ] Alt+Tab или открытие модального окна прямо во время перетаскивания → жест корректно
  завершился, следующий клик не воспринимается как продолжение перетаскивания.
- [ ] Одновременно включены ручная высота строк и ручная ширина колонок → полоски строк и
  колонок не мешают друг другу, оба жеста работают.
- [ ] Ручная ширина при активном фильтре и сортировке → ширины не сбрасываются.
