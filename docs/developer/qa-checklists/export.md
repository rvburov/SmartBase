# Чеклист: экспорт таблиц

Проверка экспорта во всех состояниях: форматы, пикер коллекций, ручная выгрузка,
раскладка по файлам/листам, ошибки записи, отмена, журнал, права. Как устроено —
[features/import-export.md](../features/import-export/overview.md) (раздел «Экспорт таблиц»),
производительность — [architecture/performance.md](../architecture/performance/overview.md).

Автоматическая матрица (62 проверки той же логики, включая round-trip) —
`Tests/Benchmarks` (`dotnet run -c Release --project Tests/Benchmarks -- export`); вручную важнее
всего визуальные сценарии (окно, пикер, прогресс) и открытие файлов в реальном Excel.

## 1. Окно и режим

- [ ] «Режим» → «Экспорт»: поля импорта сменяются полями экспорта, кнопка —
      «Экспортировать»; обратное переключение возвращает импорт. Окно не «прыгает».
- [ ] «Тип экспорта» → «Ручная выгрузка Excel»: справа раскрывается колонка
      «Параметры ручной выгрузки», окно расширяется вправо (как у ручного импорта).
- [ ] Пояснение под «Тип экспорта» меняется при смене формата (Excel / CSV / JSON —
      3 разных текста).
- [ ] Зум приложения применяется к окну и к выпадающему пикеру коллекций.

## 2. Пикер коллекций

- [ ] Кнопка «Выберите коллекции» открывает выпадающий список с поиском и чекбоксами
      (вид — как у фильтра таблицы: серая плашка, белые карточки).
- [ ] При нескольких подключенных БД коллекции сгруппированы заголовками с именами баз.
- [ ] Поиск фильтрует по имени коллекции И по имени базы; «Ничего не найдено» при пустом
      результате.
- [ ] «(Выделить все)» отмечает/снимает только найденное подмножество; галочка сама
      синхронизируется с состоянием строк.
- [ ] «Готово» применяет выбор; закрытие кликом мимо — отменяет изменения.
- [ ] Текст кнопки: «Выберите коллекции» → имя коллекции (одна) → «N коллекций»
      (склонение: 2 коллекции, 5 коллекций) → «Все коллекции».
- [ ] «Название файла» активно только при одной коллекции (или «в один файл»);
      «Лист» — только при одной коллекции.

## 3. Форматы (тип «Стандартный», одна коллекция)

- [ ] .xlsx — открывается в Excel: кириллица целая, лист назван по коллекции, шапка на
      месте, порядок колонок как в таблице (Название → свойства).
- [ ] .xlsx: числа — числовые ячейки (сортируются как числа), «точечные» даты — настоящие
      даты (сортируются, формат дд.мм.гггг / дд.мм.гггг чч:мм), диапазоны дат — текстом,
      чекбоксы — ИСТИНА/ЛОЖЬ, пустые ячейки действительно пусты.
- [ ] .xlsm — Excel открывает без жалоб (макросов нет).
- [ ] .csv — Excel открывает по двойному клику: кириллица целая (BOM), разделитель «;»,
      даты дд.мм.гггг, отмеченные чекбоксы — 1.
- [ ] .json — валидный массив объектов, кириллица читаемая (не З…), числа/булевы
      без кавычек, даты в ISO.
- [ ] Round-trip: экспортированный файл импортируется обратно без потерь (названия,
      поля, значения).
- [ ] Скрытые записи и скрытые столбцы таблицы в выгрузку НЕ попали (стандартный тип).

## 4. Ручная выгрузка Excel

- [ ] «Лист»: свое имя листа в книге (при одной коллекции).
- [ ] «Исключить столбцы»: `Цена, Комментарий` — столбцов нет в файле; несуществующее
      имя в списке молча игнорируется.
- [ ] Исключение ВСЕХ столбцов → ошибка «Все столбцы коллекции «…» исключены…»,
      файла-огрызка в папке нет.
- [ ] «Без строки заголовков»: первая строка файла — данные.
- [ ] «Включать скрытые записи и столбцы»: скрытое появляется в выгрузке.
- [ ] Ручной тип + формат CSV/JSON → ошибка «Ручная выгрузка доступна только для
      форматов Excel».

## 5. Несколько коллекций и «в один файл»

- [ ] 2–3 коллекции, стандартный тип → файл на коллекцию, имена файлов = имена коллекций.
- [ ] Занятое имя (файл уже есть в папке) → «Имя (2).xlsx», существующий не перезаписан.
- [ ] Одноименные коллекции из разных БД → второй файл с суффиксом «(2)».
- [ ] «Все коллекции в один файл (лист на коллекцию)»: одна книга, листы названы по
      коллекциям, «Название файла» действует (пусто → «Экспорт»).
- [ ] Коллекции из РАЗНЫХ БД в одной выгрузке — данные каждой на месте.
- [ ] Имя коллекции со спецсимволами (`Отчет: 2026/07*`) → файл и лист с «_» вместо
      запрещенных символов.

## 6. Переполнение листа Excel

- [ ] Коллекция > 1 048 575 записей → листы «Имя», «Имя 2», «Имя 3»… с повтором шапки,
      все записи на месте (сумма по листам сходится с числом записей).

## 7. Ошибки записи

- [ ] Пустое поле папки → «Укажите папку для экспорта»; несуществующая папка →
      «Папка не найдена».
- [ ] Ни одной коллекции → «Выберите хотя бы одну коллекцию».
- [ ] Недопустимые символы в «Названии файла» → ошибка валидации сразу в окне.
- [ ] Имя листа длиннее 31 символа или с `[]:*?/\` → ошибка валидации.
- [ ] Экспорт в защищенную папку (например, `C:\Windows`) → «Нет прав на запись в папку…»,
      диалог переоткрыт с теми же значениями.
- [ ] Мульти-экспорт с ошибкой на N-м файле → готовые файлы остаются, баннер называет
      файл и «Экспортировано файлов до ошибки: N».
- [ ] После любой ошибки в папке нет недописанных файлов.

## 8. Отмена и прогресс

- [ ] Фазы «Подготовка…» → «Экспорт записей…»; при нескольких файлах «Файл N из M: имя»;
      проценты растут плавно на большой коллекции.
- [ ] Отмена посреди большой выгрузки: кнопка гаснет, «Отмена…», недописанный файл
      удален, готовые остаются, окно не переоткрывается.
- [ ] Окно прогресса не меняет позицию/размер скачками.

## 9. Результат, журнал, права

- [ ] Успех → папка выгрузки открывается в проводнике.
- [ ] Профиль → История изменений: «{Имя} экспортировал коллекцию «X» (N записей)» —
      строка на каждую выгруженную коллекцию, в журнале БД-источника.
- [ ] Пользователь без допуска к базе не видит ее коллекций в пикере (имитация второго
      пользователя — см. [profile.md](profile.md)).
- [ ] Пользователь с отозванным правом «Просматривать коллекцию» не видит коллекцию
      в пикере.

## 10. Объем (по желанию — уже замерено харнессом)

- [ ] Коллекция ~1 млн строк: экспорт каждого формата идет с живым прогрессом, память
      процесса не растет с объемом (`Tests/Benchmarks -- export --rows 1000000`).
