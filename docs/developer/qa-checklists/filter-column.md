# Чеклист: фильтр колонки — поведение как в табличном редакторе

Ручной прогон окна фильтра колонки в конструкторе: Enter в поиске, автоотметка найденного,
порядок при повторном открытии, каскад между колонками. Как устроено —
[features/constructor/table.md](../features/constructor/table.md#фильтр-колонки-чеклист-значений).

Автотестами закрыто: правила галочек (`FilterSelectionTests`) и каскад счетчиков в SQL
(`ColumnFilterCascadeTests`). Вручную проверяется склейка с UI — перерисовка галочек в
виртуализированном списке, подпись «(Выделить все)», применение по Enter, «Загрузка…» под
каскадом.

Проверяется конструктор; служебные таблицы («Диагностика», «История изменений»,
«Пользователи») делят одно окно `ColumnFilterPanel` с тем же поведением — их прогон в п. 6.

## Подготовка

- [ ] Коллекция с двумя текстовыми свойствами, где значения повторяются — например
      «Город» (Москва/Казань/пусто) и «Статус» (Новая/Готово/пусто), 5–10 записей.
- [ ] Свойство типа «Дата» с записями за несколько месяцев.
- [ ] Коллекция на 100 000+ записей (стенд `Tests/DbGenerator`) — для скорости каскада.

## 1. Enter в поиске

- [ ] Открыть фильтр «Города», набрать «моск», нажать Enter: окно закрылось, в таблице
      только Москва, шеврон стал синей воронкой.
- [ ] Enter в пустом поиске — то же, что «Готово» (ничего не менялось — фильтр не появился).
- [ ] Выбрать сортировку, набрать текст, Enter: применились и сортировка, и отбор разом.
- [ ] Enter, пока список еще показывает «Загрузка…»: окно закрылось, фильтр колонки не
      изменился, выбранная сортировка применилась.

## 2. Поиск отмечает найденное

- [ ] Без фильтра на колонке набрать «каз»: «Казань» показана с галочкой, «(Выделить все)»
      подписан «(Выделить все найденное)» и отмечен.
- [ ] Отобрать Москву, снова открыть фильтр, набрать «каз»: «Казань» **отмечена сама** (до
      правки была без галочки — нужно было ставить руками).
- [ ] Снять галочку с найденного, допечатать букву: галочка вернулась.
- [ ] «(Выделить все найденное)» снять — найденное без галочек; поставить — с галочками.
- [ ] Очистить поиск: подпись снова «(Выделить все)», галочки те же, что были **до** ввода
      (правки внутри поиска не сохранились).
- [ ] Набрать «каз», «Готово»: в таблице только Казань — Москва из прежнего отбора
      отсечена (режим «Заменить», а не «добавить»).
- [ ] Начать печатать, пока висит «Загрузка…»: когда список пришел, найденное отмечено.

## 3. Повторное открытие

- [ ] Отобрать два значения из середины длинного списка, открыть фильтр снова: они стоят
      **первыми** и отмечены, остальные ниже без галочек, «(Выделить все)» снят.
- [ ] Переключить сортировку в окне («От А до Я» ↔ «От Я до А»): отобранные остаются
      сверху, внутри групп порядок меняется.
- [ ] Поставить или снять галочку — строки **не прыгают** (порядок зафиксирован при
      открытии).
- [ ] Отметить все → «Готово»: воронка погасла, фильтр снят.
- [ ] Колонка-дата: дерево в обычном порядке дат, «отобранные первыми» на него не
      распространяется; отобранные дни отмечены.

## 4. Каскад между колонками

- [ ] Отобрать в «Городе» Москву, открыть «Статус»: в списке только статусы московских
      записей, счетчики — московские (сумма счетчиков = числу строк в таблице).
- [ ] «(Пусто)» в «Статусе» есть, только если у московских записей есть пустой статус.
- [ ] Снова открыть «Город»: список городов **полный** (свой фильтр список не режет),
      Москва отмечена и стоит первой.
- [ ] Отобрать в «Статусе» «Новая», открыть «Город»: только города записей со статусом
      «Новая» (каскад в обе стороны).
- [ ] Скрыть запись в окне «Отображение записей»: ее значения пропали из списков и
      счетчиков.
- [ ] Отобрать в «Статусе» все, что есть в списке → воронка на «Статусе» погасла (фильтр
      снят, хотя по всей колонке значений больше).
- [ ] Ситуация «значение фильтра спрятано чужим фильтром»: «Город» = Москва + Казань,
      «Статус» = Готово (у Казани нет «Готово»). Открыть «Город» → Казани в списке нет;
      «Готово» без правок → фильтр «Города» не изменился, снять фильтр «Статуса» → Казань
      снова в таблице.
- [ ] Колонка-связь: каскад по фильтру другой колонки и по «(нет связей)».
- [ ] Большая коллекция: окно открывается сразу, под «Загрузка…» каскад досчитывается
      за разумное время (единицы секунд, не минуты); фильтр с одной колонкой и без
      фильтров — как раньше.

## 5. Дерево дат

- [ ] Набрать «август»: ветка раскрыта, все ее дни отмечены сами, «(Выделить все
      найденное)» отмечен.
- [ ] Enter → в таблице только август.
- [ ] Очистить поиск → галочки как до ввода.

## 6. Служебные таблицы — то же поведение

Прогнать в «Настройки → Диагностика», «Профиль → История изменений» и в таблице
пользователей панели администратора:

- [ ] Отобрать значение в одной колонке, открыть другую: в списке только значения отобранных
      строк, счетчики — по ним; своя колонка при повторном открытии показывает полный список,
      отобранное стоит первым и отмечено.
- [ ] Набрать текст в поиске — найденное отмечено само, подпись «(Выделить все найденное)»;
      Enter применяет отбор и закрывает окно; очистка поиска возвращает прежние галочки.
- [ ] «От А до Я» в «Действии» и «Типе» (история) и в «Уровне» (диагностика) идет по подписям
      в ячейках: «Изменение» раньше «Создания», «Ошибка» раньше «Предупреждения»; прокрутка к
      концу догружает страницы без пропусков и повторов.
- [ ] Даты без выбранной сортировки — новыми сверху; у пользователей «Подключен» и «Последняя
      активность» отбираются деревом и сортируются по времени, а не по числу месяца.
- [ ] Фильтр ничего не пропустил — надпись «Нет записей, подходящих под фильтры.».
- [ ] Сменить фильтр, пока грузится страница большого журнала, — таблица заполняется, а не
      остается пустой.
