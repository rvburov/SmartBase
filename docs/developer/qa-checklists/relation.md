# Чеклист: тип свойства «Связь»

Ручной прогон типа `relation`: создание поля, показ в ячейке, пикер и переходы, кардинальность,
разделители, дубль/перенос/удаление, календарь и задачи, межбазовые связи, фильтр и сортировка.
Как устроено — [data-types/relation.md](../architecture/data-types/relation.md), межбазовый перенос —
[cross-database-move.md](../features/import-export/cross-database-move.md).

Репозиторный слой закрыт автотестами (`Tests/Integration/RelationLinkTests.cs`, ~30 проверок:
кардинальность, каскады, дубль, межбазовый перенос коллекции и группы, перенос записи из календаря,
состав окон-предупреждений). Вручную важнее всего то, что тестами не берется: **UI-переходы между
базами**, тексты окон и показ в виртуализованной таблице.

★ — пункты, где ошибка приводит к ПОТЕРЕ или ПОДМЕНЕ данных. Их не пропускать.

## Подготовка

- [ ] Открыты две базы: «Основная» и вторая (напр. `test_database`).
- [ ] В «Основной» — коллекции «Задачи» (несколько записей) и «Проекты» («Сайт», «Инфра», «CRM»).
- [ ] Во второй базе — коллекция «Клиенты» («ООО Ромашка», «ИП Иванов»).
- [ ] Для раздела 11 пригодится возможность временно **убрать файл** второй базы (переименовать/
  отключить сетевой том). Кнопкой «Отключить» в настройках пользоваться НЕЛЬЗЯ — см. раздел 14.

## 1. Создание и настройка поля

- [ ] В «Задачах» добавить колонку → тип «Связь», «Целевая база» = Основная, «Целевая коллекция» =
  Проекты → сохранить. Колонка появилась, все ячейки серые «связи нет».
- [ ] Открыть поле на редактирование: подпись — **«Количество связей»**, значение по умолчанию —
  **«Одну»**. При смене целевой базы кардинальность не сбрасывается.
- [ ] Добавить поле «Связь» с целевой базой = вторая, коллекция = Клиенты. Сохраняется **без
  открытия** второй базы в сайдбаре.
- [ ] Добавить поле «Связь» с целью = сама коллекция «Задачи» (само-связь). Сохраняется без ошибок.

## 2. Отображение в ячейке

- [ ] Выбрать один проект → в ячейке его название.
- [ ] Переключить поле на «Несколько», выбрать 2–3 → названия через выбранный разделитель.
- [ ] Переименовать запись-цель (открыть «Проект» в панели, сменить название) → в ячейке-связи
  «Задач» имя обновилось **сразу**, без прокрутки.
- [ ] Прокрутить большую таблицу вниз и обратно → связи не пропадают и не путаются между строками.
- [ ] То же на таблице **20 000+ строк** с несколькими колонками-связями: после долгой прокрутки
  переименование цели по-прежнему обновляет ячейку сразу (см. ограничение в разделе 14).

## 3. Пикер и переход к записи

- [ ] Клик по иконке-связи в ячейке → список записей целевой коллекции, поиск по названию работает.
- [ ] Поиск в пикере не различает регистр, и у кириллицы: «договор» находит «Договор» и
      «ДОГОВОР»; «50%» находит «Скидка 50%», но не «Скидка 500».
- [ ] Поставить/снять галочки → ячейка обновилась сразу.
- [ ] Коллекция >200 записей → показаны первые 200 и серая подсказка «Показаны первые 200 — уточните
  в поиске»; поиск находит остальные.
- [ ] ★ «Карандаш» у пункта открывает **именно ту** запись, в ее базе. Проверить все четыре случая:
  - [ ] цель в этой же базе;
  - [ ] цель в другой базе — открывается запись из ее базы, со схемой ее коллекции;
  - [ ] само-связь;
  - [ ] **поле перенастроено на другую базу** (см. 13.2) — переход по старому ребру ведет в его
    прежнюю базу, а не в текущую цель конфига.
- [ ] ★ То же, но **введя текст в поиск** пикера. Выбранная межбазовая цель остается в списке с
  галочкой (не исчезает), «карандаш» на ней ведет в ее базу.
- [ ] ★ Открыть запись из **другой** базы переходом, и из нее перейти по ее внутрибазовой связи →
  открывается запись той же чужой базы, не активной.
- [ ] Переход к записи, которой уже нет → тост «Связанная запись не найдена в своей базе»,
  пустая карточка НЕ открывается.
- [ ] Переход при недоступной целевой базе → тост «База связанной записи недоступна».

## 4. Кардинальность

- [ ] «Одну»: выбрать запись, затем другую → вторая заменяет первую.
- [ ] «Несколько»: выбирать подряд → связи накапливаются.

## 5. Разделитель названий

- [ ] В списке ровно **7** вариантов: через запятую, через точку, через пробел, через точку с
  запятой, с новой строки, через запятую без пробела, через точку без пробела.
- [ ] «Через точку без пробела» при 2+ связях → `Сайт.Инфра` (точка без пробела).

## 6. Дубль записей

- [ ] Продублировать запись со связями → у копии те же связи, у оригинала не изменились.
- [ ] Выделить несколько записей со связями → дубль → связи скопированы у всех копий.

## 7. Перенос ЗАПИСЕЙ

- [ ] Перенести запись в другую коллекцию той же базы → ее исходящие связи сохранились.
- [ ] Перенести запись в коллекцию другой базы → связи сохранились (внутрибазовая на источник стала
  межбазовой).
- [ ] Перенести запись, на которую ссылались → у ссылавшихся стало «связи нет» (связь за записью не
  следует).
- [ ] ★ Перенос записи, на которую ссылаются → окно с пунктом «оборвутся связи, ссылающиеся на
  переносимые записи». Если ссылок нет — этого пункта нет.
- [ ] ★ Перенос в коллекцию, где **нет** части полей, с **выключенной** галочкой «Перенести все
  свойства» → окно перечисляет пропадающие свойства **поименно**. Отмена ничего не меняет.
- [ ] С включенной галочкой → пункт про свойства исчезает (недостающие поля создаются).
- [ ] ★ Перенос в коллекцию, где одноименное поле-связь смотрит на **другую** коллекцию → окно:
  «потеряются связи в полях: …». Поле переедет, связи — нет.
- [ ] Кнопка подтверждения в этих окнах называется **«Перенести»**, не «Удалить».
- [ ] Повторный перенос той же записи (и возврат обратно) окна про обрыв **не показывает** — это
  ожидаемо, см. раздел 14.

## 8. Перенос КОЛЛЕКЦИЙ и ГРУПП

Каждый пункт проверить **двумя путями**: контекстное меню «Расположение» и смена базы в окне
«Изменение». Раньше окно стояло только на первом.

- [ ] Перенести коллекцию в другую базу (SQLite→SQLite) → само-связи остались внутри копии, внешние
  стали межбазовыми на источник, названия показываются корректно.
- [ ] ★ Межбазовый перенос коллекции, на записи которой ссылаются **извне** → окно «Межбазовый
  перенос оборвет связи, ссылающиеся на переносимое».
- [ ] ★ Межбазовый перенос коллекции, где связи — **только само-связи внутри нее** → окна нет,
  связи переносятся.
- [ ] ★ Межбазовый перенос **группы** → окно строже: «будут потеряны и связи ВНУТРИ переносимого,
  и ссылки на него». Проверить и вариант, когда ветка ссылается **только наружу** (входящих в
  нее нет) — окно все равно должно быть.
- [ ] После межбазового переноса группы: поля-связи на месте и показывают **верную** целевую
  коллекцию (не чужие записи целевой базы), связи пусты.
- [ ] ★ Перенос коллекции/группы **внутри** той же базы (в другую группу) → окна нет, связи целы.
- [ ] ★ Любой перенос с участием **PostgreSQL** → окно «Перенос с участием PostgreSQL связи НЕ
  переносит…», в том числе для коллекции с одними само-связями.

## 9. Удаление

- [ ] Удалить запись-цель в своей базе → у ссылавшихся стало «связи нет».
- [ ] Удалить поле-связь → все его связи ушли, соседние поля целы.
- [ ] Удалить запись-источник → ее связи ушли, входящие на других не тронуты.
- [ ] ★ Удалить несколько записей, на которые ссылаются, **в таблице** → в окне «На них ссылаются
  связи из других записей — они будут удалены».
- [ ] ★ То же **в календаре / журнале / расписании / диаграмме** → та же вставка про связи.
- [ ] ★ Удалить запись в режиме **«Список»**: со ссылками — окно есть, без ссылок — удаление сразу
  без окна. В **таблице** окно показывается всегда (это ожидаемо, см. раздел 14).
- [ ] ★ Удалить коллекцию/группу, на записи которой ссылаются → «Также будут удалены связи,
  ссылающиеся на удаляемое».

## 10. Календарь и задачи

Разделы 8 и 9 (коллекции, группы, поля) здесь перепроходить не нужно — сайдбар и конструктор общие.
Проверяем то, что у календаря и задач свое: окно записи и перетаскивание.

- [ ] Перетащить/растянуть событие по датам (Месяц, Неделя, День, Диаграмма) → связи целы, окна нет
  (id записи не меняется).
- [ ] Удалить записи выделением/контекстным меню в **каждом** режиме (Список, Журнал, Месяц, Неделя,
  День, Диаграмма) → вставка «На них ссылаются связи из других записей — они будут удалены».
- [ ] ★ Кнопка «Удалить» **внутри окна записи** календаря → то же предупреждение. Без входящих связей
  окна нет.
- [ ] ★ Сменить в окне записи **коллекцию** → окно «Перенос пересоздает запись: связи… оборвутся»,
  кнопка «Перенести». После переноса **исходящие связи записи на месте** (это и была потеря).
- [ ] ★ То же со сменой **базы** → связи переехали, внутрибазовая на источник стала межбазовой.
- [ ] Правка записи без смены места (дата, название, поле-дата) → окна нет.
- [ ] ★ Окно задачи: «Удалить» и смена коллекции → те же два предупреждения. Выбора базы при
  редактировании задачи нет — это ожидаемо.
- [ ] Перенос в коллекцию, где одноименного поля-связи нет или оно смотрит на другую цель → связи не
  переезжают (как в таблице).
- [ ] ★ Дубль записи в **каждом** режиме календаря → у копии те же связи и те же свойства, что при
  дубле этой же записи из таблицы. Копия встает сразу после оригинала.
- [ ] Выделить два события ОДНОЙ записи (два поля-даты) → дубль создает **одну** копию, и она видна
  в обоих местах; окно считает записи, а не события.

## 11. Межбазовые связи

- [ ] Межбазовая связь на запись во второй базе, **вторая база не открыта** в сайдбаре → название
  цели все равно показывается.
- [ ] ★ Удалить/перенести запись-цель во второй базе (база доступна) → у источника «связи нет».
  Состояния «(запись удалена)» быть не должно.
- [ ] ★ Сделать целевую базу недоступной **пропажей файла** (переименовать файл / отключить том) →
  в ячейке «(база недоступна)», связь **держится**.
- [ ] Вернуть файл → название снова появляется (после прокрутки или переоткрытия коллекции, см.
  раздел 14).

## 12. Фильтр и сортировка

- [ ] ★ Фильтр на колонке-связи, в том числе **межбазовой** → в чек-листе реальные названия целей
  со счетчиками и пункт «(нет связей)». Отметка нескольких работает как ИЛИ.
- [ ] Недоступная целевая база → в списке значений «(база недоступна)».
- [ ] ★ Сортировка по колонке-связи (А→Я / Я→А) — по показанному тексту, включая межбазовые
  названия; записи без связей уходят в конец.
- [ ] На большой таблице фильтр/сортировка по связи не подвешивают интерфейс.

## 13. Пере-настройка цели поля

- [ ] ★ Сменить «Целевую коллекцию» на другую в той же базе → старые связи держат свое название,
  пикер тянет кандидатов из новой коллекции.
- [ ] ★ Сменить «Целевую базу» на другую → старые ребра показывают свое **реальное** имя (без
  подмены и без ложного «связи нет»), новые выборы — из новой базы.
- [ ] ★ Переключать целевую базу туда-обратно → показ стабильный, не «прыгает».

## 14. Известные ограничения — НЕ баги

Проверять их «на работоспособность» бессмысленно; убедиться, что поведение именно такое.

- **Окно об обрыве одноразовое.** Проверяются ВХОДЯЩИЕ связи. Первый перенос рвет их насовсем, у
  записи новый id — поэтому повторный перенос (и возврат обратно) окна не показывает. Чтобы увидеть
  его снова, надо создать новую входящую связь.
- **Перенос ветки-группы между базами не переносит связи.** Конфиги полей правятся (поле указывает
  на верную цель), сами ребра — нет. Окно предупреждает.
- **PostgreSQL не переносит связи** ни при каких переносах. Окно предупреждает.
- **Кнопка «Отключить базу» в настройках убивает межбазовые связи навсегда.** Она удаляет строку
  реестра, при повторном подключении база получает новый номер, и старые ребра остаются висячими.
  Диалог обещает «можно подключить снова» — это про файл, не про связи.
- **Смена пути к файлу базы** дает тот же эффект: реестр опознает базу по точному пути, новое место =
  новая база = обрыв межбазовых связей на нее.
- **Переименование межбазовой цели** обновляет имя в ячейке-источнике после прокрутки, не мгновенно.
  Возврат недоступной базы тоже требует прокрутки.
- **Совпадение id в смешанной ячейке.** Если у одного поля есть ребра на записи с ОДИНАКОВЫМ id в
  разных базах (достижимо лишь после межбазового переноса коллекции при перенастроенном поле), то
  при правке ячейки одно из них исчезнет: `SetLinks` различает ребра только по `ToRecordId`.
- **Удаление со страницы записи** отдельно не проверяется: кнопки «Удалить» на панели записи нет, а
  схема-режим `RecordDialog` в UI не создается.
- **Смена коллекции в календаре и задачах пересоздает запись.** Исходящие связи переезжают, входящие
  оборвутся (у записи новый id) — ровно как при переносе из таблицы. Окно предупреждает.
