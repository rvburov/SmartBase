# Чеклист: PostgreSQL — помощник, создание базы, настройки и данные подключения

Окна работы с сервером PostgreSQL: помощник установки (`PgServerHelpDialog`),
создание базы с ролью-владельцем (`PgCreateDatabaseDialog` + `PgDatabaseCreator`),
настройки базы (`DbSettingsDialog` — шестеренка в строке) и сводка
«Данные подключения» (`PgDetailsDialog`). Устройство —
[features/settings.md](../features/settings.md), руководство —
[user/postgresql-server.md](../../user/postgresql-server.md).

Подготовка: тестовый стенд `sb-pg` на порту 5455
([testing/automated-tests.md](../testing/automated-tests.md)); проверки идут на нем,
чтобы не трогать настоящий сервер.

## 1. Помощник «Сервер PostgreSQL»

- [ ] В окнах «Подключить сервер PostgreSQL» и «Создать базу данных PostgreSQL»
      сверху есть ссылка «Нет сервера? Установка…»; клик открывает помощник.
- [ ] Окно сразу само проверяет `localhost:5432` и показывает статус; поля сервера
      и порта редактируются, «Проверить» перепроверяет.
- [ ] Порт работающего сервера (стенд: 5455) — зеленое «Сервер работает — порт N
      отвечает».
- [ ] Порт без сервера на этой машине: если PostgreSQL установлен (brew/EDB/apt) —
      «Сервер установлен, но не запущен»; если следов нет — «Сервер не найден».
- [ ] Чужой адрес (например `192.0.2.1`) с закрытым портом — «Сервер … не отвечает —
      проверьте адрес, порт и сеть» (не «не найден»: чужую машину по каталогам
      не проверяем).
- [ ] Под статусом — приписка про предел проверки (порт/докер); инструкция в серой
      карточке соответствует текущей ОС; на Windows в ней упомянуты права
      администратора у установщика (UAC).
- [ ] «Скачать PostgreSQL» открывает страницу загрузки postgresql.org для текущей ОС.
- [ ] Escape и «Закрыть» закрывают окно; кривой порт («0», «abc») дает понятную
      ошибку в статусе, а не падение.

## 2. Создание базы на сервере

- [ ] «Настройки → Управление базой данных» → «Добавить базу данных» → в меню
      четвертый пункт «Создать базу данных PostgreSQL»; выбор открывает окно и
      сбрасывает выпадашку.
- [ ] «Проверить соединение» с верным администратором (стенд: localhost:5455,
      postgres/postgres) — зеленое «Соединение установлено (PostgreSQL 16.x)»;
      с неверным паролем — «Неверный пароль или пользователь».
- [ ] Роль-владелец зеркалит имя базы, пока ее не правили руками; после ручной
      правки зеркалирование выключено.
- [ ] «Сгенерировать» заполняет пароль роли 16 знаками, пароль виден открыто и
      копируется.
- [ ] Валидация имен: заглавные, кириллица, дефис, пробел, имя с цифры, длина > 63 —
      красный баннер с объяснением; окно не прыгает при показе/скрытии баннера.
- [ ] Успешное создание: база появляется в списке с бейджем «PostgreSQL», монтируется
      в фоне, схема строится, поверх показано окно «Данные подключения».
- [ ] Повторное создание с тем же именем базы — ошибка «База с таким именем уже
      есть на сервере…» (42P04), ничего не ломается.
- [ ] Имя существующей роли с ЕЕ паролем — база создается, роль переиспользуется;
      с ДРУГИМ паролем — понятная ошибка «База создана, но подключиться ролью не
      удалось…», нерабочая связка в список НЕ попадает.
- [ ] После проверок снести тестовые базы со стенда:
      `psql -p 5455 -U postgres -c 'DROP DATABASE <имя> WITH (FORCE)'` +
      `DROP ROLE <роль>`.

## 3. Настройки базы и данные подключения

- [ ] Шестеренка в строке любой базы открывает «Настройки базы данных»; переименование
      («Название в списке») сразу обновляет и список, и левую панель — без ремаунта.
- [ ] У PG-базы в окне настроек: живой статус сервера (для стенда — зеленое «Сервер
      работает — порт 5455 отвечает»; остановить контейнер — красное «не отвечает»),
      ссылка «Установка и автозапуск сервера…» открывает помощник с адресом и портом
      ЭТОЙ базы; у SQLite-базы этой секции нет.
- [ ] Кнопка «Данные подключения» (только у PG) показывает сервер/порт/базу/
      пользователя/SSL; пароля в окне нет, есть приписка «сообщите его коллеге отдельно».
- [ ] «Скопировать» кладет сводку в буфер (вставить в редактор: пять строк
      «Сервер: …» и т.д., пароля нет), показывается зеленое «Скопировано».
- [ ] Значения выделяются мышью по одному (SelectableTextBlock).
- [ ] То же окно «Данные подключения» открывается сразу после создания базы (п. 2).
- [ ] Смена пароля подключения: ввести неверный пароль → «Сохранить» дает красный
      баннер «Неверный пароль или пользователь», реестр не изменен; ввести верный →
      сохраняется, база продолжает работать (и переживает перезапуск программы).
- [ ] Пустое поле пароля при «Сохранить» ничего не меняет (это смена, а не проверка).

## 4. Кроссплатформенность

- [ ] Linux/Windows: CI (job `postgres`) гоняет `PgProviderTests` и
      `PgCreateDatabaseTests` на живом сервере — зеленый прогон с «Skipped: 0».
- [ ] Ручной проход окон на Windows и Linux (формулировки UAC, статусы служб,
      детект каталогов установки) — **пока не выполнялся**; при первом прогоне
      на этих ОС пройти разделы 1–3 целиком.
