# Свойство: «Итог по связи» (`rollup`)

Часть [реестра типов](overview.md). Вычисляемое поле по [связи](relation.md):
`count`, `sum`, `avg`, `min`, `max` и итоги по датам `earliest`/`latest`. Значение не сохраняется
в `db_field_values` и не правится вручную. Итог в каждой записи относится к ее связям, а не ко
всем строкам колонки. Как и [lookup](lookup.md), столбец создается в окне своей связи и удаляется
вместе с ней.

`earliest` и `latest` берут значение свойства-даты цели целиком (с временем и диапазоном) в
ISO-каноне: самая ранняя — по началу, самая поздняя — по концу; дата аудита приводится к
локальному времени. Показ (`FieldTypeInfo.FormatComputedDisplay`) и сортировка
(`ColumnSort.RollupKey`) отличают дату итога от числа по ISO-канону.

`RelationComputedConfig` задает `relationFieldId`, `targetField` и `aggregate`. Для `count`
считаются отдельные доступные существующие цели, выбор числового свойства не нужен.
Для числовых операций настройка проверяет числовой тип целевого свойства, для итогов по
датам — тип-дату; вычисление
использует его исходное значение, а не показ с разрядами или валютой.

Читатель — `ConstructorRepository.RelationComputed`: пакетная загрузка ребер и свойств,
общий с [lookup](lookup.md) контроль прав, контекстов и циклов. Хранение результата в памяти
страницы — инвариантное число; форматирование выполняется при показе. Сортировка числовая.
Фильтр, страница записи и экспорт вычисляют результат из текущих значений целей.

Копирование и перенос переписывают ссылку на локальное поле-связь и выбранное свойство
цели; промежуточное вычисленное значение не копируется как редактируемый текст.

Проверки: `RelationComputedTests`, `RelationComputedConfigTests`,
`Tests/RecordPage --only relationcomputed`.
