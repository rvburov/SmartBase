# Свойство: «Файл» (`file`)

Часть [реестра типов свойств](overview.md). Единый источник классификации — [`FieldTypeInfo`](../../../../Core/Models/FieldTypeInfo.cs).


**Ссылки на файлы на диске, без копирования.** Один абсолютный путь в `db_field_values`
остается обычной строкой, как прежде. Несколько найденных файлов хранятся в той же строке
JSON-объектом `{"paths":["/папка/первый.pdf","/папка/второй.pdf"]}`. Столбцы таблицы не меняются.
Для раскрытия списка в библиотеке PostgreSQL используется SQL-функция из парных
миграций `MultipleFilePaths` / `MultipleFilePathsPg`.
Файлы никуда не копируются, папок рядом с БД не создается.

Разбор и запись — [`FileValue.ReadPaths` / `Serialize`](../../../../Core/Models/FileValue.cs):
пустой список записывается как `""`, один путь — как прежняя строка, несколько — как объект
со строковым массивом `paths`. При записи порядок сохраняется, пустые пути и повторы одного пути
отбрасываются с `Ordinal`-сравнением. При чтении повторяющиеся пути сохраняются; SQL библиотеки
также сохраняет исходный индекс каждого непустого пути для адресации документа.
Разбор некорректного или постороннего JSON сохраняет
значение как один прежний путь. Запятая служит разделителем только в показе: имя файла
может содержать запятые, поэтому пути никогда не разбиваются через `Split(',')`.

## Показ (одинаково в таблице и на странице записи)

| Состояние | Что видно |
|---|---|
| Есть файл (путь ведет к существующему файлу) | имя файла с расширением — **синяя подчеркнутая ссылка**; клик открывает файл штатным приложением ОС |
| Найдено несколько файлов | до 8 имен через запятую, каждое — отдельная ссылка; кнопка `+N` открывает полный виртуализированный список |
| Путь задан, но файла нет | `имя.ext — файл не найден` (серым) |
| Пусто | серое некликабельное `Выбрать файл…` |

Путь, созданный в одной ОС (`C:\…`), в другой (`/…`) не резолвится — это не ошибка данных,
просто показывается «файл не найден».

## Правка (по аналогии с типом «дата»)

Редактор — [`FileEditor`](../../../../Controls/Widgets/FileEditor.axaml.cs), общий для таблицы и
страницы записи:

- **Правая иконка-скрепка** (`IconFieldFile`, доступна в ручном режиме) — открывает системный выбор
  файла (`StorageProvider.OpenFilePickerAsync`), путь подставляется в значение.
- **Ручной ввод пути** — двойной клик по значению (или клик по «файл не найден») превращает
  показ в текстовое поле с полным путем; ввод/правка/очистка вручную. Коммит — Enter или уход
  фокуса; Escape отменяет.
- **Проверка при ручном вводе:** непустой путь без существующего файла → текст поля **красный** +
  плашка-уведомление [`NoticeBanner`](../../../../Controls/Widgets/NoticeBanner.axaml.cs)
  («Укажите путь и наименование файла»), которая держится, пока путь не станет верным или поле не
  покинут. После коммита неверный путь сохраняется и показывается как «файл не найден».
- **Имя файла** для показа (ссылка, «файл не найден», список значений фильтра, журнал изменений) —
  общий источник [`FileValue.DisplayName`](../../../../Core/Models/FileValue.cs): из каждого пути берется
  базовое имя, несколько имен соединяются запятой, а значение, доставшееся от прежнего типа поля,
  показывается по прежним правилам. В журнале
  правок (`SetFieldValue` → `ChangeDetail`) «до → после» тоже сворачивается до имени файла, а не
  абсолютного пути.

Открытие файла — `Process.Start(UseShellExecute=true)` (делегирование ОС: `open`/ассоциация/
`xdg-open`). Иконка типа — скрепка `IconFieldFile` (реестр [`Icons.axaml`](../../../../Assets/Styles/Icons.axaml)),
используется в шапке колонки, диалоге свойства и на карточке записи.

## Тумблер «Добавить в библиотеку документов»

В диалоге свойства у типа «Файл» есть тумблер, включающий столбец в раздел
[«Библиотека документов»](../../features/library.md) — ровно так же, как «Отображать в
календаре» включает поле-дату, а «Добавить в раздел задач» — user-поле. Он поднимает флаг
`IsDocFile` на `db_fields` (миграция `AddDocFieldFlags`) и доводит коллекцию до полного набора
ролей раздела: заводит или подтягивает по имени столбец **«Тип документа»** (`select`,
`IsDocType`).

Отличие от задач — **роль не эксклюзивна**: файловых столбцов у коллекции может быть сколько
угодно, и каждый дает разделу свои документы («Оригинал» и «Скан» — это два разных документа
записи). Коллекция уходит из раздела только когда выключен последний столбец.

Выключение ничего не удаляет: снимается один флаг, столбцы и значения остаются. Смена типа
снимает флаг записью (`ClearRolesIncompatibleWithType`), удаление столбца работает обычным
каскадом; оба случая окно предупреждает словами из
[`FieldRoleText`](../../../../Utils/FieldRoleText.cs).

Раздел читает **только непустые** пути: строка без ссылки документом не считается.

## Автоподстановка файлов

### Включение и совместимость

Явный `ToggleSwitch` **«Автоподстановка файлов»** включает подбор из папки по свойству.
Новое свойство создается в ручном режиме, тумблер выключен. Старое корректное правило без
`enabled` остается включенным: обновление не переводит существующие авто-колонки в ручные.

Настройки сохраняются в `ConfigJson` — [`FileAutoRule`](../../../../Core/Models/FileAutoRule.cs):
`{ "auto": { "source": "…", "folder": "…", "format": "pdf", "recursive": true, "partialMatch": false, "enabled": true } }`.
`source` — `__title__` для системного «Названия» или строковый Id текстового поля;
старый `sourceFieldId` читается для совместимости. Чтение сохраненных настроек отделено
от проверки, можно ли применять включенное правило.

Выключение сохраняет уже найденные пути и параметры правила, возвращает ручной выбор и ввод.
Выключенное правило не реагирует на правки источника. Тумблер, источник, папка, формат,
рекурсивность и частичное совпадение меняют только черновик диалога до **«Сохранить»**.
Сохранение включенного правила применяет его ко всей колонке; замена прежних значений
подтверждается в диалоге. Сохранение выключенного правила пути не очищает.

### Сопоставление

- Источник — системное **«Название»** или поле `text`, включая обычное поле «Описание».
  Папка выбирается системным диалогом; формат — из списка или свой.
- По умолчанию имя совпадает точно: `значение_источника` + «.» + `формат`.
  Регистр учитывается. При одном имени в нескольких подпапках сохраняется прежнее правило:
  точный режим выбирает первый перечисленный путь.
- **«Частичное совпадение имени»** по умолчанию выключено. Во включенном режиме значение
  источника ищется обычной подстрокой с `Ordinal`-сравнением в имени без суффикса «.» + формат.
  Составной формат `tar.gz` снимается целиком. Папки и расширение в подстрочном поиске не участвуют,
  `*` не является шаблоном; пустой или пробельный источник не дает совпадений.
- Частичный режим сохраняет все разные полные пути, включая одноименные файлы из разных
  подпапок. Пути упорядочиваются через `StringComparer.Ordinal` и записываются `FileValue.Serialize`.
- **«Искать во вложенных папках»** у нового правила включено. Отсутствующий `recursive`
  у старого правила означает `false`: область поиска не расширяется молча.

### Дисковый каталог и атомарное применение

Каталог имен строится потоком в **локальном SQLite-кеше**, без списка всех файлов в RAM.
Точные имена ищутся по индексу, для подстроки FTS5 `trigram` отбирает кандидатов, после чего
совпадение обязательно перепроверяется по исходным строкам с `Ordinal`. FTS не определяет
окончательные правила регистра и совпадения. Это каталог метаданных путей, не копия файлов.
Кеш пересобираемый, не является пользовательскими данными и не хранится в общей базе.
Короткие или неиндексируемые подстроки, а также отсутствие поддержки FTS5 `trigram`, используют
потоковый проход по дисковому каталогу в фоне с отменой; результат поиска остается тем же.

**«Сохранить»** включенное правило и **«Обновить привязку»** обновляют каталог перед подбором.
Правки источника используют готовый неизменяемый снимок каталога. Активный читатель держит
lease: обновление или вытеснение кеша не удаляет его снимок до завершения чтения. Непрерывного
watcher папки нет. Полученные значения сначала пишутся в staging; финальная атомарная запись
в `db_field_values` повторно проверяет конфигурацию, Id записей, значения источника и прежние
file-значения. Изменившиеся
данные или правило дают конфликт вместо записи устаревшего результата.

Слишком широкий результат — **больше 10 000 различных полных путей на ячейку** или **больше
4 × 1024 × 1024 символов** в сумме путей либо сериализованной строке — дает `TooManyMatches`.
Длина измеряется как `String.Length` (единицы UTF-16), а не размер UTF-8 на диске.
Список не обрезается: прежние значения
сохраняются, человеку предлагается уточнить поиск. Недоступный каталог, отмена и конфликт
также не заменяют сохраненные значения пустым или частичным результатом.

### Фоновые реакции и показ

Все вызванные UI обходы и запросы к каталогу выполняются в фоне, с задержкой повторяющегося
ввода (`debounce`), отменой устаревшей работы и отдельным свежим контекстом. Правка источника
обновляет авто-файлы реактивно; результат применяется к кешу ячейки и панели, не сбивая ввод
и каретку. Долгий полный проход показывает прогресс и отмену. UI-поток не собирает весь
каталог и не проверяет доступность каждого пути синхронно.

`AddRecord`, `AddRecordIsolated` и `AddCalendarRecord` запускают включенные правила новой записи,
если источник уже заполнен. Пустой источник ждет обычной правки; выключенное правило не подбирает
файлы ни при создании, ни при правках. В приложении работа попадает в фоновую очередь после
commit исходной транзакции; rollback отменяет накопленные задания. Без главного окна сохраняется
синхронный контракт API. Синхронный подбор проверяет, что исходное свойство принадлежит той же
коллекции и имеет тип `text`, либо используется системное «Название».
Изменение названия через `UpdateRecord` и `UpdateCalendarRecord` также запускает реакцию
правила по названию; перестановка записи или изменение одной даты ее не запускает.
При переносе календарной записи между коллекциями начальный подбор отложен до копирования
всех свойств. Затем применяется правило целевой коллекции, одинаково в API и фоновом режиме.

Автоподстановка использует тот же атомарный путь при обычной и изолированной записи.
Старые маски прав не пропускают работу и не меняют результат. Сохраняются проверки
свежести конфигурации, принадлежности записи и значения источника перед финальным применением.

`FileAutoCreationTests` покрывают создание с заполненным источником, выключенное правило,
commit/rollback, недоступную папку и некорректный источник. Сохранность данных после
удаления ограничений проверяют тесты совместимости старых метаданных.

Проверки существования файлов ограничены по объему, одинаковые запросы объединяются и
выполняются в фоне. В ячейке/редакторе показывается не более **8 отдельных ссылок**, полный
набор доступен в виртуализированном списке. В авто-режиме ручного ввода и скрепки нет;
выключение автоподстановки возвращает их, сохраняя пути.

Фильтр проверяет принадлежность **любого полного пути** ячейки выбранному набору, варианты
фильтра содержат отдельные пути. Совпавшая подпись файла не заменяет полную идентичность пути.
Старый сохраненный групповой ключ с несколькими путями сохраняет точное сравнение исходной
JSON-строки, включая порядок и пробелы: он не превращается в «ИЛИ» отдельных путей. Такой ключ
может сосуществовать с новыми выбранными путями, но новые варианты фильтра его не предлагают.
Сортировка использует показ имен и стабильный keyset-ключ, чтобы одноименные файлы не терялись
и не повторялись между страницами.

### Проверка масштаба (21.10.2026)

`RecordPage --only fileload --files 10000000` на облачном Linux прошел на **10 млн
синтетических имен**, записанных в настоящий временный SQLite-каталог с FTS5 `trigram`.
Это не обход 10 млн физических файлов и не проверка скорости пользовательского или сетевого диска.

| Измерение | Результат одного прогона |
|---|---|
| Построение каталога и индексов | 63,779 с |
| Размер SQLite-каталога | 2 217 234 432 байта (около 2,065 ГиБ) |
| Пик RSS / private / managed при построении, весь процесс | 144 236 544 / 159 178 752 / 18 235 392 байта; RSS около 137,55 МиБ |
| Точное имя | 23,3 мс |
| Избирательная подстрока | 243,9 мс |
| Короткая подстрока без совпадений, потоковый проход | 3,436 с |
| Слишком широкий поиск, отказ без обрезания | 23,3 мс |
| Отмена длинного запроса | 45,2 мс; следующий запрос успешен |
| Полный headless-прогон | 68,016 с; 2 992 тика UI-таймера, 2 995 принятых вводов |
| Максимальный промежуток UI pump за прогон / heartbeat при построении | 79,0 / 84,6 мс |

Ввод и таймер проверяет настоящий dispatcher Avalonia.Headless. Времена относятся к этому
синтетическому стенду и среде, не являются гарантированными порогами для произвольной папки.
В автоматический CI входит только smoke на 100 000 метаданных; 10 млн запускаются вручную.

## Смена типа

- «Файл» → «Текст»: сохраненное значение остается строкой, в том числе JSON-список нескольких путей.
- «Текст» → «Файл»: строка трактуется как путь (существует — ссылка, нет — «файл не найден»).

## Осознанно не сделано

Копирование файлов в хранилище, ручной выбор нескольких файлов, превью изображений, фильтр по
расширениям, drag & drop — надстройки на будущее.
