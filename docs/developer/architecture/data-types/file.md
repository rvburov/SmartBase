# Свойство: «Файл» (`file`)

Часть [реестра типов свойств](overview.md). Единый источник классификации — [`FieldTypeInfo`](../../../../Core/Models/FieldTypeInfo.cs).


**Ссылки на файлы на диске, без копирования.** Один абсолютный путь в `db_field_values`
остается обычной строкой, как прежде. Несколько найденных файлов хранятся в той же строке
JSON-объектом `{"paths":["/папка/первый.pdf","/папка/второй.pdf"]}`. Столбцы таблицы не меняются.
Для раскрытия списка в библиотеке PostgreSQL используется SQL-функция из парных
миграций `MultipleFilePaths` / `MultipleFilePathsPg`.
Файлы никуда не копируются, папок рядом с БД не создается.

Разбор и запись — [`FileValue.ReadPaths` / `Serialize`](../../../../Core/Models/FileValue.cs):
пустой список записывается как `""`, один путь — как прежняя строка, несколько — как объект
со строковым массивом `paths`. При записи порядок сохраняется, пустые пути и повторы одного пути
отбрасываются с `Ordinal`-сравнением. При чтении повторяющиеся пути сохраняются; SQL библиотеки
также сохраняет исходный индекс каждого непустого пути для адресации документа.
Разбор некорректного или постороннего JSON сохраняет
значение как один прежний путь. Запятая служит разделителем только в показе: имя файла
может содержать запятые, поэтому пути никогда не разбиваются через `Split(',')`.

## Показ (одинаково в таблице и на странице записи)

| Состояние | Что видно |
|---|---|
| Есть файл (путь ведет к существующему файлу) | имя файла с расширением — **синяя подчеркнутая ссылка**; клик открывает файл штатным приложением ОС |
| Найдено несколько файлов | имена через запятую; каждое имя — отдельная ссылка на свой путь |
| Путь задан, но файла нет | `имя.ext — файл не найден` (серым) |
| Пусто | серое некликабельное `Выбрать файл…` |

Путь, созданный в одной ОС (`C:\…`), в другой (`/…`) не резолвится — это не ошибка данных,
просто показывается «файл не найден».

## Правка (по аналогии с типом «дата»)

Редактор — [`FileEditor`](../../../../Controls/Widgets/FileEditor.axaml.cs), общий для таблицы и
страницы записи:

- **Правая иконка-скрепка** (`IconFieldFile`, доступна в ручном режиме) — открывает системный выбор
  файла (`StorageProvider.OpenFilePickerAsync`), путь подставляется в значение.
- **Ручной ввод пути** — двойной клик по значению (или клик по «файл не найден») превращает
  показ в текстовое поле с полным путем; ввод/правка/очистка вручную. Коммит — Enter или уход
  фокуса; Escape отменяет.
- **Проверка при ручном вводе:** непустой путь без существующего файла → текст поля **красный** +
  плашка-уведомление [`NoticeBanner`](../../../../Controls/Widgets/NoticeBanner.axaml.cs)
  («Укажите путь и наименование файла»), которая держится, пока путь не станет верным или поле не
  покинут. После коммита неверный путь сохраняется и показывается как «файл не найден».
- **Имя файла** для показа (ссылка, «файл не найден», список значений фильтра, журнал изменений) —
  общий источник [`FileValue.DisplayName`](../../../../Core/Models/FileValue.cs): из каждого пути берется
  базовое имя, несколько имен соединяются запятой, а значение, доставшееся от прежнего типа поля,
  показывается по прежним правилам. В журнале
  правок (`SetFieldValue` → `ChangeDetail`) «до → после» тоже сворачивается до имени файла, а не
  абсолютного пути.

Открытие файла — `Process.Start(UseShellExecute=true)` (делегирование ОС: `open`/ассоциация/
`xdg-open`). Иконка типа — скрепка `IconFieldFile` (реестр [`Icons.axaml`](../../../../Assets/Styles/Icons.axaml)),
используется в шапке колонки, диалоге свойства и на карточке записи.

## Тумблер «Добавить в библиотеку документов»

В диалоге свойства у типа «Файл» есть тумблер, включающий столбец в раздел
[«Библиотека документов»](../../features/library.md) — ровно так же, как «Отображать в
календаре» включает поле-дату, а «Добавить в раздел задач» — user-поле. Он поднимает флаг
`IsDocFile` на `db_fields` (миграция `AddDocFieldFlags`) и доводит коллекцию до полного набора
ролей раздела: заводит или подтягивает по имени столбец **«Тип документа»** (`select`,
`IsDocType`).

Отличие от задач — **роль не эксклюзивна**: файловых столбцов у коллекции может быть сколько
угодно, и каждый дает разделу свои документы («Оригинал» и «Скан» — это два разных документа
записи). Коллекция уходит из раздела только когда выключен последний столбец.

Выключение ничего не удаляет: снимается один флаг, столбцы и значения остаются. Смена типа
снимает флаг записью (`ClearRolesIncompatibleWithType`), удаление столбца работает обычным
каскадом; оба случая окно предупреждает словами из
[`FieldRoleText`](../../../../Utils/FieldRoleText.cs).

Раздел читает **только непустые** пути: строка без ссылки документом не считается.

## Авто-привязка файлов (по столбцу)

Поле «Файл» можно перевести в **авто-режим**: файлы не выбираются вручную, а подбираются из папки
по совпадению имени. Правило хранится в ConfigJson —
[`FileAutoRule`](../../../../Core/Models/FileAutoRule.cs):
`{ "auto": { "source": "…", "folder": "…", "format": "pdf", "recursive": true, "partialMatch": false } }`. `source` —
строковый ключ колонки (как в сортировке/фильтре): `__title__` — системное «Название» (значение в
db_records), число — Id текст-поля (значения в db_field_values). Старый формат `sourceFieldId`
читается для совместимости.

- **Настройка** — в диалоге свойства (блок «Авто-привязка»): столбец-источник — системное
  **«Название»** (на него можно ссылаться, хотя в db_field_values его нет) и **поля типа
  `text`** (в том числе «Описание» — оно обычное поле); папка (системный выбор); галочка
  **«Искать во вложенных папках»**; формат (21 популярный + свой);
  **«Частичное совпадение имени»** (по умолчанию выключено). Первый пункт списка
  источников — серая заглушка **«Выбрать…»** (обычный ручной режим, без авто).
- **Точное сопоставление (по умолчанию):** для записи имя = `значение_столбца` + «.» + `формат`; ищется в папке,
  **регистр учитывается, имя точное** (`Отчет.pdf`). Нет файла или пустое значение
  источника → «файл не найден». Правило без ключа `partialMatch` остается точным.
- **Частичное совпадение (`PartialMatch`):** `MatchesFileName` проверяет наличие значения
  источника как обычной подстроки в имени без суффикса «.» + `Format`, с `Ordinal`-сравнением.
  Расширение обязательно и тоже сравнивается с учетом регистра; составной формат `tar.gz`
  снимается целиком. Имя папки и само расширение в подстрочном поиске не участвуют,
  шаблоны `*` не интерпретируются. Пустой или состоящий только из пробелов источник
  не дает совпадений. Подбираются **все** подходящие файлы; полные пути упорядочиваются
  через `StringComparer.Ordinal` и передаются в `FileValue.Serialize`.
- **Вложенные папки** (`recursive`): у нового свойства галочка **включена**
  (`FileAutoRule.DefaultRecursive`), скан идет `SearchOption.AllDirectories`. Одно имя в разных
  подпапках — в точном режиме берется **первое найденное**. В частичном режиме сохраняются
  все разные полные пути, в том числе пути к одноименным файлам из разных подпапок.

  > **Ключа нет в конфиге — значит `false`.** Правила, созданные до появления настройки, искали
  > только по верхнему уровню; трактовать их как рекурсивные нельзя — у поля разом и молча
  > поменялись бы значения. Такие поля переводятся на вложенный поиск вручную, галочкой.
- **Материализация:** найденный путь либо список путей **пишется в `db_field_values`**
  ([`ResolveAutoFileField`](../../../../Database/Repositories/ConstructorRepository.cs)) — поэтому
  значение остается доступно штатным механизмам чтения. При включении правила прежние значения
  столбца **затираются** (с подтверждением в диалоге).
- **Применение настроек:** диалог меняет свое состояние до нажатия **«Сохранить»**. После
  сохранения правило записывается и для всей колонки выполняется полный пересчет. Само
  переключение `partialMatch`, формата или рекурсивности до сохранения не меняет значения.
- **Пересчет:** полный проход — с окном прогресса, если долго (иначе без мелькания); правка
  столбца-источника пересчитывает файл записи реактивно и **сразу обновляет файл-ячейку**. Для
  текст-поля — `SetFieldValue`, для системного источника — `SetRecordTitle`/`SetRecordDescription`
  (общий `ReactToSourceEdit`). Все три возвращают побочные изменения (FieldId файл-поля → путь), а
  строка таблицы / панель записи применяют их к своему кешу и файл-редактору, не трогая
  редактируемое поле (каретка не сбивается). Изменения
  файлов в папке — по кнопке **«Обновить привязку»** в меню колонки. Фоновый большой проход —
  `ResolveAutoFileFieldAsync` (изолированное подключение). Значения источника **стримятся** сырым
  reader'ом (без EF-материализации всех строк — важно на миллионах); окно прогресса показывает
  **проценты** (чтение 0–90%, запись 90–100%) и кнопку **«Отмена»** (`CancellationToken`): при
  отмене транзакция откатывается, значения не меняются (статус `Cancelled`). Окно появляется
  только если операция долгая (маленькая коллекция — без мелькания).
- **Показ ячейки (read-only):** имя-ссылка или несколько отдельных ссылок через запятую
  (клик открывает именно выбранный файл) / «файл не найден» / **«папка
  недоступна»** (папки нет или нет прав; клик — плашка «Папка недоступна»). Скрепки и ручного
  ввода в авто-режиме нет.
- **Не сделано на этом этапе:** несколько форматов на столбец, слежение за папкой в
  реальном времени (только кнопка «Обновить привязку»).

## Смена типа

- «Файл» → «Текст»: сохраненное значение остается строкой, в том числе JSON-список нескольких путей.
- «Текст» → «Файл»: строка трактуется как путь (существует — ссылка, нет — «файл не найден»).
