# Свойство: Вычисляемые (`created_*` / `updated_*`)

## Назначение

Часть [реестра типов свойств](overview.md). Значения `created_at`, `updated_at`, `created_by`
и `updated_by` доступны только для чтения: в `db_field_values` их нет, источник — аудит записи
`db_records.CreatedAt/UpdatedAt/CreatedBy/UpdatedBy`. Автор — снимок отображаемого имени в
момент операции; у старых записей он может быть неизвестен.

## Как работает

Создание штампуется при `AddRecord`/`SaveChanges`, правка — через `TouchUpdated` и запись
значения поля, только при реальной смене данных. Читающие запросы получают свежий аудит из
БД, без экземпляров долгоживущего трекера. Оставшаяся от прежнего типа EAV-строка не
перекрывает вычисляемое значение. Поле должно принадлежать запрошенной коллекции; ее права
применяются и к фоновым клонам репозитория.

Фильтры включения и исключения, счетчики, поиск и итоги списка значений используют одну
проекцию. Пустые строки старых записей означают «(Пусто)». Счетчики учитывают фильтры остальных
колонок и скрытые записи, а собственный фильтр колонки не сужает список ее значений.
При множестве разных значений список ограничивается общим `FilterValueCap`; остальные
значения доступны поиском. Имена ищутся в SQL; даты — по локальному показу потоком одной
колонки, с отменой и памятью не больше ограниченного списка совпадений.

Даты показаны как `дд.MM.гггг чч:мм` в локальном времени через
`FieldTypeInfo.FormatComputedDisplay`. Хранение — исходная ISO-строка: обычный `DateValue`
не покрывает ее доли секунды и смещение. Сортировка дат сравнивает моменты UTC с точностью
до тика, а не строки или сокращенный показ. При равных моментах сохраняется порядок
`Position, Id`; пустые и неразбираемые старые даты идут в конце в обоих направлениях.
Для старой даты без смещения используется UTC, как при ее показе. Даты сортируются потоком
одной колонки с накоплением только компактных ключей, без загрузки остальных значений записи.

## Взаимодействия

Экспорт и чтение через API возвращают **исходную ISO-строку и исходное имя**, сохраняя
смещение и точность. CSV/XLSX/JSON получают значения как строки снимка аудита; формат
обычного поля-даты не меняется. Переносимый JSON получает те же значения выбранных полей.
Исходящие сохраненные привязки читают одинаковый аудит для всей коллекции и выделенных
записей, включая поля условий, даже если тип поля изменили после настройки привязки.
Перед началом экспорта проверяется живая принадлежность и тип поля: чужое или удаленное
поле не открывает аудит, а сменившее тип читается по новому источнику. Порядок строк,
скрытие и ключевые курсоры экспорта остаются общими с обычными полями.

Регрессии — `AuditColumnQueryTests` (SQLite и PostgreSQL, все четыре типа, фильтры и
счетчики, ограниченный список, свежие изменения, права, чужие поля, экспорт и API),
`UserValueTests.Author_column_is_filterable_sortable_and_exported` и `ColumnSortTests`.
Локальную подпись и поиск по ней в настоящем фильтре таблицы проверяет `GridProto --ops`
(сценарий «Дата аудита в фильтре»).

Вычисляемая длительность по диапазону даты описана отдельно: [«Дата период времени»](date-period.md).
