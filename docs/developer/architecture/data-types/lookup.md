# Свойство: «Данные из связи» (`lookup`)

Часть [реестра типов](overview.md). Значение вычисляется из существующей [связи](relation.md)
и свойства ее цели; в `db_field_values` не записывается и вручную не редактируется.

В списке типов этого типа нет: столбец — строка блока «Данные из связанных записей» в окне
своей связи (`PropertyEditorDialog.RelationData`, запись — `SaveRelationDataColumns`). Окно
такого столбца открывает окно связи с подсвеченной строкой; удаление связи или смена ее типа
удаляет столбец. Столбец, оставшийся без связи от прежней версии, открывается своим окном с
выбором связи.

Конфиг — `RelationComputedConfig`: `relationFieldId`, `targetField` (`__title__` или строковый
ID свойства), `aggregate: "lookup"`. Выбор локального поля-связи определяет целевые базу и
коллекцию. При копировании и переносе конфиг переписывается через полные карты свойств.

`ConstructorRepository.RelationComputed` читает ребра и значения пакетно. Для одной цели
берется ее значение, для нескольких — значения в порядке ребер. Показ использует формат
целевого свойства: число, дата, список, файл и вычисляемые значения. Для автоматического
сопоставления отдельно доступны исходные типизированные значения — показанное число с
валютой не становится ключом связи.

`FieldTypeInfo.IsRelationComputed` отделяет этот тип от аудита (`IsAuditComputed`). Обычные
и оконные `GetFieldValuesBatch`, страница записи, фильтр и экспорт получают вычисленное
значение; сортировка lookup идет по показанному тексту. Для числового итога по нескольким
целям служит [rollup](rollup.md).

Значение записи не зависит от соседей по странице: отказ (база цели недоступна, коллекция
закрыта, сбой чтения) — у группы целей одной базы, и подпись ошибки получают только записи с
ребрами в эту базу; запись без ребер получает значение пустого набора. Склейка значений и
старшинство ошибок — одна функция `RelationComputedFold`, общая для страницы, карточки и
столбца целиком.

## Столбец целиком: отбор, сортировка, окно фильтра

Отбор, сортировка и окно фильтра читают столбец целиком
([`ConstructorRepository.RelationComputedColumn`](../../../../Database/Repositories/ConstructorRepository.RelationComputedColumn.cs)):
один проход по ребрам свойства-связи от записей коллекции (индекс `(FieldId, FromRecordId,
Position)`, без сортировки — план держит тест), значения различных целей — пакетами по 1000 тем
же читателем, что у страницы, по одному подключению на базу за весь расчет, и та же свертка.
Число обращений к базе зависит от числа различных целей, а не записей. Результат —
`RelationComputedColumn`: значение по умолчанию у записей без ребер и номер различного значения
у остальных. Срез до `SubsetLimit` (20 000) записей считается сам, пакетами страницы.

- **Отбор** (`ComputedFilter`) идет вторым проходом, после остальных фильтров колонок: малый срез
  — списком подошедших, иначе списком меньшей стороны (подошедших или не подошедших записей с
  ребрами), смотря что дает значение по умолчанию.
- **Сортировка** (`RelationComputedSort`) — тем же компаратором, что раньше (текст или итог), но
  ключ разбирается один раз на различное значение; равные для компаратора остаются в порядке
  таблицы, пустые — в конце.
- **Окно фильтра** считает одну колонку, а не все вычисляемые колонки среза, и хранит
  результат на время окна (`ColumnValueSnapshot`): поиск и итоги того же окна идут по нему.
  Поиск — по показанному тексту (итог «11,75», а не «11.75»), первые 1 000 значений — порядком
  колонки; у ограниченного списка «(Пусто)» досчитывают итоги, в списке его нет. Закрытое окно
  отменяет расчет.
- **Ход.** Фоновый расчет (`RelationColumnRun`) дольше секунды виден строкой в значке фоновых
  работ: «Данные из связанных записей», под ней «Столбец «Итого»: база «Архив», 12 000 из
  48 000», «Столбец «Итого»: связанные записи, 12 000 из 48 000» или «прочитано 340 000
  записей». Остановки нет: новый отбор или сортировка и закрытие
  окна фильтра отменяют расчет сами. Путей и строк подключения в строке нет.
- **Пути других баз** для фона снимаются без SQL: все подключенные базы и настроенная цель
  связи. Ребро в неподключенную базу, кроме настроенной цели, показывает «(база недоступна)» и не
  подключает базу синхронно на UI-потоке.

Целевая коллекция проверяется на `ViewCollection`. Фон открывает собственные контексты и
использует снятые разрешенные пути, а не общий контекст окна. Вложенные зависимости имеют
ограничение глубины и защиту от циклов; сохранение некорректной настройки блокируется.
Отсутствие доступа и недоступность базы показываются явно и не удаляют исходные ребра.
