# Свойство: «Пользователь» (`user`)

Часть [реестра типов свойств](overview.md). Единый источник классификации — [`FieldTypeInfo`](../../../../Core/Models/FieldTypeInfo.cs).


Хранит строку-**имя** — снимок отображаемого имени (как `select`, значением, а не ссылкой на учетку).
Опции — `ConstructorRepository.GetUserOptions(includeValue)` (допущенные пользователи базы; текущее
значение остается в списке, даже если пользователь ушел из базы). Читаются **при каждом построении
редактора** — состав пользователей меняют соседи, а уже открытые списки оживляет `PermissionService.Changed`
(см. [users-permissions](../users-permissions.md)). При ручном создании записи из таблицы,
календаря или задач (со сроком и без) все ее user-поля по умолчанию получают **текущего
пользователя**. Явно выбранные в диалоге значения, в том числе роли задачи, заменяют эти
начальные значения. Перенос существующей записи начальные значения не проставляет: исторические
имена и пустые ячейки сохраняются, а user-поля только целевой коллекции остаются пустыми.
Редактор — `ComboBox`. Участвует в разделе «Задачи» через флаги поля
(см. [tasks/overview.md](../../features/tasks.md)):

- `IsTaskExec` — исполнитель; включает **всю коллекцию** в раздел задач: задачей становится каждая
  ее запись, а пустое значение показывается прочерком. Исполнитель у коллекции **один** — пока
  тумблер стоит на одном user-поле, включить второе нельзя;
- `IsTaskAssigner` — роль «Назначил» (тоже user-поле);
- `IsTaskStatus` — роль «Статус» (поле типа `status`; `select` тоже годится). «Назначил»/«Статус»
  авто-создаются при включении задач.

Роль держится не только флагом, но и типом (`RoleAllowsType`): перевод поля-исполнителя или
«Назначил» в не-`user` снимает привязку, о чем окно свойства предупреждает до сохранения.
