# Свойство: «Дата период времени» (`date_period`)

## Назначение

Часть [реестра типов свойств](overview.md). Вычисляет длительность диапазона **одного**
обычного свойства `date` с учетом выбранных дней недели и часов дня. Значение только для
чтения; автоматический режим вычисляет его из исходной даты, фиксированный сохраняет снимок.
Пользовательская инструкция с примерами — [date-period](../../../user/date-period.md).

## Как работает

### Источник и границы

Редактор показывает один список **«Даты для расчета»**: обычные поля `date` этой коллекции.
Без них тип недоступен. Поля аудита `created_at`/`updated_at` источниками не служат.
Начало и конец берутся из `DateValue.Start`/`End` одного значения; второй источник
и зависимость от текущего времени отсутствуют.

Расчет использует полуоткрытый интервал **[Start, End)**. У `AllDay` обе границы
приводятся к `.Date`, даже если канонический `DateValue.End` содержит конец дня.
Поэтому `01.09.2026–04.09.2026` — три суток, а не четыре. Единственная дата без диапазона
или один момент времени дают `0`. Отсутствующий, пустой, неразбираемый источник и обратный
диапазон дают пустую строку, а не ноль.

Даты считаются в записанном локальном календарном времени без перевода в часовой пояс
сервера. Число часов отражает календарные часы, а не UTC-длительность с поправками
на перевод часов. От часов компьютера результат не зависит.

### Дни и часы

`Weekdays` — маска 1–127: бит 0 — понедельник, бит 6 — воскресенье. Нулевая маска
недопустима. Календаря праздников и переносов рабочих дней нет.

`DayStart`/`DayEnd` задаются как `HH:mm`, конец строго позже начала. `24:00` допустимо
только в конце; `00:00–24:00` означает полные сутки. Ночное окно `22:00–06:00`
не поддерживается. Сам исходный диапазон при этом может пересекать полночь: при полном
дне `01.09 23:00–02.09 02:00` дает три часа.

Для каждого выбранного дня учитывается пересечение исходного диапазона с его окном часов.
Отсутствие пересечения дает `0`. `DatePeriodValue.Prepare` разбирает правило один раз
на поле; целые недели считаются арифметически, отдельно обрабатываются граничные дни
и остаток недели. Нет обхода каждого дня многолетнего диапазона.

### Результат и режимы

Сырой результат — неотрицательное целое число секунд в invariant-формате. Показ — дни,
часы, минуты; один день равен **86400 секундам**, то есть 24 накопленным часам, а не
одной рабочей смене. Ноль показывается как **«0 мин»**. Например, три дня по девять часов
дают 97200 секунд и **«1 д 3 ч»**. Секунды участвуют в числовой сортировке, показ минут
не округляет их вверх.

При `Automatic=true` отдельного результата в `db_field_values` нет; его получают при
чтении. Изменение даты или правила инвалидирует значения открытых представлений. Минутных
таймеров, снимков «сейчас» и запросов из-за смены минуты нет.

При `Automatic=false` результат записывается в `db_field_values` при создании записи
и после явной команды **«Пересчитать»**. Поздние изменения исходной даты или настройки
сами снимок не обновляют. Пустая дата при создании оставляет пустой снимок; после заполнения
нужна команда пересчета. Добавление свойства к существующим записям тоже требует явного
пересчета. Старые фиксированные значения сохраняются до него.

### Настройка и совместимость

Правило хранится в `ConfigJson.datePeriod`:

```json
{
  "datePeriod": {
    "version": 2,
    "dateFieldId": 42,
    "automatic": true,
    "weekdays": 127,
    "dayStart": "09:00",
    "dayEnd": "18:00"
  }
}
```

`DateFieldId` должен указывать на обычное поле `date` той же коллекции. Запись
через `ToConfigJson` сохраняет прочие корневые ключи конфигурации и заменяет блок
`datePeriod` версией 2.

Читатель версии 1, включая настройку без `version`, переносит прежний `startFieldId`
в `DateFieldId`. Прежний `endFieldId` и режим до текущего времени игнорируются: диапазон
берется только из выбранного прежде начального поля. Неизвестная версия или неверная
структура не превращаются в другое правило. При сохранении настройки пишется версия 2;
массовой перезаписи старых фиксированных снимков нет.

### Производительность

Обычное чтение таблицы ограничено запрошенными страницами и колонками. Уже загруженные
исходные даты используются повторно, недостающие зависимости дочитываются пакетом.
Скрытая вычисляемая колонка сама не вызывает расчет миллионов строк. Фиксированный
режим читает сохраненные секунды без исходной даты.

Глобальный фильтр и сортировка обрабатывают весь соответствующий срез. Потоковое чтение,
группировка одинаковых источников и ограниченный кеш уменьшают число запросов и память,
но не делают такие операции независимыми от количества строк. Для коллекции в десять
миллионов записей нельзя переносить стоимость глобального отбора на обычный показ страницы
или обещать мгновенную сортировку. Общие принципы — [performance/overview](../performance/overview.md).

## Взаимодействия

Таблица и страница записи показывают результат без редактора; фиксированный режим дает
команду **«Пересчитать»** для записи или выделения. Фильтр использует рассчитанные значения,
сортировка — числовую длительность; экспорт и API читают то же правило.

Автоматический период допустим как ключ источника или цели автоподбора связи, в том
числе через `lookup`/`rollup`. Обновление учитывает зависимость от `DateFieldId`: если
исходная дата удалена или сменила тип, правило сообщает явную ошибку и сохраняет прежние
связи. Исторические снимки фиксированного периода допустимы и без существующего источника.

При дублировании коллекции или переносе между базами `dateFieldId` переназначается на
скопированное поле. Источник должен остаться датой той же коллекции; произвольное совпадение
числового ID не заменяет перенос зависимости. Сохраненные фиксированные снимки переносятся
без неявного пересчета. Изменение типа или удаление источника не дает подставить текущее время.

Покрытие: `DatePeriodValueTests` — границы, часы и дни; `DatePeriodPropertyTests` — режимы
и запись; `DatePeriodMoveTests` — зависимости между базами; `DatePeriodScalingTests` —
окно чтения и глобальные запросы; `Tests/RecordPage --only dateperiod` — живой редактор,
показ, смена правила и ручная команда. Наличие тестов не заменяет отчет о фактическом прогоне.
