# Свойство: «Связь» (`relation`)

Часть [реестра типов свойств](overview.md). Связь хранит ссылки на записи своей или другой
коллекции, в том числе в другой базе. Для показа и поиска можно выбрать любое свойство цели;
по умолчанию используется «Название». Изменение подписи не меняет выбранную запись.

Ручной выбор и автоматическое сопоставление используют одну модель ребер. Отдельные
вычисляемые типы [lookup](lookup.md) и [rollup](rollup.md) читают значения по уже существующим
связям; собственные ребра эти типы не создают.

## Хранение и идентичность

Связи лежат в `db_record_links`
([`DbRecordLinkEntity`](../../../../Database/Entities/CoreEntities.cs)), а не в `db_field_values`.

| Колонка | Смысл |
|---|---|
| `Id` | Первичный ключ ребра |
| `FieldId` | Свойство-связь |
| `FromRecordId` | Запись-источник |
| `ToRecordId` | Идентификатор записи в целевой базе |
| `TargetDbId` | `0` — база источника; положительный — идентификатор базы в реестре |
| `Position` | Порядок целей в ячейке |

Цель определяется парой `RelationTarget(DbId, RecordId)`. Одинаковые численные `RecordId`
разных баз обозначают разные записи. Контрол выбора, запись ребер, буфер обмена и отмена
сохраняют полную пару; подпись, разделитель и значение выбранного свойства идентичностью
не являются. Для межбазового переноса относительный `DbId=0` пересчитывается относительно
базы назначения.

Уникальный индекс `(FieldId, FromRecordId, TargetDbId, ToRecordId)` запрещает дубли. Индекс
`(FieldId, FromRecordId, Position)` обслуживает показ в порядке ребер, индекс `ToRecordId` —
поиск входящих. Каскады на свойство и запись-источник удаляют исходящие ребра. Внешнего ключа
на цель нет: межбазовую ссылку нельзя проверить одним FK. Локальные входящие очищает код
удаления записи, коллекции или группы.

Значения целей не дублируются в ребрах. Читатель разрешает каждое ребро по его собственному
`TargetDbId`, включая смешанные исторические наборы. Переименование или правка свойства цели
меняет показ, сохраняя идентичность связи.

У исторического смешанного набора численный selector свойства имеет смысл только в базе,
для которой он настроен. Ребро из другой базы получает «(свойство недоступно)»: совпавший
численный ID чужого свойства не используется. Существование цели и права по-прежнему
проверяются; недоступность базы и запрет доступа сохраняют свои отдельные признаки.
`__title__` безопасно разрешается для каждой базы. Локальный `0` и абсолютный ID своей базы
считаются одной базой. Хранить отдельный selector для каждой исторической цели модель пока
не умеет; полная идентичность самого ребра при этом сохраняется.

## Настройка свойства

[`RelationConfig`](../../../../Core/Models/RelationConfig.cs) хранится в `ConfigJson`:

```json
{
  "targetCollectionId": 42,
  "targetDbId": 7,
  "single": false,
  "separator": "comma",
  "displayField": "123",
  "searchField": "124",
  "auto": { "sourceField": "15", "targetField": "125" }
}
```

`targetDbId` можно опустить для своей базы. `single=true` означает не более одной цели,
`false` — несколько. Новое свойство в диалоге по умолчанию допускает одну цель; старый JSON
без `single` по-прежнему читается как несколько.

Ключ свойства — `__title__` для названия либо строковый ID обычного или вычисляемого
свойства. `displayField` по умолчанию равен `__title__`; отсутствующий `searchField`
использует `displayField`. Показ и поиск могут обращаться к разным свойствам. Отсутствие
`auto` означает ручной режим. `RelationAutoRule` содержит только ключи исходного и целевого
свойств, без побочных эффектов при создании или разборе настройки.

Нечитаемый JSON и неверный тип идентификатора цели дают ненастроенное свойство, а не
исключение из `JsonElement`. Старые настройки сохраняют прежний показ по названию.
Селекторы свойств при копировании и переносе переписываются по картам ID, а не угадываются
по совпавшему численному идентификатору в новой базе.

Разделитель влияет только на показ нескольких значений:

| Ключ | Разделитель |
|---|---|
| `comma` | `, ` — по умолчанию |
| `dot` | `. ` |
| `space` | пробел |
| `semicolon` | `; ` |
| `newline` | перевод строки |
| `comma_tight` | `,` |
| `dot_tight` | `.` |

Общий источник — `MultiSelectValue.SeparatorFor`. Порядок пунктов диалога и ключей должен
совпадать. Разделитель не используется как структурный формат набора ссылок.

## Общий читатель и поиск

Основной код —
[`ConstructorRepository.RelationProperties`](../../../../Database/Repositories/ConstructorRepository.RelationProperties.cs)
и [`RelationProperty`](../../../../Core/Models/RelationProperty.cs).

- `GetRelationPropertyOptions` возвращает доступные свойства целевой коллекции.
- `ReadRelationPropertyValues` возвращает `RecordId`, исходный `Title`, `Raw`, `Display`,
  `FieldType` и `ConfigJson`. Сырое значение служит типизированному сопоставлению, текст — показу.
- `GetRecordPropertyValues` разрешает набор целей из их собственных коллекций.
- `GetRelationLinks` / `GetRelationLinksBatch` возвращают полные пары целей и выбранный показ.
- `SearchRelationRecords` и асинхронный вариант ищут по выбранному свойству. Title и текстовые
  свойства используют SQL; форматированные значения читаются ограниченными страницами.
- `GetLinkEdges` возвращает хранимые пары без разрешения подписей. `SetLinkEdges` записывает
  полный набор с порядком, проверкой источника и целей, удалением дублей и прямой ссылки на себя.

Старые `GetLinks` / `GetLinksBatch` оставлены как локальные обертки: только `TargetDbId=0`,
но подпись уже учитывает `displayField`. `GetRecordTitles` и `SearchRecordTitles` сохраняют
сигнатуры для старых клиентов. Старый `SetLinks` адаптирует численные ID к базе текущего
конфига; новый код с межбазовыми или смешанными ребрами использует `SetLinkEdges`.

Число показывается с форматом поля, дата — в пользовательском формате, мультисписок — через
его разделитель, файл — именами файлов, пользователь — сохраненным именем. Аудит берется из
метаданных записи; lookup и rollup передают исходное типизированное значение отдельно от
показа. Для relation исходное значение содержит полные пары целей. Вложенное разрешение
использует общий `RelationPropertyResolution`: посещенные свойства и ограничение глубины
защищают от рекурсии.

Таблица, страница записи, копирование, экспорт и `RelationTitlesBySource` используют общий
показ. Последний обслуживает сортировку, фильтр и счетчики столбца-связи. Фильтр по нескольким
подписям использует «или»; счетчик подписи считает записи-источники, имеющие такую цель.
Это отличается от `rollup:count`, который считает цели одной записи.

## Интерфейс

Диалог свойства задает целевые базу и коллекцию, одну или несколько целей, свойства для
показа и поиска, разделитель и ручной либо автоматический режим. Собственная коллекция
допустима; непосредственная ссылка записи на себя исключается.

[`RelationSelectBox`](../../../../Controls/Widgets/RelationSelectBox.cs) показывает подписи
через разделитель; пустой набор обозначается «связи нет». Иконка связи открывает список
с поиском и галочками. В режиме одной цели выбор заменяет прежнюю, снятие галочки очищает
связь. Если показывается другое свойство, подпись дополняется названием записи, чтобы
различать одинаковые статусы, даты и пустые значения. Карандаш открывает целевую запись.

В поиске есть задержка объединения ввода 150 мс, отмена и проверка поколения запроса.
Закрытие списка и снятие контрола отменяют незавершенный поиск; устаревший результат не
перекрывает новый. Кандидатов не более 200; при превышении показана просьба уточнить поиск.
Форматированные значения просматриваются страницами по 256 записей, с проверкой отмены
между страницами. Чтение идет на отдельных подключениях в фоне; UI применяет готовый результат.

Без `EditRecord` и в автоматическом режиме выбор недоступен, но разрешенный переход к цели
сохраняется. Проверка прав выполняется до изменения выбранного набора; отказ записи не
оставляет ложное состояние галочек. Read-only показ без редактора содержит только текст.

## Автоматическое сопоставление

[`ConstructorRepository.RelationAuto`](../../../../Database/Repositories/ConstructorRepository.RelationAuto.cs)
подбирает цели по равенству исходного свойства записи и выбранного свойства целевой коллекции.
Предварительный просмотр не меняет настройку и ребра. Диалог показывает изменения и причины,
которые мешают применению; настройка и полный результат сохраняются после «Сохранить».

Сравнение задает [`RelationAutoMatch`](../../../../Core/Models/RelationAutoMatch.cs):

- Текст, URL, список, статус и текстовый аудит сравниваются точно, с учетом регистра.
- Числа сравниваются по числовому значению независимо от формата показа; даты — по
  каноническим границам и признаку целого дня; чекбокс различает истинное и ложное значения.
- Мультисписки и наборы файлов сравниваются как полные наборы без дублей и зависимости от
  порядка. У файла ключом служит путь, а не только показанное имя.
- Пользователь сравнивается по историческому имени из ячейки: действующая модель не хранит
  ссылку на учетную запись, поэтому одинаковые имена не доказывают одинаковую личность.
- Связи сравниваются по полным целям с абсолютной базой. Вычисляемые свойства передают
  типизированные ключи; формат валюты или даты не становится ключом сопоставления.

Пустое значение не совпадает со всеми пустыми записями. Для нескольких целей сохраняются
все совпадения в определенном порядке; для одной несколько совпадений дают неоднозначность,
блокирующую применение всего результата. Несовместимый тип, цикл зависимости, поврежденное
значение, потеря доступа или недоступная база также сохраняют прежние ребра.

Перед применением повторно проверяются настройка, значения и прежние ребра по отпечатку
предварительного просмотра. Конфликт требует нового просмотра; отмена и ошибка не оставляют
часть нового результата. Настройка и ребра записываются в одной транзакции.

`NotifyRelationDataChanged` сообщает об изменениях после сохранения; внутри внешней
транзакции уведомление откладывается до ее коммита и отбрасывается при откате. В окне события
объединяются и пересчет идет в фоне на отдельных подключениях. Без окна API выполняет
соответствующую работу после успешной записи. Чужие изменения и зависимые вычисления
попадают в тот же механизм. Недоступность цели откладывает пересчет, сохраняя прежние связи.

## Права, межбазовые связи и недоступность

Показ, поиск кандидатов, выбор свойства, вычисления и переход требуют `ViewCollection`
у соответствующей цели. Запрещенная коллекция не отдает заголовок или значение свойства;
существующее ребро показывается как «(нет доступа)». Ручная правка дополнительно требует
`EditRecord` источника. Сохранение настройки автосвязи требует права создания/изменения
свойства и правки записей. Проверки репозитория повторяют UI-проверки на случай изменения прав.

[`RelationDbResolver`](../../../../Database/RelationDbResolver.cs) разрешает базы по реестру.
`RepoFor` может открыть зарегистрированную базу; `MountedRepoFor` и `MountedReposExcept`
читают только уже открытые. Фон захватывает адреса и снимки прав заранее, создает собственные
контексты и устанавливает `UseScopedResolver`; вложенные связи не используют общий контекст окна.
`RelationLinksCache` хранит полные пары и подписи видимой страницы, включая пустые наборы.

Навигация передает базу вместе с записью. Панель сохраняет собственный `DbId`, поэтому
локальная ссылка из открытой чужой записи остается в ее базе. Несуществующая цель не
подменяется записью с тем же численным ID активной базы.

Доступная база без записи-цели означает обрыв: цель пропускается в показе. Недоступная база
дает «(база недоступна)», но ребро сохраняется. Локальное удаление чистит входящие явно;
межбазового каскада нет. Предупреждение `RelationDeleteImpact` проверяет входящие из своей и
уже открытых баз. Оно не перечисляет все закрытые базы и не заменяет проверку целостности
всего реестра.

## Копирование связей при дублировании / переносе записи

Дубль отдельной записи сохраняет ее исходящие ссылки на прежние цели; входящие остаются
у оригинала. Календарь и задачи используют те же данные, а при пересоздании записи в другой
коллекции вызывают `CopyRelationLinksByName` вместе с копированием обычных значений.

Дублирование свойства копирует его ребра. Для копирования коллекции или всей группы
[`RelationLifecycle`](../../../../Database/Repositories/ConstructorRepository.RelationLifecycle.cs)
сначала строит карты коллекций, свойств и записей, затем переносит ребра. Внутренние цели
направляются в копию, внешние остаются прежними. Общая карта всей ветки позволяет сохранить
ссылку в коллекцию, которая копируется позже источника. Переписываются также display/search,
исходное и целевое свойства автосвязи и зависимости lookup/rollup.

Те же правила действуют при переносе одной коллекции или группы между базами: SQLite ATTACH
использует SQL по временным картам, общий путь SQLite/PostgreSQL читает ограниченные страницы
и завершает граф после построения полной карты. Цели внутри переносимого набора получают
новые ID и локальную базу; внешние сохраняют абсолютную базу, пересчитанную относительно
назначения. Неизвестная база внешней цели вызывает отказ вместо подстановки локального ID.

При переносе записей между коллекциями свойства сопоставляются по имени и совместимой
целевой коллекции/базе. Несколько ребер нельзя молча перенести в свойство с одной целью:
операция требует устранить противоречие. Входящие извне ссылки на удаляемый оригинал не
следуют за новым ID; предупреждение проверяется до переноса. При переносе целой ветки
внутренние входящие сохраняются, предупреждение относится к связям снаружи ветки.

Снимки коллекций/групп тоже включают конфиги, исходные ID и полные ребра. Импорт проверяет
внешние базы и разрешения до записи, затем восстанавливает граф по полным картам.

## Смена типа, буфер обмена и экспорт

[`RelationConversion`](../../../../Database/Repositories/ConstructorRepository.RelationConversion.cs)
проверяет смену типа внутри транзакции `UpdateField`:

- `text`/`markdown` → `relation` требует настроенной цели и однозначного сопоставления всех
  непустых значений. Ошибка не оставляет часть созданных ребер.
- `relation` → `text`/`markdown` материализует выбранные подписи через разделитель и удаляет
  ребра. Недоступное значение не превращается молча в пустой текст.
- Смена цели заполненной связи и переход «несколько → одна» с лишними ребрами блокируются
  до явной очистки или исправления данных. Возврат типа не воскрешает старые скрытые ребра.

Таблица копирует читабельный текст и отдельный структурный `RelationClipboard` с координатами
ячеек, полными целями и проверяемыми идентичностями баз. Структурная вставка сохраняет
пунктуацию, пустые значения и одинаковые подписи разных записей. Для обычного внешнего текста
используется сопоставление подписей; неоднозначность отклоняется. `SetLinksBulk` и история
отмены сохраняют полные пары, ожидаемые прежние ребра и настройку свойства; конфликт схемы
или чужая правка не затираются. Лимит истории учитывает и ребра.

CSV/XLSX и обычная текстовая проекция экспорта используют актуальный показ связей, включая
межбазовые цели. Импорт обычной таблицы без схемы не восстанавливает идентичность по подписи.

Для JSON с relation/lookup/rollup экспорт таблицы использует переносимый формат
[`RelationPortableSchema`](../../../../Core/Models/RelationPortable.cs): версия, схема типов и
конфигов, ID записей, исходные значения и упорядоченные полные ребра. Вычисленные подписи не
подменяют исходные данные. Экспорт требует включить используемые свойства этой коллекции;
импорт проверяет внешние базы, доступность целей и ограничение одной связи до завершения
транзакции, а внутренние ID переписывает по карте. Идентичность базы проверяется непрозрачным
отпечатком; один реестровый номер другой установки сам по себе недостаточен. Не удалось
подтвердить внешнюю базу — импорт отклоняется, а не связывает запись по случайному ID.

## Проверки и дальнейшее развитие

Модель и форматирование проверяют `RelationPropertyConfigTests`, `RelationConfigTests`,
`RelationPropertyTests`; автоматический режим — `RelationAutoMatchTests`, `RelationAutoTests`
и `RelationReactiveTests`; жизненный цикл — `RelationCopyLifecycleTests` и
`RelationCrossMoveLifecycleTests`; преобразование и IO — `RelationIoSafetyTests` и
`RelationPortableJsonTests`. Вычисления покрывают `RelationComputedConfigTests` и
`RelationComputedTests`. UI-стенд `Tests/RecordPage --only relations` проверяет выбор,
навигацию, readonly и смену запроса; `--only relationcomputed` — вычисляемые карточки.

Это перечень покрытия, а не утверждение о запуске проверок в конкретной среде.

Пока не реализованы:

- Свойства самого ребра: количество, роль, период и другие значения пары записей.
- Иерархические ограничения, разузлование и транзитивный обход. Защита вычисления от рекурсии
  не запрещает циклы в произвольном графе данных.
- Пользовательский список обратных ссылок и переходов к записям-источникам; существующие
  проверки входящих обслуживают предупреждения удаления/переноса.
- Произвольные формулы по связанным значениям сверх lookup и заданных агрегатов rollup.
- Глобальная проверка и очистка осиротевших ребер всех баз реестра, включая закрытые.
- Несколько целевых коллекций в одном правиле, дополнительные условия выбора кандидатов,
  редактируемая вложенная таблица целей и перестановка отдельных видимых элементов.
