# Свойство: «Число» (`number`)

Часть [реестра типов свойств](overview.md). Единый источник классификации — [`FieldTypeInfo`](../../../../Core/Models/FieldTypeInfo.cs).


В `db_field_values` лежит **сырой ввод** как строка: что ввели, то и сохранили (`42,5` или `42.5`),
в БД значение **не нормализуется**. Запятая приводится к точке только при типизации на чтении —
`WriterHelpers.TryNumber`. Редактор — `TextBox` с фильтром ввода.

**Формат** (`NumberFormat` / [`NumberFormatValue`](../../../../Core/Models/NumberFormatValue.cs)) хранится
в `ConfigJson` поля (ключи `numberFormat`/`decimals`/`thousands`/`currency`/`symbolSuffix`/
`decimalSeparator`, не пересекаются с опциями списка) и задается в диалоге свойства (блок «Формат
числа»). Делится на **две части с разной семантикой**:

- **Показ** (вид/точность/разряды/валюта) — только рисование, значение НЕ трогается, смена
  **обратима**: `Обычное число` (по умолчанию), `Число с разрядами`, `Деньги` (символ спереди/сзади),
  `Проценты` (без домножения: величина показа = хранимой); плюс знаков после запятой (`Авто`/0–4)
  и группировка разрядов (неразрывный пробел). Применяется в **таблице** (`FieldDisplayConverter`),
  на **странице записи** (форматированное вне фокуса, сырое при правке) и в значениях **фильтра**.
  Нечисловое значение (после смены типа из текста/даты) показывается как есть.
- **Десятичный разделитель** (`decimalSeparator`: запятая/точка) — влияет и на показ, и на
  **хранение**: значение приводится к выбранному символу (цифры сохраняются, меняется только
  разделитель) — на записи (`SetFieldValue` → `NormalizeNumberValueForField`) и при смене настройки
  разделителя, когда уже сохраненные значения мигрируют одним bulk-SQL
  (`UpdateField` → `NormalizeNumberSeparatorValues`, как конверсия при смене типа). Нечисловые
  значения не трогаются. Это осознанное отступление от «хранение всегда сырое» — только для символа
  разделителя, ради предсказуемого экспорта/сортировки в едином виде.

**Сортировка/фильтр-сравнение и экспорт** работают с хранимой строкой (число канонизировано по
разделителю поля): CSV сохраняет ее как есть, XLSX/JSON — числовую ячейку/значение через
`WriterHelpers.TryNumber` (Этап 4 типизации остается отдельно).

## Ремонт значений, записанных показом

До 15.09.2026 панель записи при каждом открытии писала в поле с форматом показа (разряды, деньги,
проценты) отформатированную строку — «1 234 567,50 ₽» вместо `1234567,5`: отложенный
`TextChanged` поля принимался за правку (см. [ui/widgets.md](../../ui/widgets.md), «Ловушка:
TextBox.TextChanged отложенный»). На экране такое значение неотличимо от числа, но для
сортировки, фильтра, экспорта и расширений это текст, а в панели его не поправить — фильтр ввода
числа не пропускает буквы. «Обычное число» показывается как есть и не пострадало.

Монтирование чинит файл один раз (`DatabaseManager.RepairFormattedNumbers`, флаг
`repair.number-display` в `db_meta`, в фоне на свежем подключении — как ремонт NULL в
«Названии»): у полей «Число» с форматом показа кандидаты отбираются `GLOB '*[^0-9.,-]*'` по
индексу `(FieldId, Value)`, из них чинятся те, что не число, но разбираются
`NumberFormatValue.TryParseDisplay` по формату поля — они получают канон хранения
(`1234567,50`). Текст, который числом не был (после смены типа из текстового), не трогается. В
«Диагностику» уходит строка с числом исправленных. PostgreSQL ремонт не покрывает — как и ремонт
названий. Тест — `NumberRepairTests` (Tests/Integration).
