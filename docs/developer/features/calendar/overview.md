# Календарь — общий обзор

## Назначение

Модуль календаря показывает события (`CalendarRecord`) в семи режимах:
**Расписание**, **Журнал**, **День**, **Неделя**, **Месяц**, **Год**, **Диаграмма**.
Режимы переключаются на лету, навигация (← Сегодня →) работает в контексте текущего режима.

## Где в коде

- Оркестратор (то, что реально работает в окне): [CalendarControllerView.axaml.cs](../../../../Views/ConstructorDb/Calendar/CalendarControllerView.axaml.cs)
- Вью-контролы режимов: [Views/ConstructorDb/Calendar/](../../../../Views/ConstructorDb/Calendar/) — `ListView`, `JournalView`, `DayView`, `WeekView`, `MonthView`, `YearView`, `DiagramView` (логика — в code-behind этих контролов)
- Модель события: [CalendarRecord.cs](../../../../Core/Models/CalendarRecord.cs)

## Как работает

В главном окне ([MainWindow.axaml](../../../../Views/MainWindow.axaml)) стоит
`CalendarControllerView`. Это **code-behind-оркестратор**, а не MVVM: он сам
держит состояние и кормит вью-контролы готовыми данными. Параллельно существует
MVVM-слой (`CalendarControllerViewModel` и `*ViewModel`) с такой же логикой
дат/навигации — он содержит ту же бизнес-логику диапазонов, но рендеринг идет
через вью-контролы.

### Состояние контроллера

- `_currentViewIndex` — текущий режим (0-Расписание, 1-Журнал, 2-День, 3-Неделя, 4-Месяц, 5-Год, 6-Диаграмма; по умолчанию **4 — Месяц**).
- `_currentDate` — опорная дата.
- `_dbs` — список **всех смонтированных БД** (мультибаза): события агрегируются из всех, CRUD маршрутизируется по `DbId`.
- `_activeByDb` — активные коллекции по каждой БД (фильтр сайдбара). Галочки переживают
  перезапуск: снятые лежат в app.db под ключом `hiddenCollections.calendar` (у задач свой
  набор, механика — [[../tasks]], раздел «Галочки между запусками»).
- `_searchQuery` — строка поиска.

### Цикл обновления `RefreshCurrent()`

1. `GetDateRange()` считает диапазон дат под текущий режим (день / неделя / 6 недель для месяца / год / календарный месяц для диаграммы).
2. События собираются **из всех смонтированных БД**, каждое помечается своим `DbId`, и фильтруются по активным коллекциям этой БД.
3. Применяется фильтр поиска (`Title.Contains`, без учета регистра).
4. `UpdateTitle()` обновляет заголовок в навбаре (для прошедших дат — серый, для сегодня — красный).
5. Данные передаются в видимый вью-контрол через его `Refresh(records, …)`.

Для сетки (День/Неделя/Месяц/Год) шаги 2–3 и 5 идут **в фоне** (`LoadGridAsync`, изолированные
подключения) с ограничением `GridDayCap` (2000) timed-событий на день (и all-day на коллекцию):
день-гигант с миллионами записей отдает сетке только первые 2000 (ячейкам больше не отрисовать),
панель «весь день» дополнительно рисует не больше 300 блоков (+«+N еще»). Загрузка — **двумя
фазами**: события окна (индексные сики, миллисекунды) показываются сразу — оверлей «Загрузка…»
(появляется при >400 мс) в норме не успевает возникнуть; затем для Месяца/Года фоном доезжает
**карта счетчиков дней** (`LoadCalendarDayCountsAsync`; GROUP BY окна с днем-гигантом — секунды)
и ТИХО уточняет «+N еще»/числа на днях повторным применением. Поколение `_gridGen` отменяет
устаревшие загрузки (переключение вида/даты до прихода данных). При активном поиске карта не
применяется — «+N еще» считается от фактически показанного.

**Точечная правка сетки — НА МЕСТЕ, без чтения окна** (`TryApplyGridDelta`): создание/изменение/
удаление/дублирование, перенос/растяжение времени в Дне/Неделе и по дням в Диаграмме (дельта
`[(r,−1),(r,+1)]`, ключ записи не меняется) и перенос между днями в Месяце (drag отдает исходные
даты — дельта `[(старое,−1),(новое,+1)]`) мутируют **снимок последней загрузки** (`_gridRecords`/`_gridTotals`)
и синхронно перерисовывают вид — без БД, без оверлея и без фоновой волны, как в Расписании/
Журнале. Карта счетчиков правится по дню начала записи. Снимок не годится и идет полная
загрузка: навигация/смена вида (другое окно), загрузка еще в полете, активный поиск.

### Переключение режимов `SwitchView(idx)`

Все семь контролов всегда в дереве; переключение — это смена `IsVisible` у нужного
и `RefreshCurrent()`. Навигация (`NavigatePrev`/`NavigateNext`) сдвигает `_currentDate`
с шагом под режим (день / 7 дней / месяц / год). Для Журнала навигация особая —
прокрутка к соседней группе внутри самого контрола.

### Создание / редактирование / удаление

Контроллер ловит события вью-контролов и открывает диалоги:

- создание → `OpenAddDialog` / `OpenAddAllDayDialog` ([RecordDialog](../../../../Controls/Dialogs/RecordDialog.axaml.cs));
  создание записи отсюда заводит в коллекции поле-дату («Дата», если своей нет) и поле
  **«Описание»** — календарь и задачи единственные, кто его создает
  ([[../../architecture/data-types/description]]). То же делает тумблер «Отображать в
  календаре» в диалоге свойства: включенная дата тянет за собой роль «Описание», а про
  одноименный столбец коллекции UI спрашивает подтверждение — механизм общий с задачами
  ([[../tasks]] → «Полный набор ролей и подтягивание по имени»; подтягивается только столбец
  подходящего типа, а смена типа привязку снимает — с предупреждением). Столбцы появляются не молча:
  `ConfirmCalendarSetup` (→ `PlanCalendarSetup`) показывает [окно подготовки](../../ui/dialogs.md#подготовка-коллекции-к-разделу),
  если коллекция изменится, и отказ отменяет создание записи;
- редактирование → `OpenEditDialog`; правка тоже проходит через окно подготовки: перенос готовит
  целевую коллекцию, а правка на месте вернула бы удаленное «Описание»;
- удаление нескольких → `DeleteRecordsWithConfirm` ([ConfirmDialog](../../../../Controls/Dialogs/ConfirmDialog.axaml.cs)) с русским склонением «запись/записи/записей»;
- дублирование → `DuplicateCalendarRecord`.

Выбор целевой БД встроен в само окно записи ([RecordDialog](../../../../Controls/Dialogs/RecordDialog.axaml.cs)) —
комбобокс «База данных» виден при нескольких смонтированных БД (при изменении это переносит запись
в другую базу). Если в коллекции несколько видимых полей-дат, в окне есть список «Дата записи» —
в какое поле положить дату события; смена поля переносит дату (старое поле очищается). После любой
правки поднимается `CollectionsMayHaveChanged` (обновить сайдбар) и `RefreshCurrent()`.

> **Несколько дат на запись.** Событие — это пара `(Id записи, FieldId поля-даты)`: запись с
> несколькими видимыми полями-датами показывается в календаре несколько раз. Какие поля-даты
> видны — задается тумблером «Отображать в календаре» (окно свойства / контекстное меню коллекции
> в сайдбаре). Видимость поля и галки коллекций в сайдбаре — **мгновенные фильтры чтения**
> (проекция не пересобирается; пустой набор активных коллекций = ни одной, см.
> [performance.md](../../architecture/performance/overview.md)). Подробнее —
> [[../../architecture/data-model]] (раздел «Где календарь»).

## Режимы

| Режим | Индекс | Диапазон данных | Документ |
|---|---|---|---|
| Расписание | 0 | один день, плоский список | [schedule.md](schedule.md) |
| Журнал | 1 | лента по дням | [journal.md](journal.md) |
| День | 2 | один день, сетка часов | [day.md](day.md) |
| Неделя | 3 | 7 дней, сетка часов | [week.md](week.md) |
| Месяц | 4 | сетка 6×7 | [month.md](month.md) |

вынесены в [interactions.md](interactions.md).
