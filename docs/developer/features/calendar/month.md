# Режим «Месяц»

## Назначение

Классическая сетка месяца 6 × 7 (6 недель × 7 дней, неделя с понедельника).
Показывает однодневные события чипами внутри ячеек дня и многодневные/all-day
события — горизонтальными барами поверх сетки. Режим по умолчанию при запуске.

## Где в коде

- View + вся логика раскладки: [MonthView.axaml.cs](../../../../Views/ConstructorDb/Calendar/MonthView.axaml.cs) (`UserControl`, рисует вручную)
- Данные приходят от [CalendarControllerView](../../../../Views/ConstructorDb/Calendar/CalendarControllerView.axaml.cs) через `MonthViewCtrl.Refresh(records, currentDate)`
- Диапазон для месяца — 6 недель (42 дня) от понедельника недели, в которую попадает 1-е число (`GetDateRange`, индекс 4)

## Как работает

Контрол вручную рисует сетку 6 × 7 поверх двух слоев: `DayGrid` с ячейками дней
и `SpanCanvas` — оверлей-Canvas для многодневных событий. Вся раскладка
пересчитывается с нуля при каждом изменении данных или размера контейнера.

### Построение сетки

Точка входа — `Refresh(events, currentDate)`, которая сохраняет события и текущую
дату и вызывает `_BuildAll()`. Этот же метод вызывается при `SizeChanged`
контейнера, поэтому раскладка всегда соответствует актуальному размеру окна.

`_BuildAll()`:

1. Определяет первый день месяца и сдвигает начало сетки к ближайшему понедельнику (`startOffset` — неделя начинается с Пн).
2. Считает ширину/высоту ячейки как `W / 7` и `H / 6`.
3. Проходит по 6 строкам недель. Для каждой недели сначала раскладывает **многодневные бары** на `SpanCanvas`, затем строит **7 ячеек дней**.

### Раскладка многодневных событий

`_ComputeWeekLayout(weekStart)` — жадный алгоритм распределения многодневных и
all-day событий по строкам внутри недели:

- События, пересекающие неделю, сортируются по дате начала, затем по убыванию длительности.
- Для каждого события ищется первая строка, где оно не пересекается с уже размещенным (`sc > rowEnds[r]`); если такой нет — добавляется новая строка.
- Результат — `Dictionary<eventId, LayoutEntry(RowIdx, Sc, Ec)>`, где `Sc`/`Ec` — индексы колонок начала и конца в пределах недели (0–6).
- **Пятидневка** (настройка «Дней в неделе: 5»): сетка остается 7 колонок, но сегмент
  бара клипуется пятницей (`CalendarMath.ClipSpanToWorkdays`; сегмент целиком в Сб/Вс не
  рисуется — «Пт–Пн» распадается на пятницу этой недели и понедельник следующей),
  обрезанный конец теряет `rightCap`, а выходные ячейки не резервируют строки под бары
  (`_SpanRowsForDay` возвращает пустое множество).

Бары рисуются методом `_AddSpanBar`. Учитываются «капы» (скругленные торцы)
только на реальных краях события: `leftCap`, если событие начинается в этой
неделе, `rightCap` — если заканчивается. Под цветной полупрозрачный фон
подкладывается белый слой, чтобы бар перекрывал линии сетки. События с одинаковым
`Id`, разрезанные на несколько недель, хранятся списками в `_spanBgBorders` /
`_spanTextBlocks`, поэтому ховер и выделение подсвечивают **все** сегменты одного
события сразу.

### Ячейки дней и однодневные события

`_MakeCell` строит одну ячейку:

- **Число дня** в кружке справа-сверху. Сегодняшний день — белый текст на красном кружке; выходные (Сб/Вс) — красный текст; дни соседних месяцев — приглушенный серый, фон ячейки чуть темнее.
- **Однодневные события** (`_MakeChip`) укладываются в `StackPanel`, смещенный вниз на `topOff`, чтобы не перекрывать многодневные бары. `topOff` зависит от максимальной занятой строки spanning-событий в этой ячейке.
- Сколько чипов влезает (`maxVis`) рассчитывается из доступной высоты; все, что не помещается (вместе со скрытыми барами), сворачивается в подпись **«+N еще»** внизу ячейки.
- Раскладка однодневных событий по строкам ячейки — линейная: события раскладываются по дням одним проходом, свободная строка ищется бегущим курсором (строки занимаются по возрастанию), бары перебираются по короткому списку многодневных событий. Прежде на каждый день заново фильтровались все события окна, а свободная строка искалась с нуля для каждого события — на днях-гигантах квадратично, и построение месяца держало UI-поток 1,2–1,7 с (в журнале пользователя — «Интерфейс не отвечал 4–11 с … загрузка календаря»).
- Окно читается с ограничением на день (см. [overview](overview.md)): день-гигант отдает виду только первые `MonthDayCap` (24) timed-событий — ячейке больше не показать (строк 13–14 даже на высоком окне) — и отдельно столько же многодневных timed, начинающихся в этот день (иначе в переполненном дне вечерние, пересекающие полночь, отсекались бы вместе с однодневными), all-day — с общим `GridDayCap`, поэтому в «+N еще» дополнительно входит недоставленное — разница карты счетчиков дней (`Refresh(events, currentDate, dayTotals)`) и фактически полученного по дню старта. Карта доезжает **второй фазой** (события показываются сразу, без «Загрузка…»; «+N еще» тихо уточняется по ее приходе). Без карты (поиск/первые мгновения) — расчет от полученного.
- Перенос события между днями (drag) — **на месте**: `RecordMoved` отдает контроллеру исходные даты, дельта `[(старое,−1),(новое,+1)]` правит снимок сетки и карту счетчиков без перезагрузки окна.

Константы макета: высота строки числа `DateH=34`, высота бара `BarH=18`, шаг между
барами `BarStep=20`, высота «+N еще» `MoreH=16`.

## Взаимодействия

- **Ховер по ячейке** — подсветка фона (`_UpdateCellHover`), вычисляется по позиции курсора через `_DayAtPos`.
- **Ховер по кружку с числом** — число заменяется иконкой «+» (`_UpdateCircleHover` + `_CircleDayAtPos` проверяет попадание в круг радиусом 12px).
- **Клик по «+»** → `DayAddClicked` (создать событие в этот день).
- **Двойной клик по ячейке/числу** → `DaySelected` (перейти в режим «День»).
- **Клик по событию** → выделение (заливка сплошным цветом, белый текст). **Двойной клик по событию** → `RecordClicked` (открыть на редактирование).
- Клик мимо событий снимает выделение — обработчик вешается на окно в `OnAttachedToVisualTree`.

### Drag & Drop переноса событий

Перетаскивание реализовано вручную через захват указателя:

1. `_BeginDragTrack` запоминает событие, исходный день и позицию нажатия, захватывает указатель. Drag активируется только после смещения курсора более чем на 6px (`_OnDragMoved`), чтобы не путать с кликом.
2. Во время перетаскивания исходный чип/бар становится полупрозрачным, а на целевом дне рисуется **превью** (`_UpdateDragPreview`): существующие однодневные события дня сдвигаются вниз на `BarStep`, освобождая место; если места нет — превью не показывается.
3. При отпускании (`_OnDragReleased`), если целевой день отличается от исходного, у события на дельту дней сдвигаются `StartDt`/`EndDt` и вызывается `RecordMoved` для сохранения. `_CancelDrag` восстанавливает прозрачность и убирает превью.
4. При пятидневке целевой день под курсором прижимается к ближайшему рабочему по
   направлению перетаскивания (`CalendarMath.SnapToWorkday` в `_OnDragMoved`) — ghost
   сразу встает на прижатый день, на Сб/Вс событие бросить нельзя.

### События контрола

| Событие | Когда возникает |
|---|---|
| `DaySelected` | Двойной клик по дню — переход в режим «День» |
| `DayAddClicked` | Клик по «+» в кружке дня — создать событие |
| `RecordClicked` | Двойной клик по событию — открыть на редактирование |
| `RecordMoved` | Событие перетащено на другой день |
| `RecordDeleteRequested` / `RecordsDeleteRequested` | Удаление одного / нескольких |
| `RecordDuplicateRequested` | Дублирование из контекстного меню |

Общие правила выделения, удаления и контекстного меню — в [interactions.md](interactions.md).

## Отрисовка

Месяц рисуется двумя контролами ([`MonthSurfaces`](../../../../Views/ConstructorDb/Calendar/MonthSurfaces.cs)): ячейки с числами, плашками однодневных событий и «+N еще» — под слоем линий сетки, полосы многодневных — над ним (белая подложка полосы закрывает линии). Раскладку — строки полос, свободные строки плашек, скрытые — по-прежнему считает `MonthView`; поверхности рисуют и находят плашку под указателем, а полосы ловят указатель только над собой — мимо них нажатие уходит к ячейкам. Раньше ячейка собиралась из восьми контролов, плашка — из шести, полоса — из семи: месяц на базе 10 млн строил 1,5–2 тысячи контролов, и построение (90–240 мс, по приходе чисел дней — еще раз) почти целиком уходило на привязку их стилей. Кадры (`Tests/Sections --only frames`: обычный, наведение на плашку и на полосу, выделение, масштаб 1 и 2) совпадают с прежними, кроме трех пикселей сглаживания одной буквы; перенос плашки мышью проверяется там же по дате в базе.
