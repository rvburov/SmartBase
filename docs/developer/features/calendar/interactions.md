# Календарь — общие взаимодействия

Жесты выделения, удаления, контекстного меню, drag & drop работают одинаково во
всех режимах. Каждый вью-контрол лишь поднимает события наверх, а
[CalendarControllerView](../../../../Views/ConstructorDb/Calendar/CalendarControllerView.axaml.cs)
открывает диалоги и пишет в нужную БД.

## Выделение

- **Одиночный клик** по событию — выделить только его (остальные снимаются).
- **Shift+клик** — аддитивно: добавить или снять событие из набора (множественное выделение).
- **Ctrl+Shift+клик** («Расписание»/«Журнал») — выделить ДИАПАЗОН: все строки между якорем
  (последней выделенной кликом записью) и кликнутой, включительно; в Журнале заголовки дней
  пропускаются. Под виртуализацией помечаются строки из кеша страниц (включая заглушки
  «Загрузка…» — заполнившись, они остаются выделенными); страницы вне кеша не трогаются.
- **Клик по пустому месту** — снять все выделение. Реализовано глобальным обработчиком `PointerPressed` (tunnel) в `OnAttachedToVisualTree`. Исключения: **правый клик** и **Shift+клик** выделение не сбрасывают.
- **Правый клик по невыделенному событию** — сначала выделяет его одно, чтобы меню действовало на видимо выделенное.

## Удаление

- Клавиши **Delete / Backspace** удаляют выделенное, пока режим виден (`IsVisible`) и фокус не в текстовом поле (`TextBox`/`AutoCompleteBox`).
- Одно событие → `RecordDeleteRequested`; несколько → `RecordsDeleteRequested`. Оба пути идут
  через ОДНО подтверждение (`DeleteRecordsWithConfirm`): контроллер показывает
  [ConfirmDialog](../../../../Controls/Dialogs/ConfirmDialog.axaml.cs) с русским склонением
  «запись/записи/записей» — и для одной записи тоже. В Журнале и Расписании записи остаются
  выделенными, пока открыт диалог, — видно, что именно удаляется.
- Больше 100 записей — массовые удаление/дублирование: bulk в фоне (`DeleteRecordsIsolated` по
  каждой БД / `DuplicateRecordsMappedIsolated` по каждой паре «база + коллекция»), с окном прогресса
  («Удаление записей…»/«Дублирование записей…» + «Количество записей: N» + %, как удаление
  коллекции в сайдбаре), если операция дольше 400 мс.
  См. [performance.md](../../architecture/performance/overview.md).
- Дубль и удаление — те же методы репозитория, что у таблицы: копия несет все свойства и исходящие
  связи, удаление предупреждает об обрыве входящих. Дублируется ЗАПИСЬ, а не событие: два события
  одной записи (два поля-даты) дают одну копию, видимую в обоих местах.

## Контекстное меню

Фабрика [EventContextMenu](../../../../Controls/Components/) дает три варианта:

- `Single` — по одному событию: «Редактировать» (`RecordClicked`) / необязательное «Дублировать» / «Удалить» (`RecordDeleteRequested`);
- `Multi` — по нескольким выделенным: необязательное «Дублировать» + «Удалить»;
- `Background` — по пустому месту: «Создать» (`CreateRequested` с датой под курсором).

Дублирование ЕДИНО во всех видах: и одно (`RecordDuplicateRequested`), и несколько выделенных
(`RecordsDuplicateRequested`) — через один путь `DuplicateRecordsWithConfirm` с подтверждением
«Вы дублируете N записей» (кнопка «Дублировать»), как удаление — и для одной записи тоже.
В «Дне»/«Неделе» (включая полосу «весь день» — кросс-зонный набор через хук
`DuplicateAllSelected`, как у удаления) и в «Месяце» (общий набор чипов и многодневных баров)
пункт «Дублировать» при множественном выделении действует на весь набор разом. В «Журнале» и «Расписании» записи остаются
выделенными, пока открыт диалог, а после дублирования выделение ПЕРЕХОДИТ с оригиналов на
копии; лента/список едет к последней по дате/времени копии, только если ее строка не видна
(в сетке перерисовка после дубля выделение не сохраняет).

## Создание

- **Двойной клик по фону** — создать событие на соответствующую дату/время.
- **Месяц**: клик по «+» в кружке дня → создать в этот день.
- **День/Неделя**: клик по слоту времени → `TimeSlotCreationRequested` (дата + время); клик по полосе all-day → `AllDayCreationRequested`.

## Drag & Drop и ресайз

- **Месяц** — перетаскивание чипа/бара на другой день (порог 6px, превью на целевом дне) → `RecordMoved`.
- **День/Неделя** — перетаскивание по времени (и между днями в «Неделе») и ресайз за край для изменения длительности → `RecordMoved`. Во время операции рисуется полупрозрачный ghost с обновляемым временем.
- **Диаграмма** — перенос бара и ресайз за края **целыми днями** (время суток сохраняется), ghost с пересчитанной длительностью → `RecordMoved`. Клик выделяет, Shift+клик — аддитивно, Ctrl+Shift+клик — диапазон, двойной клик открывает; контекстное меню и Delete — как в остальных видах (см. [diagram.md](diagram.md)).

Настройки календаря меняют поведение жестов (см. [overview.md](overview.md#настройки-календаря)):
при пятидневке перетаскивание и ресайз перепрыгивают выходные (в Месяце целевой день
прижимается к рабочему, в Дне/Неделе соседний день — только видимый), а рабочие часы
зажимают drag/создание в период дня и дают перескок ресайза через его границу
(18:00 → 09:00 следующего видимого дня). Дефолты настроек оставляют все как было.

## Что делает контроллер с этими событиями

| Событие вью | Действие контроллера |
|---|---|
| `RecordClicked` | `OpenEditDialog` → [RecordDialog](../../../../Controls/Dialogs/RecordDialog.axaml.cs); смена коллекции/БД = перенос записи с грамотным переносом значений свойств (см. ниже) |
| `CreateRequested` / `TimeSlotCreationRequested` / `AllDayCreationRequested` | `OpenAddDialog` (выбор БД и поля-даты — в самом окне) |
| `RecordMoved` | `UpdateCalendarRecord` в БД события (дата пишется в поле `FieldId` события) |
| `RecordDeleteRequested` / `RecordsDeleteRequested` | удаление (с подтверждением для нескольких) |
| `RecordDuplicateRequested` | копия записи в той же БД (в фоне; копия выделяется вместо исходной) |

После правки контроллер правит вид на месте (`RefreshCurrent` с дельтой) и выделяет созданную,
скопированную или перенесенную запись — как нажатием. `CollectionsMayHaveChanged` (перестроить
сайдбар) поднимают только создание и правка из окна записи: дубль, удаление и перенос состав
коллекций не меняют.

> **Смена коллекции/БД = перенос записи.** Выбор другой коллекции (или БД) в окне события
> переносит запись целиком. Раньше при этом пересоздавалась пустая запись и **значения свойств
> терялись**; теперь они переносятся грамотно — сопоставление полей по имени с приведением типов
> (`ConstructorRepository.CopyFieldValuesByName`, поле-дата исключается, чтобы не затереть
> отредактированную дату). Недостающие в целевой коллекции свойства календарь **не создает** (окно
> визуально не меняется); та же логика с галочкой «Перенести все свойства» доступна при переносе
> через таблицу — см. [[../constructor/table]].
>
> **Аудит записи перенос сохраняет** (`RestoreMovedRecordAudit`): пересоздание строки штампует
> чужой аудит трижды — `AddCalendarRecord` ставит «создано сейчас», `StampNewRecordAudit` —
> текущего пользователя автором, копирование значений и связей добивает «изменено». Поэтому
> четыре поля аудита источника возвращаются ПОСЛЕ копирования, и событие коллеги не выглядит
> созданным вами сегодня — как и при переносе из таблицы (`MoveRecordsCore`).

> **Несколько дат на запись.** Событие опознается парой `(Id, FieldId)` (вью используют ее
> для выделения/перетаскивания, не путая «соседние» даты одной записи). **Перетаскивание/ресайз**
> меняет дату именно в поле `FieldId` события. **Удаление** удаляет всю запись (а не только эту
> дату) — поэтому пропадают и остальные ее события. **Перенос даты в другое поле** — через
> список «Дата записи» в окне (старое поле очищается). См. [[overview]] и
> [[../../architecture/data-model]].
