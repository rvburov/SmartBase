# Страница записи (RecordPageView)

## Назначение

Правая панель с деталью записи в стиле Obsidian: сверху — свойства (типизированные
поля), снизу — текстовое описание в Markdown с переключением «редактор ↔ просмотр».
Все изменения сохраняются в БД сразу (по потере фокуса).

## Где в коде

- View: [RecordPageView.axaml.cs](../../../../Views/ConstructorDb/RecordPageView.axaml.cs)
- ViewModel: [RecordPageViewModel](../../../../ViewModels/ConstructorDb/) (`Show(repository, recordId, collectionId)`)
- Markdown: [MarkdownUtils](../../../../Utils/MarkdownUtils.cs) + `Markdown.Avalonia`

## Как работает

`Show(repository, recordId, collectionId)` создаёт `RecordPageViewModel`, заполняет
заголовок, текст описания и список свойств (`BuildProperties`).

### Заголовок

Кликабельный `TextBlock` превращается в `TextBox` для редактирования; по Enter/Escape
или потере фокуса возвращается обратно. Пустой заголовок показывается серым «Без
названия».

### Свойства

Для каждого поля (`PropertyRowVm`) `MakeInputForField` строит контрол под тип:

| `FieldType` | Контрол |
|---|---|
| `text` / `url` | `TextBox` (у url — watermark `https://`) |
| `number` | `TextBox` |
| `date` | `DateEditor` (тот же виджет, что и в таблице: канон `DateValue` — диапазоны, дата+время, «весь день») |
| `select` / `status` | `ComboBox` с вариантами из `ConfigJson` → `options` (у `status` — три статуса по умолчанию) |
| `multiselect` | `MultiSelectBox` — текст через запятую + выпадающий чеклист с поиском; значение — JSON-массив |
| `checkbox` | `CheckBox` (хранится как `1`/`0`) |

Каждый ввод сохраняется по потере фокуса/изменению через `row.Persist()`
(→ `SetFieldValue` в репозитории).

### Граница свойства / описание (ручка перетаскивания)

Между блоком свойств и описанием — ручка-пилюля `PropsResizeGrip` (горизонтальная,
с тремя точками — как вертикальные ручки сайдбара/панели записи в MainWindow) поверх
тонкой линии-разделителя. Свойства лежат в `ScrollViewer` (`PropertiesScroll`),
строка свойств в `PageGrid` по умолчанию `Auto` (высота по контенту), описание —
в Star-строке.

Перетаскивание (`OnPropsGripPressed/Moved/Released`) задаёт строке свойств пиксельную
высоту: вниз — свойства растут и сжимают описание; вверх — свойства сжимаются, и если
их больше, чем влезает, `ScrollViewer` даёт прокрутку. Высота ограничена
`PropsHeightMin`…(высота панели − запас на шапку/футер/минимум описания). Выбранная
высота (`_propsHeight`) помнится в пределах сессии и переносится между записями
(на диск не пишется — у разных записей разное число свойств).

### Нижний блок (Markdown)

Снизу — редактор ОДНОГО текстового свойства. Цель по умолчанию — поле с ролью
«Описание» (`RecordPageViewModel.DescriptionFieldId`); выбор любой другой карточки типа
«Текст» переключает цель на неё. Коллекция без описания и без текстовых полей — снизу
пусто (см. [[../../architecture/data-types/description]]).

Пока поля-описания у коллекции нет, в крошке вместо имени свойства стоит синяя ссылка
**+ «Добавить описание»** (`AddDescriptionLink`, скрыта без права `CreateField`). Она занимает
место имени, поэтому видна ровно тогда, когда снизу пусто: выбор текстовой карточки отдаёт
крошку её имени и прячет ссылку до следующего открытия записи (`Show` сбрасывает
`_bottomFieldId`). Клик уходит наверх событием `AddDescriptionRequested` → MainWindow →
`ConstructorControllerView.CreateDescriptionFieldFromPanel`: поле заводится без диалога (имя и
тип у роли предопределены), в таблице появляется колонка, а `FieldsChanged` перечитывает
панель — блок открывается уже на описании, каретка сразу в редакторе.

`MarkdownEditor` — исходный текст; `PreviewToggle` переключает на динамический
просмотр (`MarkdownPreview.Markdown`). Сохранение текста и заголовка — по потере
фокуса (`WireAutoSave`, «save on blur», чтобы не было шторма записей при печати),
после чего поднимается `RecordChanged`.

### Живая синхронизация с таблицей (обе стороны)

Запись и таблица — одни и те же строки одной БД, поэтому правка в одной сразу видна
в другой, без полной перезагрузки:

- **Запись → таблица:** правка имени/описания/значения шлёт `RecordChanged` →
  `RefreshRecordRow` (перечитывается ОДНА строка на месте).
- **Таблица → запись:** правка ячейки в `TableRowVm` (сеттер индексатора) поднимает
  событие `Edited(recordId)` → `VirtualRowList.RecordEdited` → `TableView.RecordValueEdited`
  → `ConstructorControllerView.RecordValueEdited` → MainWindow. Если открыта ИМЕННО эта
  запись (`rid == _lastOpenedRecordId`), вызывается `RecordPageView.ReloadFromDb()`.
- **Добавление/правка/дубль/удаление свойства в таблице → запись:** структурные методы
  свойств в `ConstructorControllerView` поднимают `FieldsChanged` → MainWindow → если панель
  открыта, `ReloadFromDb()` перестраивает список свойств (новое поле появляется сразу).

Важно про `RefreshRecordRow` (запись → таблица): перед перечитыванием строки таблица делает
`RecordsGrid.CancelEdit()`. Редакторы даты/выбора в таблице задают значение императивно
(`Storage`/`SelectedItem` ставятся один раз) и НЕ обновляются по `NotifyAllCells` — открытый
редактор показывал бы старое значение, а при коммите ещё и затёр бы свежее из панели. После
отмены ячейка показывает биндинг-дисплей со свежими данными.

`ReloadFromDb()` перечитывает запись из БД (значения свойств, имя, описание) и обновляет
панель на месте. Поле, которое пользователь сейчас редактирует в панели (заголовок в
режиме правки или markdown-редактор в фокусе), не трогается — чтобы не затереть
набираемый текст; режим просмотра markdown сохраняется. `WireAutoSave` повторно не
вызывается (его подписки читают актуальный `_vm`).

### Кнопка панели коллекции

`CollectionPanelBtn` шлёт `CollectionPanelToggled` — MainWindow показывает/прячет
блок коллекции рядом со страницей записи.

## Взаимодействия (события наверх)

- `RecordChanged` — запись изменена (обновить таблицу/счётчики).
- `CollectionPanelToggled` — переключить видимость панели коллекции.
