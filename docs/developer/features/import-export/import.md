# Импорт таблиц

Часть [обзора импорта/экспорта](overview.md).

## Импорт таблиц

### Форматы

- **Excel** `.xlsx` / `.xlsm` / `.xlsb` / `.xls` — библиотека **ExcelDataReader** (MIT,
  чисто управляемая, потоковое чтение строк без материализации книги). ClosedXML в
  проекте остался только для **записи** отчётов в расширениях (PdfAnalyzer/AssemblyCalc/
  ProductCompare) — импорт его больше не использует.
- **CSV** — собственный потоковый парсер (RFC 4180: кавычки экранируют разделитель и
  перенос строки, `""` → `"`). Разделитель `,`/`;`/таб и кодировка (UTF-8 / Windows-1251 /
  UTF-16 по BOM) определяются автоматически по первым 64 КБ. Для Windows-1251 нужен
  провайдер legacy-кодировок — регистрируется на старте (`EncodingSetup.Ensure()` из
  `Program.Main`).
- **JSON** — массив объектов `[{…},{…}]` или **NDJSON** (объект в каждой строке);
  раскладка определяется по первому значимому токену. Читается потоково
  (`Utf8JsonReader` поверх FileStream с дозаполнением буфера; одно значение больше
  64 МБ → дружелюбная ошибка).

Формат выбирается по расширению файла. Цель импорта — всегда **новые** коллекции.

### Конвейер (двухпроходный, потоковый)

```
ImportPlanner.Plan(ImportSpec) → список ImportUnit (1 юнит = 1 будущая коллекция)
на юнит: ITableSource.Analyze  — проход 1: валидация + схема (поля, точное число записей,
                                 счётчик пустых названий); строки в память НЕ складываются
         ITableSource.ReadRows — проход 2: записи потоком (файл переоткрывается)
         ConstructorRepository.ImportStreamedCollectionIsolated — запись пакетами
```

Почему два прохода: набор полей должен быть известен ДО создания коллекции (у JSON —
объединение ключей по всем записям), границы по непустому содержимому (см. ниже) нельзя
узнать без полного чтения, файл валидируется целиком до первой записи в БД, а память
остаётся O(1) на любом объёме. Последовательное чтение файла дважды — дёшево на фоне
записи в SQLite.

### Структура окна

Открывается по кнопке в сайдбаре. Стиль — как у остальных диалогов:
`SizeToContent`, баннер ошибок, удержание позиции окна.

1. **Режим**: «Импорт» / «Экспорт» — переключает набор полей левой колонки и подпись
   кнопки (экспорт — см. раздел «Экспорт таблиц»).
2. **Файл**: поле пути + «Обзор…» (фильтр `*.xlsx; *.xlsm; *.xlsb; *.xls; *.csv; *.json`).
   Под полем — чекбокс **«Все файлы из папки (включая подпапки)»**: путь указывает на
   папку, «Обзор…» открывает выбор папки. Чекбокс общий (не часть ручного типа — он
   меняет смысл поля «Файл» и работает со стандартным типом): импортируются все
   поддерживаемые файлы рекурсивно, в порядке путей; название коллекции — имя файла без
   расширения (занятые имена репозиторий уникализирует «(копия)»-схемой); Excel-файлы
   уважают ручные параметры и чекбоксы листов, **CSV/JSON всегда идут по стандартным
   правилам**.
3. **Название коллекции** — обязательное (пусто/дубль → ошибки в баннере). В режиме
   папки поле выключено: названия берутся из имён файлов/листов.
4. **База данных** — выбор подключённой БД.
5. **Расположение** — родительская группа (перестраивается при смене БД).
6. **Тип импорта**: «Стандартный» / «Ручной (только Excel)». Под стандартным — серое
   пояснение, которое **меняется под формат выбранного файла** (Excel/CSV/JSON/не выбран).
7. Кнопки: **Импортировать** / **Отмена**. По «Импортировать» окно валидирует ввод
   (включая белый список расширений и «ручной — только Excel») и возвращает заявку
   (`ImportRequest` с `ImportSpec`) — сам импорт выполняет вызывающий
   (`Sidebar.OpenImportExport`).

### Ручной тип (только Excel)

Карточка с параметрами: **Лист** (пусто — первый), **Строка заголовков**, **Строка
данных**, **Столбец названия** (число или буква; проверяется сразу в окне) и **исключения**:

- **Исключить листы** — названия через запятую (без учёта регистра). Исключённые листы
  пропускаются во всех режимах; «первый лист» стандартного выбора — первый неисключённый;
  лист, указанный в поле «Лист» и одновременно исключённый, — ошибка валидации.
- **Исключить строки** — номера и диапазоны, можно вперемешку: `4-9, 11, 14-28`
  (разделители — запятая или точка с запятой). Номера — абсолютные номера строк листа,
  как «Строка заголовков»/«Строка данных».
- **Исключить столбцы** — номера, буквы и диапазоны: `B, D-F, 8`. Столбец названия
  исключать нельзя (ошибка сразу в окне).

Исключённое не участвует ни в данных, ни в границах импорта (исключённый крайний столбец
не тянет за собой пустые «Без названия»-колонки); заголовки читаются даже из исключённой
строки — исключения действуют на данные. Действуют только на Excel (как весь ручной
режим); диапазон вроде `1-1000000` хранится диапазоном, а не миллионом чисел. Ниже —
чекбоксы:

- **«Все листы в одну коллекцию»** — столбцы сопоставляются по итоговому имени
  заголовка (после дедупликации в пределах листа), объединение в порядке первого
  появления по порядку листов; у листа без какого-то столбца значения пустые; подпись
  «Название» — с первого непустого листа; полностью пустые листы пропускаются.
- **«Все листы в разные коллекции»** — коллекция на лист, имя «{Название} — {Лист}»
  (один лист в книге → просто «{Название}»). Взаимоисключающий с предыдущим
  (отметка одного снимает другой).

Параметры ручного режима (строки/столбец) одни на все листы и файлы; с режимом папки
(чекбокс при поле «Файл») сочетаются свободно.

### Окно загрузки и отмена

После «Импортировать» показывается [ProgressDialog](../../../../Controls/Dialogs/ProgressDialog.axaml.cs)
с **кнопкой «Отмена»** (opt-in через `EnableCancel`; остальные операции приложения — без неё).
Работа идёт в фоне (`Task.Run`), юниты по очереди; юнит занимает свой сегмент шкалы:
«Анализ файла…» — 0–30 % сегмента (прогресс по байтам файла), «Импорт записей…» —
30–100 % (прогресс по строкам, счёт точный из прохода 1). При нескольких юнитах строка
под заголовком показывает «Файл N из M: имя».

**Отмена**: кнопка гаснет, полоса переходит в «Отмена…», фоновая задача прерывается
между пакетами записи; недолитая коллекция **удаляется целиком** (батч-удалением),
уже готовые коллекции остаются. Диалог импорта после отмены не переоткрывается.

При **ошибке** окно загрузки исчезает, а окно «Импорт/Экспорт» открывается заново с теми
же значениями (prefill) и текстом ошибки в баннере. В пакетном режиме готовые коллекции
остаются, сбойная удалена, текст ошибки называет файл и число успевших коллекций.
Валидация полей показывается сразу в окне, **без** показа загрузки.

### Производительность

- **Потоковая запись пакетами**: строки пишутся пакетами по 20k, **каждый пакет — своя
  транзакция** (WAL не разрастается на весь объём; модель — батч-удаление), записи и
  значения — сырым ADO.NET prepared-INSERT (EF на миллионах строк ≈60× медленнее).
  В своей транзакции импорт — единственный писатель, поэтому id пакета непрерывны:
  `RecordId = firstNew + индекс` (`firstNew = last_insert_rowid − размер_пакета + 1`).
- **Шаг Position**: 1000, но при объёме > 2 млн строк — 1: `(idx+1)*1000` в `int`
  переполнялся после ~2,1 млн строк (латентный баг старого пути).
- **Границы по содержимому (важно).** Последняя строка/столбец берутся по реально
  непустым ячейкам, а не по dimension листа (Excel) и не по максимальной длине строки
  (CSV): пустые отформатированные хвосты и «запятые до последнего столбца» из
  Excel-экспорта иначе раздували импорт тысячами колонок «Без названия».
- **Изолированное подключение** + `ApplyBulkPerformancePragmas` (кеш ~512 МБ,
  mmap 2 ГБ) — без них вставка в глобальные индексы `db_field_values` деградирует.
- Замер ([Tests/ImportPerf](../../../../Tests/ImportPerf/Program.cs), `--perf --rows N`;
  рабочий ноутбук, свежая БД): CSV 1 млн строк × 8 колонок (97 МБ) — анализ 1,3 с +
  импорт 115 с; CSV 10 млн (1 ГБ) — анализ 9 с + импорт 1232 с (~8,1 тыс. строк/с ≈
  70 тыс. INSERT/с, скорость НЕ падает с ростом объёма). Пик памяти процесса
  (~0,7–1,4 ГБ) — это mmap-окно SQLite из bulk-прагм, а не буферизация строк.

### Стандартный тип (правила по форматам)

- **Excel**: берётся первый лист; первая строка — заголовки; 1-й столбец → название
  записи, остальные → текстовые свойства; данные со второй строки.
- **CSV**: то же, разделитель и кодировка — автоматически.
- **JSON**: ключи объектов → свойства (объединение по всем записям, порядок первого
  появления). Название записи — ключ **«Название» → `name` → `title`** (без учёта
  регистра), иначе первый ключ первого объекта. Вложенные объекты/массивы сохраняются
  **сырым JSON-текстом**, числа/булевы — как в файле, `null` → пусто.
- Колонка «Описание» создаётся пустой и ставится в конец (данные в неё не импортируются);
  все значения сохраняются как текст.

### Скрытые данные Excel

Скрытые **строки, столбцы и листы** импортируются наравне с видимыми — данные не
теряются. В стандартном режиме «первый лист» — первый по порядку в книге, даже скрытый;
режимы «все листы …» включают скрытые листы.

### Правила пустых значений (фолбэк «Без названия»)

- Пустая ячейка в строке заголовков (или пустой ключ JSON) → «Без названия»; несколько →
  «Без названия 1», «Без названия 2»… Повторяющиеся имена дедуплицируются номером.
- Пустое название записи → «Без названия» (одна такая запись) или «Без названия N»
  (несколько; счётчик точный, из прохода 1). Строки **не пропускаются**.

### Ошибки и сообщения

**Никаких отчётов** в конце (нет «Импортировано N, пропущено M») — показываются только
ошибки, как `ImportException` с дружелюбным текстом в баннере диалога. Карта
([ImportErrors](../../../../Core/Importers/ImportErrors.cs); ошибки записи переводит репозиторий):

| Ситуация | Текст |
|---|---|
| Файл не найден / удалён во время импорта | «Файл … не найден или был удалён во время импорта.» |
| Нет прав доступа (файл или папка) | «Нет прав доступа к … Проверьте разрешения и повторите.» |
| Эксклюзивная блокировка другим процессом | «Файл … занят другой программой. Закройте его и повторите.» |
| Слишком длинный путь | «Слишком длинный путь к файлу.» |
| Пустой файл / пустой лист / нет записей | «… — нет данных для импорта.» |
| Битый или чужой формат (Excel/JSON) | «Файл повреждён …» / «Некорректный JSON …» |
| Неподдерживаемое расширение | «Формат файла не поддерживается. Доступны: …» |
| Диск переполнен (SQLITE_FULL) | «Недостаточно места на диске — импорт отменён, частичные данные удалены.» |
| Прочая ошибка записи в БД | «Ошибка записи в базу данных. Импорт отменён.» |
| Лист не найден (ручной режим) | «Лист „…" не найден.» |

Файлы открываются с `FileShare.ReadWrite` — файл, открытый в Excel, импортируется без
конфликта. **Mark-of-the-Web** (файл «из интернета», `Zone.Identifier`) чтению данных не
мешает — это политика запуска исполняемых файлов и офисных макросов, а не чтения; спец-
обработка не нужна. Любая ошибка или отмена после создания коллекции откатывается
удалением этой коллекции — БД остаётся чистой. Исключение — крэш всего приложения
посреди импорта: частичная коллекция останется (транзакция-на-пакет), её можно просто
удалить.

### Прочие дефолты

- **Даты** — фиксированный `дд.MM.гггг` (со временем — `дд.MM.гггг чч:мм`), как ждёт
  `DateValue`: импортированный столбец без потерь переводится в тип «дата» и обратно.
- **Числа Excel** — `G15` инвариантно (15 значащих цифр — столько хранит Excel; без
  двоичного шума, разделитель — точка). Числовой **формат ячейки не применяется**
  (0.5 с процентным форматом → `0.5`, а не «50%») — осознанное отличие от прежнего
  ClosedXML-пути с `GetFormattedString`; путь отката — пакет ExcelNumberFormat.
- Булевы Excel → `TRUE`/`FALSE`; ошибки ячеек (`#DIV/0!` и т.п.) → пусто.
- Новая коллекция получает цвет `#007AFF` и иконку `table`.

### Проверки

[Tests/ImportPerf](../../../../Tests/ImportPerf/Program.cs) (в решении, как SidebarPerf) —
селф-тест матрицы: вызывает те же методы, что приложение, на сгенерированных файлах
(кодировки/кавычки CSV, JSON/NDJSON/вложенность, скрытые строки/столбцы/листы, merge/split,
ручные параметры, папка с подпапкой и битым файлом, отмена, занятые имена, карта ошибок) и
сверяет содержимое БД; `--perf --rows N` — замер большого CSV.
Запуск: `dotnet run -c Release --project Tests/ImportPerf`.
