# Экспорт таблиц

Часть [обзора импорта/экспорта](overview.md).

## Экспорт таблиц

### Форматы

- **Excel** `.xlsx` / `.xlsm` — **DocumentFormat.OpenXml** (SAX-писатель `OpenXmlWriter`:
  строки уходят в архив по мере записи, книга в память не поднимается; ClosedXML — DOM,
  на миллионах строк непригоден и остаётся только в расширениях). `.xlsm` — тот же
  контейнер с macro-enabled типом, макросов внутри нет (осознанно: экспорт из БД макросы
  не порождает; некоторые политики/антивирусы к расширению относятся строже).
  **`.xlsb`/`.xls` не экспортируются** — свободных библиотек записи двоичных книг для
  .NET не существует (импорт их читает через ExcelDataReader).
- **CSV** — разделитель `;`, CRLF, кавычки RFC 4180, **UTF-8 с BOM**: Excel открывает
  кириллицу без вопросов, а наш же импорт сниффит BOM и `;` — круговой обмен без настроек.
- **JSON** — массив объектов, без отступов (на 10 млн строк отступы — +30–50 % объёма),
  кириллица не экранируется (`UnsafeRelaxedJsonEscaping`). Ключи — названия столбцов
  (пустые → «Колонка N», дубликаты → «Имя (2)»); колонка названия уходит своим именем
  (дефолт «Название») — импорт находит её первой, круг сходится.

### Конвейер (потоковый)

```
ExportPlanner.Plan(ExportSpec) → список ExportUnit (1 юнит = 1 файл; юнит = список таблиц)
на таблицу юнита:
  GetExportColumnsIsolated  — колонки в порядке таблицы (column_meta.Position/дефолт, без markdown)
  CountRecordsIsolated      — точный total для процентов
  ReadExportRowsIsolated    — строки потоком: keyset-страницы по 2000 + значения пакетом
  ITableWriter              — SAX/поток; листы и переполнение внутри писателя
```

Чтение — на **отдельных подключениях** с bulk-прагмами (страницы `GetRecordsPageAfter` —
row-value сик по индексу, O(страницы) памяти на любом объёме; значения — `GetFieldValuesBatch`,
EF9 транслирует `Contains` в `json_each` — лимита параметров нет). Создание файла — первый
шаг юнита: недоступная папка/диск падают до чтения данных.

### Структура окна (режим «Экспорт»)

1. **Выгрузить в папку** — поле пути + «Обзор…» (выбор папки).
2. **Название файла** — активно, когда файл один (одна коллекция или «в один файл»);
   пусто → имя коллекции (для «в один файл» — «Экспорт»). Иначе поле выключено:
   имена файлов — из имён коллекций.
3. **Формат файла**: `.xlsx` / `.xlsm` / `.csv` / `.json`.
4. **Коллекция** — кнопка-комбо открывает выпадающий выбор с **поиском и чекбоксами**
   ([CollectionPickerFlyout](../../../../Controls/Components/CollectionPickerFlyout.cs), по
   образцу фильтра таблицы: плашка `filterFlyout`, «(Выделить всё)» действует на
   найденное подмножество, «Готово» применяет — закрытие мимо кнопки отменяет выбор).
   Показываются коллекции **всех допущенных БД** (запертые базы и коллекции без права
   «Просматривать коллекцию» отфильтрованы), при нескольких БД — с заголовками-группами.
5. **Тип экспорта**: «Стандартный» / «Ручная выгрузка Excel». Под стандартным — серое
   пояснение, которое меняется под выбранный формат.
6. Кнопка **Экспортировать** валидирует ввод (папка существует, ≥1 коллекция, допустимые
   символы имени файла и листа, «ручной — только Excel») и возвращает `ExportRequest` —
   саму выгрузку выполняет вызывающий (`SidebarTree.RunExport`).

### Ручная выгрузка Excel (правая колонка)

- **Лист** — своё имя листа (только при одной коллекции; пусто — имя коллекции).
- **Исключить столбцы** — названия свойств через запятую; **несовпавшие имена молча
  игнорируются** (выбор может охватывать коллекции с разными наборами полей). Исключение
  всех столбцов коллекции — ошибка. Совпадение — без учёта регистра.
- **Без строки заголовков** — выгружаются только данные.
- **Включать скрытые записи и столбцы** — по умолчанию экспортируется только видимое
  (скрытые записи `record_display` и столбцы `column_meta.Visible=0` не попадают); галочка
  добавляет скрытое.
- **Все коллекции в один файл (лист на коллекцию)** — одна книга, листы названы по
  коллекциям (дубликаты имён → «Имя (2)»).

### Столбцы и порядок

Выгружаются колонки таблицы в её порядке: «Название», свойства, «Описание» — с учётом
перестановок и переименований системных колонок (аспекты `Position`/`DisplayName` в `column_meta`).
Поля типа `markdown` не выгружаются (они и не колонки таблицы).

### Правила форматирования значений

Хранение: числа — сырой ввод (допускает `.` и `,`), даты — ISO-канон `DateValue`,
checkbox — `1`/`0`, остальное — строки.

| Тип | .xlsx/.xlsm | .csv | .json |
|---|---|---|---|
| текст/select/url/user/Название/Описание | строка (inline) | строка | string |
| number | числовая ячейка (`,`→`.`, invariant); неразобранное — строка | сырая строка | number; неразобранное — string |
| date | «точечные» даты — настоящие датные ячейки (формат `дд.мм.гггг[ чч:мм]`); диапазоны — строкой `дд.MM.гггг - дд.MM.гггг` | человекочитаемо (`дд.MM.гггг …`) | ISO-канон хранения (лосслесс круг) |
| checkbox | булева ячейка (ИСТИНА/ЛОЖЬ) | `1` / пусто (круговой truthy) | true / false |
| пусто | ячейка не пишется (сетку держат ссылки `r=`) | пустое поле | `""` (стабильная схема строки) |

### Имена файлов и листов, переполнение

- Названия коллекций могут содержать что угодно — имена файлов санитайзятся
  (`\/:*?"<>|` и управляющие → `_`, крайние точки/пробелы срезаются, ≤100 символов,
  резервные имена Windows типа `CON` получают префикс), имена листов — по правилам Excel
  (`[]:*?/\` → `_`, ≤31 символа).
- Занятые имена файлов уникализируются: «Имя (2).xlsx» — против диска и между юнитами
  одной выгрузки (одноимённые коллекции разных БД не затирают друг друга). Существующие
  файлы **никогда не перезаписываются** (`FileMode.CreateNew` — страховка от гонок).
- **Переполнение листа**: лист Excel вмещает 1 048 576 строк (с шапкой); длинная
  коллекция автоматически продолжается на листах «Имя 2», «Имя 3»… с повтором шапки.
  Все данные выгружаются всегда. У CSV/JSON лимита нет.

### Окно загрузки, отмена, результат

Тот же [ProgressDialog](../../../../Controls/Dialogs/ProgressDialog.axaml.cs) с кнопкой
«Отмена»: юнит занимает свой сегмент шкалы («Подготовка…» — первые 5 % таблицы, счёт
записей; «Экспорт записей…» — остальные 95 % по строкам), при нескольких файлах — строка
«Файл N из M: имя». **Отмена/ошибка**: недописанный файл удаляется, готовые файлы
остаются; после отмены окно не переоткрывается, после ошибки — переоткрывается с теми же
значениями и текстом в баннере (в мульти-режиме текст называет файл и число успевших).
**Успех**: папка выгрузки открывается в проводнике; БД не менялась — сайдбар не
перечитывается.

### Права и журнал

Пикер показывает только допущенное: базы с `AccessGranted`, коллекции с правом
«Просматривать коллекцию» (`ViewCollection`); оркестрация перепроверяет право перед
чтением (страховка от отзыва прав при открытом окне). Отдельного бита «экспорт» нет —
экспорт есть чтение. В журнал изменений пишется строка `export` на каждую выгруженную
коллекцию (в БД-источнике, с числом записей): «экспортировал коллекцию «X» (N записей)».

### Ошибки и сообщения

Карта ([ExportErrors](../../../../Core/Exporters/ExportErrors.cs)):

| Ситуация | Текст |
|---|---|
| Папка не найдена / удалена во время экспорта | «Папка не найдена или была удалена во время экспорта.» |
| Нет прав на запись | «Нет прав на запись в папку. Выберите другую папку и повторите.» |
| Диск переполнен | «Недостаточно места на диске — экспорт отменён.» |
| Целевой файл занят/заблокирован | «Файл … занят другой программой или уже существует. Закройте его и повторите.» |
| Слишком длинный путь | «Слишком длинный путь к файлу.» |
| Недопустимое имя | «Недопустимое имя файла ….» |
| Все столбцы исключены | «Все столбцы коллекции «…» исключены — нет данных для экспорта.» |
| Право просмотра отозвано | «Недостаточно прав: просмотр коллекции «…» запрещён администратором базы данных.» |

### Производительность

- Чтение: keyset-страницы по 2000 записей + значения пакетом на отдельном подключении
  с bulk-прагмами (без них чтение `db_field_values` на десятках ГБ деградирует).
- Запись: SAX/поток во всех форматах; xlsx — без shared strings (inline), пустые ячейки
  не пишутся; JSON — принудительный `Flush` каждые 500 строк (иначе `Utf8JsonWriter`
  копит весь вывод в памяти). Память процесса — O(страницы), не растёт с объёмом.
- Замер ([Tests/ExportPerf](../../../../Tests/ExportPerf/Program.cs), `--perf --rows N`,
  рабочий ноутбук, коллекция 1 млн строк × 8 столбцов): CSV — 53 с (~19 тыс. строк/с,
  файл 98 МБ), JSON — 48 с (~21 тыс., 260 МБ), XLSX/XLSM — 73–78 с (~13 тыс., 46 МБ);
  пик памяти процесса ~1,6 ГБ — это фикстура-импорт и mmap-окно SQLite, память не
  растёт с объёмом.
- Попутная находка: `GetFieldValuesBatch` переведён на `AsNoTracking` — потоковый
  экспорт зовёт его сотни раз на одном контексте, и change tracker копил ВСЕ значения
  до конца операции (пик 7,9 ГБ и вдвое медленнее на 1 млн записей).

### Проверки

[Tests/ExportPerf](../../../../Tests/ExportPerf/Program.cs) (в решении, как ImportPerf) —
селф-тест матрицы из 62 проверок: вызывает те же методы, что приложение, и главное —
**round-trip**: экспорт → импорт нашим же конвейером → сравнение значений; плюс типы
ячеек xlsx (чтение назад ClosedXML), скрытые записи/столбцы, порядок колонок, ручные
параметры, мульти-коллекция и «в один файл», переполнение листа (инъекция лимита),
санитайз/уникализация имён, отмена посреди второго файла, карта ошибок, журнал.
Запуск: `dotnet run -c Release --project Tests/ExportPerf`.
