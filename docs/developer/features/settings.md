# Настройки

## Назначение

Экран настроек с разделами: **Общее**, **Оформление**, **Управление базой данных**,
**Резервное копирование**, **Календарь**, **Задачи**, **Конструктор базы данных**,
**Заметки**, **Расширения**, **Интеграции**, **Сочетания клавиш**,
**Инструкция пользователя**, **Диагностика**, **О программе**.
Главная функциональная часть — управление списком подключенных БД.

## Где в коде

- View: [SettingsView.axaml.cs](../../../Views/Settings/SettingsView.axaml.cs)
- Строка списка БД: [DatabaseRow.cs](../../../Views/Settings/DatabaseRow.cs)
- Боковая навигация: [SettingsSidebar](../../../Controls/Components/Sidebar/SidebarList.axaml)
- Хранилище значений: app.db через [AppSettings](../../../Utils/AppSettings.cs) (см. [../architecture/databases.md](../architecture/database/storage-and-migrations.md))

## Разделы

`ShowCategory(key)` переключает панель и заголовок:

- **Общее** (`general`) — пять независимых тумблеров: «Уведомления календаря» (напоминания о
  событиях, `notificationsEnabled`, стандарт — включено), «Уведомления задачи «Исполнитель»»
  (`notifyTaskAssigned`) и «Уведомления задачи «Смена стадии»» (`notifyTaskStatus`) — оба по
  стандарту ВЫКЛЮЧЕНЫ, включает их тот, кто работает в общей базе, «Автозапуск при входе в систему»
  (`autostartEnabled`) и «Фоновый режим» (`backgroundEnabled` — не закрывать программу, а
  сворачивать в значок трея). Хранятся дельтами в app.db; рядом с ними в app.db лежит
  состояние службы — водяная метка календаря (`notifyWatermark`) и курсоры очередей задач
  (`notifyTaskCursors`), они пишутся всегда и дельтами не являются. Подробнее — [[notifications]].
- **Оформление** (`appearance`) — масштаб интерфейса (1.0–1.3, `scale`), размер шрифта
  (дельта −3…+3, `fontDelta` → [FontScale](../../../Utils/FontScale.cs)) и две строки по
  разделу навигации: что открывается по умолчанию (`startupModule`) и что вообще показывать
  (`hiddenViews.navigation`). Строки календаря, задач и конструктора переехали в свои разделы
  (контролы те же, механизм `InitAppearance` общий).
  Устройство — [«Виды и их видимость»](#виды-и-их-видимость)
- **Управление базой данных** (`database`) — список и операции над БД
- **Резервное копирование** (`backup`) — папка копий (`backupFolder`), глубина ротации
  (`backupKeep`) и расписание на каждую базу (`backup.<dbId>.enabled` / `.schedule` /
  `.lastRun`); копии снимает служба BackupService, см. [[backup]]
- **Календарь** (`calendar`, [SettingsCalendarPanel.cs](../../../Views/Settings/SettingsCalendarPanel.cs)) —
  все настройки раздела «Календарь»: стартовый вид (`calendarView`) и видимость видов
  (`hiddenViews.calendar`) — переехали из «Оформления» без переименования ключей; новые:
  дней в неделе 7/5 (`calendarDaysInWeek`), рабочие часы в минутах (`calendarDayStartMin` /
  `calendarDayEndMin`, стандарт 0/1440 = «без ограничений», кросс-инвариант start + 60 ≤ end),
  режим прокрутки недели (`calendarWeekScroll`: `week` / `day` / `weekStopToday`),
  длинные события в сетке (`calendarMultiDayGrid`, стандарт false — событие длиннее суток
  уходит в полосу «весь день») и
  длительность нового события (`calendarNewEventDuration`: 30/60/90/120). Живой доступ —
  статический [CalendarSettings](../../../Utils/CalendarSettings.cs) (кэш + событие
  `Changed`, по образцу FontScale): календарь подписан и пересобирается без перезапуска.
  Поведение — [calendar/overview.md](calendar/overview.md#настройки-календаря)
- **Задачи** (`tasks`, [SettingsTasksPanel.cs](../../../Views/Settings/SettingsTasksPanel.cs)) —
  стартовый вид (`tasksView`) и видимость видов (`hiddenViews.tasks`) — переехали из
  «Оформления» без переименования ключей; новые: момент просрочки (`tasksOverdueNextDay`,
  стандарт false — с момента срока), показ выполненных (`tasksShowDone`, стандарт true),
  фильтр при открытии раздела (`tasksStartFilter`: `All` / `Today` / `AssignedToMe` / `NoDue` /
  `Overdue` / `Last`), стадия новой задачи (`tasksDefaultStage`, стандарт «Запланировано»),
  исполнитель (`tasksQuickExecutorMe`, стандарт true) и срок (`tasksQuickDue`: `none` / `today` /
  `tomorrow`) в строке быстрого добавления. Живой доступ — статический
  [TaskSettings](../../../Utils/TaskSettings.cs) (кэш + событие `Changed`, по образцу
  `CalendarSettings`): раздел «Задачи» подписан и перечитывается без перезапуска. Список стадий
  для «Стадии новой задачи» отдает главное окно провайдером `taskStages` в `Initialize` — сам
  экран рабочего пространства не видит. Тумблеры уведомлений по задачам остаются в «Общее».
  Поведение — [tasks.md](tasks.md#настройки-раздела)
- **Конструктор базы данных** (`constructor`,
  [SettingsConstructorPanel.cs](../../../Views/Settings/SettingsConstructorPanel.cs)) —
  стартовый вид (`constructorView`) и видимость видов (`hiddenViews.constructor`) — переехали
  из «Оформления» без переименования ключей; новые: тип нового свойства
  (`constructorNewFieldType`, стандарт `text`; список в панели без `relation`, `user` и
  вычисляемых — им нужна цель или готовые данные записи), открывать созданную запись
  (`constructorOpenNewRecord`, стандарт false — только вид «Таблица», «Список» открывает
  всегда), подтверждение удаления (`constructorConfirmDelete`, стандарт true; предупреждения
  `RelationDeleteImpact` и `RoleLossWarning` ему НЕ подчиняются), цвет новой коллекции
  (`constructorNewCollectionColor`, стандарт `#007AFF` + палитра `AppPalette`), плотность строк
  (`constructorRowHeight`: 28/36/44), стандартная ширина столбца (`constructorColWidth`,
  100–400, стандарт 160 = прежняя константа `MinColWidth`), ручные размеры у новых коллекций
  (`constructorColResize` / `constructorRowResize` — их отдает `GetUiSettings` коллекции без
  своей записи, ровно как `constructorView`), открытие записи двойным кликом
  (`constructorOpenDoubleClick`), вид описания записи (`constructorDescriptionPreview`),
  восстановление записи при запуске (`constructorRestoreRecord`), память раскладки панели
  (`constructorRememberLayout`) и отбора (`constructorRememberFilters`), период опроса чужих
  правок (`constructorPollSeconds`: 3/10/30, фоновый = ×5 — прежние 3 с и 15 с в
  [ChangePoller](../../../Database/ChangePoller.cs)). Живой доступ — статический
  [ConstructorSettings](../../../Utils/ConstructorSettings.cs) (кэш + событие `Changed`, по
  образцу `TaskSettings`): таблица, дерево коллекций и поллер подписаны и перечитываются без
  перезапуска. Плотность строк едет к экрану ресурсом приложения `RowHeightTable` (как
  `AppZoomTransform` у `Scaling`) — только `DynamicResource`, иначе смена настройки не дойдет
  до разметки. Рядом в app.db лежит СОСТОЯНИЕ, а не настройки: раскладка панели
  (`constructorPropsHeight`, `constructorNameColWidth`), последняя открытая запись
  (`constructorLastRecord`, формат «база:запись») и запомненный отбор (`constructorFilters`,
  JSON — см. [ConstructorFilterMemory](../../../Utils/ConstructorFilterMemory.cs), 20 коллекций
  и не более 100 значений на столбец). Выключение «запоминать» стирает запомненное.
  Поведение — [constructor/overview.md](constructor/overview.md#настройки-раздела)
- **Расширения** (`extensions`) — какие расширения показывать (`hiddenViews.extensions`,
  первая строка раздела) и настройки, которые расширения объявили сами
  (`IExtension.Settings`): панель собирается циклом по `ExtensionRegistry.All`, разметка и
  code-behind не знают ни одного расширения по имени, значения лежат в app.db под ключом
  `ext.<id>.<имя>`. Перестраивается при каждом показе — те же ключи пишет кнопка «Обзор» в
  окне расширения. Следы удаленных расширений убирает старт приложения
  (`RemoveOrphanExtensionSettings` + `PruneHiddenViews`). Устройство и почему не отдельная БД —
  [extensions/overview.md](extensions/overview.md#настройки-расширения)
- **Интеграции** (`integrations`) — обмен с чужими программами. Раздел один, а внутри вкладки;
  переключатель — выпадающий список в навбаре (`NavbarSettings.IntegrationsCombo`), как виды
  календаря. Список вкладок задает [IntegrationTabs](../../../Settings/IntegrationTabs.cs), и в
  нем лежат только готовые: пустая вкладка с обещанием читается как поломка раздела. Открытая
  вкладка запоминается (`integrations.tab`). Панель собирает
  [SettingsIntegrationsPanel](../../../Views/Settings/SettingsIntegrationsPanel.cs); вкладка
  «Безопасность» только показывает то, чем заряжен шлюз (`EgressSetup.Last`), — правится
  политика вне программы, см. [integrations/overview.md](integrations/overview.md).
  Кнопка «В коллекцию» на карточке запроса ведет обмен целиком
  ([SettingsIntegrationsRun](../../../Views/Settings/SettingsIntegrationsRun.cs)) и потому
  единственная в разделе настроек пишет в РАБОЧУЮ базу; список открытых баз дает `MainWindow`
  вызываемым провайдером `databases` в `Initialize` — базы монтируются и отцепляются на ходу.
  Вкладка «Сценарии»
  ([SettingsIntegrationsScenarios](../../../Views/Settings/SettingsIntegrationsScenarios.cs))
  правится окном [ScenarioDialog](../../../Controls/Dialogs/ScenarioDialog.axaml.cs), а тумблер
  живет в самой строке — включение ставит якорь расписания, поэтому идет через
  `IntegrationsRegistry.EnableScenario`, а не через правку поля. Шаг «действие расширения» имеет
  свое окно ([ScenarioActionDialog](../../../Controls/Dialogs/ScenarioActionDialog.axaml.cs)): в
  строку списка не помещаются ни коллекция, ни список полей, которого окно не знает наперед. Список
  действий и список коллекций собирает сама вкладка — `ExtensionRegistry.All` называется здесь,
  а не в исполнителе сценариев.
  Вкладка «Доступ извне» ([SettingsIntegrationsInbox](../../../Views/Settings/SettingsIntegrationsInbox.cs)
  плюс [SettingsIntegrationsAccess](../../../Views/Settings/SettingsIntegrationsAccess.cs))
  пишет туда же — папку обмена, режим приема по сети и номер порта; все ее настройки
  (`integrations.inbox.*`, `integrations.ingress.*`) намеренно МАШИННЫЕ. У папки потому, что одну
  папку смотрят несколько компьютеров разом, и общая настройка включала бы прием сразу у всех;
  у порта — потому что порт открывает конкретный компьютер, и иначе тут быть не может. Вкладка «Журнал»
  ([SettingsIntegrationsJournal](../../../Views/Settings/SettingsIntegrationsJournal.cs)) читает
  `integrations.db` (`RunJournal.Current`) и первой строкой показывает расход по накопительным
  потолкам: считается он по этому же журналу, и без него отказ шлюза нечем проверить. Отбор по
  каналу и «только неудачные» живет в полях экрана и НЕ запоминается в настройках — это лупа, а
  не режим работы.
  Вид у всех вкладок один и собирается из
  [SettingRows](../../../Controls/Widgets/SettingRows.cs): строка
  настройки, кнопка (`dialog auto`), выпадающий список и поле (`ControlHeightStandard`), тумблер
  без подписей, ячейка с данными (`Border.dataBox`) и строка таблицы (`RowHeightStandard` +
  `separator h`). Числа берутся оттуда, а не пишутся по месту: раздел собирается в code-behind,
  где остальные разделы описаны разметкой, и без общего набора вкладки разъезжаются — стандарт
  показанного и набранного см. [../ui/theming.md](../ui/theming.md)
- **Сочетания клавиш** (`shortcuts`,
  [SettingsShortcutsPanel.cs](../../../Views/Settings/SettingsShortcutsPanel.cs)) — все действия
  программы с их клавишами одним списком. Блок не заголовок над группой, а приставка в названии
  строки (`ShortcutActions.FullTitle` — «Таблица: Копировать значения ячеек»): список читается
  сплошняком, и строка сама говорит, где действует ее клавиша. Пояснений под названием нет —
  строка это название, сочетание и две кнопки. Список строит цикл по
  [ShortcutActions.All](../../../Core/Models/ShortcutActions.cs) — единственному месту, где
  действия перечислены: появилось действие в реестре, появилась строка в разделе, разметка о
  нем не знает. Поиск — в навбаре (`NavbarSettings.ShortcutSearchBox`, общий виджет
  `SearchInput`), отбор идет по названию строки (вместе с приставкой блока) и подписи сочетания.
  Переназначение — окно захвата
  [ShortcutCaptureDialog](../../../Controls/Dialogs/ShortcutCaptureDialog.axaml.cs); сброс —
  кнопка с круговой стрелкой, активная только пока привязка отличается от стандарта.
  Пользовательские привязки лежат в app.db ключами `shortcut.<id действия>` (значение —
  каноническая строка жеста, «Ctrl+Shift+K»), живой кэш и событие — у
  [ShortcutSettings](../../../Utils/ShortcutSettings.cs) (образец — `TaskSettings`).
  Устройство и правила конфликтов — [«Сочетания клавиш»](#сочетания-клавиш)
- **Инструкция пользователя** (`guide`) — документы `docs/user/*.md` с панелью
  «Содержание» справа, см. [[user-guide-section]]
- **Диагностика** (`logs`) — журнал `logs.db` с фильтром и панелью «Детали», см. [[logging]]
- **О программе** (`about`) — версия (из сборки), обновления, папка данных, система

Часть значений в app.db экрана настроек не имеет — их пишет сам интерфейс, запоминая
свое состояние: вид календаря (`calendarView`), режим конструктора (`constructorView`),
ширина панели записи, последний выбранный фильтр задач (`tasksLastFilter` — для режима
«последний выбранный»), а также галочки коллекций боковой панели
(`hiddenCollections.calendar` / `hiddenCollections.tasks` — хранятся СНЯТЫЕ, пустая
настройка означает «видно все»; см. [[tasks]]).

## Виды и их видимость

Модули панели навигации и виды разделов перечислены в ОДНОМ месте —
[ViewCatalog](../../../Settings/ViewCatalog.cs): по разделу (`scope`) список пар «ключ +
подпись». Оттуда их берут и навбары, и обе группы строк «Оформления». Прежде эти списки
лежали копиями в каждом навбаре, и добавление вида требовало правок в трех местах.

**Порядок пунктов значим.** Позиция в списке — глобальный номер вида, на который завязаны
`CalendarControllerView.SwitchView` и сохраненный `calendarView`. Скрытие пунктов номера НЕ
сдвигает: навбар показывает только видимые, но наружу отдает и принимает по-прежнему
глобальный номер (перевод «позиция ↔ номер» держит сам навбар). Поэтому новые виды
дописываются **в конец** — иначе у людей поменяется смысл уже сохраненных значений.

Скрытые пункты лежат в `hiddenViews.<scope>` строкой «key;key». Хранятся именно СКРЫТЫЕ, как
у галочек коллекций: пустая настройка = «видно все», и новый вид появляется у всех сам, без
дописывания в каждую установку.

**Динамический раздел — расширения.** Scope `extensions` пунктов в каталоге не перечисляет:
они берутся из `ExtensionRegistry` (ключ — Id расширения). Его строка галочек стоит не в
«Оформлении», а в разделе **«Расширения»** — там речь о составе самого раздела, а не о видах;
правило «позиция = глобальный номер вида» к нему не относится. Раз состав меняется между
запусками, для него есть уборка `AppSettings.PruneHiddenViews(scope, liveKeys)` — на старте она
выбрасывает Id расширений, которых в сборке больше нет (подробности —
[extensions/overview.md](extensions/overview.md#какие-расширения-показывать)).

Два инварианта:

- **Хотя бы один пункт остается.** В интерфейсе это держит
  [CheckListDropdown](../../../Controls/Widgets/CheckListDropdown.axaml.cs) (у последней
  галочки чекбокс выключается), а `ViewCatalog.Visible` страхует на чтении: если настройка
  почему-то прячет все, возвращается первый пункт.
- **Умолчание не указывает на скрытое.** Сняли галочку с пункта, который стоял «по
  умолчанию», — `SettingsView` переводит умолчание на первый видимый и сохраняет. На старте
  то же делает `MainWindow` для стартового раздела.

Где применяется: `ActivityBar.ApplyModuleVisibility` (кнопки разделов), `NavbarCalendar`,
`NavbarTasks`, `NavbarConstructor` (переключатели видов), `MainWindow.SyncExtensionsSidebar` +
`ExtensionsView` + `BuildExtensionsSettingsList` (состав раздела расширений). «Настройки» и
«Профиль» в каталоге навигации отсутствуют намеренно — спрятав настройки, человек не смог бы
их вернуть.

Добавить вид: дописать пункт в `ViewCatalog` (в конец списка своего раздела) и, если у вида
свое представление, обработать его у потребителя (например, в `SwitchView`). Разметку
настроек править не нужно — обе строки соберутся сами.

## Сочетания клавиш

Три слоя, как у прочих живых настроек, но со своим правилом сравнения.

**Модель** ([Core/Models](../../../Core/Models/ShortcutGesture.cs)) — чистая логика без UI,
поэтому проверяется тестами целиком:

- `ShortcutGesture` — жест как значение. Канон один на обе платформы: **«Ctrl» означает
  командный модификатор**, `Meta` (Cmd) нормализуется в `Control` и на разборе строки, и на
  сравнении с нажатием; `Display()` показывает «Cmd» только на macOS. Так формализовано то, что
  раньше вручную повторялось в восьми файлах (`mods == Control || mods == Meta`). Цифровой ряд и
  NumPad — одна клавиша, как и «+»/«−» основного ряда и NumPad. Строка хранения
  (`Canonical`) — «Ctrl+Alt+Shift+Клавиша», порядок модификаторов фиксирован, поэтому
  сравнение строк и есть сравнение жестов.
- `ShortcutActions` — реестр действий: id (`table.copy`), подпись, блок, зона конфликтов,
  стандартные жесты и признак «переназначаемое». Первый стандартный жест — основной (он
  показывается и участвует в сбросе), остальные — псевдонимы (Backspace у удалений).
  Справочные строки (стрелки, Tab, Enter, Escape) жестов не имеют — только `FixedLabel`.

**Применение** — [ShortcutSettings](../../../Utils/ShortcutSettings.cs): кэш привязок, событие
`Changed`, `Init()` на старте рядом с `TaskSettings.Init()`. Обработчики спрашивают
`Matches(id, e)` на каждое нажатие, поэтому переназначение действует сразу.
**Сравнивается целый жест** — клавиша и полный набор модификаторов. Это сохраняет прежнее
свойство таблицы «Ctrl+Shift+C принадлежит не ей», но уже без строгих `mods ==`, которые не
пережили бы пользовательское сочетание с двумя модификаторами.

**Правила:**

- **Привязка заменяет весь список стандартов.** Назначил свое — стандартные псевдонимы гаснут.
- **Дельты, как везде:** `SetGesture` с основным стандартным жестом = сброс (ключ удаляется),
  `Reset` удаляет ключ. Привязки исчезнувших действий убирает старт
  (`RemoveOrphanShortcutSettings` рядом с `RemoveOrphanExtensionSettings`), мусор и неизвестные
  id молча читаются как стандарт.
- **Конфликты считаются по зонам** (`ShortcutContext`): одинаковая зона или участие `Global`.
  Разные локальные зоны делят жест законно — Delete в таблице, календаре и боковой панели живут
  в разных фокусах. Тройка Delete-действий таблицы (ячейки / записи / колонки) разводится
  состоянием выделения и вынесена в явное исключение `AllowSameGesture`; сторожит
  `ShortcutActionsTests`.
- **Занятый жест не перехватывается**: окно захвата называет владельца и не дает сохранить —
  сначала освободи жест у него. Каскадная правка двух ключей одним кликом была бы неотменяемой.

**Где вплетено:** таблица ([TableView.axaml.cs](../../../Views/ConstructorDb/TableView.axaml.cs),
`TableView.CellSelection.cs` — только `table.selectAll`, подписи меню в
`TableView.CellClipboard.cs`), боковые панели (`SidebarTree`, `SidebarFiles`), шесть видов
календаря, `TaskListView`, `RecordPageView`, заметки
([NoteEditorBox.CommandFor](../../../Controls/Widgets/NoteEditorBox.cs) — таблица «действие →
`NoteCommand`»), глобальные — `MainWindow.InitGlobalShortcuts`. Действий, которых на клавиатуре
не было вовсе (создание и дублирование записей и коллекций, группа, масштаб), заведены новые
входы: они зовут те же методы, что пункты контекстных меню, с той же проверкой прав.

## Управление базой данных

`Initialize(registry, isMounted, queueStatus, storage, canMaintain)` дает настройкам реестр, способ узнать,
смонтирована ли БД, и статус фоновой очереди монтирования. Список
(`RefreshDatabaseList`) показывает все БД из реестра со статусом: дефолтная /
смонтирована / серым живой статус очереди («в очереди…», «Обновление · 45% · ≈ 2 мин») /
красным «недоступна (связь потеряна) с 14:05 · повтор через ≈ 1 мин» с кнопкой
«Подключить заново». Надпись у недоступной базы живая — ее фазы («переподключится сама»,
«повтор через…», «проверяю…») ставит монитор доступности через `MountQueue.UpdateFailedText`,
и текст обновляется на месте (`UpdateQueueStatus`), без пересборки списка; у вернувшейся
базы на несколько секунд серое «снова доступна» (`SetDatabaseStatus` из MainWindow). Тот же
текст в тот же момент — под именем базы в трех сайдбарах.

Добавление — кнопка «Добавить базу данных» в навбаре раздела
([NavbarSettings](../../../Controls/Components/Navbar/NavbarSettings.axaml.cs), видна только
в этом разделе, стиль — как у переключателей других навбаров) с выпадающим меню:
«Создать базу данных SQLite», «Подключить базу данных SQLite», «Подключить сервер
PostgreSQL», «Создать базу данных PostgreSQL» — вместо кнопок в ряд с неочевидной
разницей.

Операции:

- **Создать базу данных SQLite** — собственное русское окно
  [CreateDatabaseDialog](../../../Controls/Dialogs/CreateDatabaseDialog.axaml.cs) (имя + папка
  через «Обзор…») вместо системного save-диалога: тот говорит на языке ОС и предлагает
  ПЕРЕЗАПИСАТЬ существующий файл — здесь занятое имя дает ошибку «уже существует»,
  перезапись невозможна в принципе. Регистрируется и монтируется (схема создается при
  монтировании).
- **Подключить базу данных SQLite** — `OpenFilePicker` (в т.ч. из сетевой папки); уже
  подключенный файл дает уведомление «уже подключена», а не тихий no-op.
- **Подключить сервер PostgreSQL** — русское окно
  [PgConnectDialog](../../../Controls/Dialogs/PgConnectDialog.axaml.cs): сервер/порт/база/
  пользователь/пароль/SSL, кнопка «Проверить соединение» (проба с таймаутом 5 с, русские
  тексты типовых ошибок сервера — общий словарь [PgErrors](../../../Database/PgErrors.cs));
  «Подключить» прогоняет ту же пробу. Схему внутри пустой базы приложение строит само
  при монтировании. Пара сервер+порт+база уже в реестре — уведомление «уже подключена».
  Введенный пароль хранится защищенно ([SecretProtector](../../../Utils/SecretProtector.cs):
  macOS — Связка ключей, Windows — DPAPI; отключение базы удаляет секрет). В строке
  списка у серверных БД бейдж «PostgreSQL», вторая строка — `postgres://host:port/db`
  (без пароля). Ссылка «Нет сервера? Установка…»
  открывает помощник [PgServerHelpDialog](../../../Controls/Dialogs/PgServerHelpDialog.axaml.cs).
  Пошаговая настройка сервера — [../guides/postgresql-setup.md](../guides/postgresql-setup.md);
  внутреннее устройство —
  [../architecture/database/storage-and-migrations.md](../architecture/database/storage-and-migrations.md),
  раздел «Провайдеры».
- **Создать базу данных PostgreSQL** — приложение теперь умеет создавать базу на
  сервере само: окно
  [PgCreateDatabaseDialog](../../../Controls/Dialogs/PgCreateDatabaseDialog.axaml.cs)
  подключается администратором к служебной базе `postgres`, создает роль-владельца и
  базу ([PgDatabaseCreator](../../../Database/PgDatabaseCreator.cs); `OWNER` — из-за
  правил схемы `public` в PostgreSQL 15+), делает контрольную пробу новой ролью
  (существовавшая роль с другим паролем не пройдет — нерабочая связка в реестр не
  попадает), регистрирует базу и показывает «Данные подключения». Администратору
  остается только поставить сам сервер.
- **Отключить** (корзинка) — с подтверждением ([ConfirmDialog](../../../Controls/Dialogs/ConfirmDialog.axaml.cs)); **файл на диске не удаляется** (у PostgreSQL — данные на сервере), дефолтную отключить нельзя.
- **Переподключить** недоступную БД.
- **Сведения о файле** — у смонтированной SQLite-базы третья строка «файл 1,7 ГБ · свободно
  1,1 ГБ (64 %)» (`DatabaseRow.StorageText`; данные — `DatabaseManager.Storage`, снимаются при
  монтировании и приходят через `storage` в `Initialize`). Выше порога
  `DatabaseManager.NeedsCompaction` — красная с пометкой «— стоит сжать».

В строке списка из действий остались только шестеренка и корзинка; остальное живет в окне
**«Настройки базы данных»** ([DbSettingsDialog](../../../Controls/Dialogs/DbSettingsDialog.axaml.cs),
`OnDbSettingsClick`):

- **Название в списке** — переименование любой базы (включая дефолтную):
  `DatabaseRegistry.Rename` + событие `DatabaseRenamed` → MainWindow меняет `Name`
  смонтированного `DatabaseManager` на месте и зовет `SyncMountedToUi()` — сайдбары
  обновляются без ремаунта.
- **Сжать файл** — только у администратора базы (`canMaintain`), не у дефолтной и только когда
  строка красная: колбэк окна → `DatabaseCompactRequested` → MainWindow отцепляет базу и
  запускает `MountQueue.RunMaintenance` (состояние `Maintenance`: «сжимаю файл · 45 % · ≈ 2 мин»
  здесь и под именем базы в сайдбарах), по завершении база встает в очередь обратно; итог —
  карточка «Файл базы «X» сжат: A → B» или ошибка (занятый файл — «попробуйте позже»).
- **Резервная копия** здесь больше не живет: кнопка переехала в раздел
  **«Резервное копирование»** (см. [[backup]]) — там же расписания автокопий; прежней
  модалки с выбором файла нет, копии складываются в настроенную папку раздела.
- **PostgreSQL**: живой статус сервера (TCP-проба `PgServerProbe` при открытии окна) со
  ссылкой на помощник установки/автозапуска (передает адрес и порт этой базы), кнопка
  «Данные подключения» ([PgDetailsDialog](../../../Controls/Dialogs/PgDetailsDialog.axaml.cs) —
  сводка для коллеги без пароля) и **смена сохраненного пароля** — проба новым паролем до
  записи, затем `DatabaseRegistry.UpdatePgPassword` (старый секрет удаляется из хранилища
  ОС); несмонтированной базе тут же шлется `DatabaseReconnectRequested`.

Изменения реестра уходят наверх событиями `DatabaseAdded` / `DatabaseRemoved` /
`DatabaseReconnectRequested` / `DatabaseRenamed` /
`DatabaseCompactRequested`; MainWindow ставит базу в фоновую очередь
[MountQueue](../../../Database/MountQueue.cs) (в хвост — даже если сейчас мигрирует
другая), размонтирует в [Workspace](../../../Database/Workspace.cs) и обновляет сайдбар.
Модального окна нет: прогресс виден в статусе строки списка и в заглушке узла
сайдбара, по готовности база оживает сама. Подробнее —
[../architecture/multi-database.md](../architecture/database/multi-database.md).
