# Расширение «Переименование PDF»

Часть [обзора расширений](overview.md): устройство одного расширения. Общий механизм
(контракт, реестр, настройки, видимость) — там же.

## Назначение

Пакетно переименовывает PDF-файлы в выбранной папке по правилу **«все до первого пробела
+ `.pdf`»** — например, `Отчет 2024 итог.pdf` → `Отчет.pdf`.

Самое простое из расширений и потому **образец структуры**: контракт, логика без UI и окно —
три файла, ни одной зависимости кроме `IExtension` и контролов приложения. Новое расширение
проще всего начинать с копии этой папки.

## Как работает

### План и прогон

Работа разбита надвое: `BuildPlan` строит план без единого изменения на диске, `Process`
применяет уже готовый план (`IProgress`/`CancellationToken`). Отсюда и две кнопки в окне:
«Проверить» показывает план, «Запустить» его применяет — с подтверждением через
[ConfirmDialog](../../../../Controls/Dialogs/ConfirmDialog.axaml.cs) и с возможностью остановить.

План учитывает две причины конфликта — занятое имя на диске и внутрипакетное совпадение
(несколько файлов дают одно имя). Конфликтные файлы **пропускаются**, а не перезаписываются:
переименование не должно терять документы. Файлы только переименовываются, не удаляются.

Папку выбирает `StorageProvider`, прогон идет в фоне (`Task.Run`).

### Масштаб (тысячи файлов)

План строится один раз и в фоне; UI не обновляется на каждый файл. Прогресс и журнал идут
**с троттлингом** (~20 раз в секунду), журнал копится в `StringBuilder` и рендерится пачкой,
а на реальном прогоне в него пишутся **только конфликты и ошибки** — успехи уходят в счетчик
и полосу. Число строк журнала ограничено.

Поэтому окно остается отзывчивым на десятках тысяч файлов, а узким местом остается диск или
сеть, а не отрисовка.
