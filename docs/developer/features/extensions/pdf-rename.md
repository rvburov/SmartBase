# Расширение «Переименование PDF»

Часть [обзора расширений](overview.md): устройство одного расширения. Общий механизм
(контракт, реестр, настройки, видимость, плагины) — там же.

## Назначение

Пакетно переименовывает сканы конструкторской документации **по содержимому**: на листе
находятся десятичное обозначение и наименование изделия, исходный PDF получает имя
`Обозначение Наименование.pdf` **в той же папке** — без копий, без изменения содержимого.
Сомнительные файлы пропускаются, причина остается в журнале.

Второй режим — прежний: имя «все до первого пробела + `.pdf`», без OCR.

## Расширение — отдельный плагин

Это первое расширение-**плагин**: его сборка, OCR, OpenCV, PDFium и модели лежат в собственной
папке вне программы и ставятся отдельно (механизм — [overview.md, «Плагины»](overview.md#плагины)).

| Что | Где |
|-----|-----|
| Проект | [Extensions/PdfRename/SmartBase.Extensions.PdfRename.csproj](../../../../Extensions/PdfRename/SmartBase.Extensions.PdfRename.csproj) — собирается отдельно, в программу не входит |
| Манифест | [extension.json](../../../../Extensions/PdfRename/extension.json) — Id, сборка, версия контракта, платформа (подставляется при сборке) |
| Архив для установки | `Scripts/extension-pack.sh pdf-rename linux-x64` или `win-x64` → `artifacts/extensions/pdf-rename-<версия>-<платформа>.zip` |
| Установлен | Release: `%LOCALAPPDATA%/SmartBase/extensions/pdf-rename` (Windows), `~/.local/share/SmartBase/extensions/pdf-rename` (Linux); Debug: `.localdata/extensions/pdf-rename` |
| Отладка | `dotnet build Extensions/PdfRename -p:DeployPlugin=true` кладет сборку в `.localdata/extensions/pdf-rename`, `dotnet run` программы ее подхватит |

Содержимое папки плагина (Linux, ≈520 МБ, архив ≈200 МБ; Windows меньше):

```
pdf-rename/
├── extension.json, SmartBase.Extensions.PdfRename.dll (+ .deps.json)
├── OpenCvSharp.dll, Sdcb.PaddleOCR.dll, Sdcb.PaddleInference.dll, YamlDotNet.dll, Docnet.Core.dll
├── runtimes/<платформа>/native/   OpenCV, Paddle Inference (OpenBLAS), PDFium
└── ocr/
    ├── paddle/mobile_zh_det/, eslav_PP_OCRv5_mobile_rec/   модели PaddleOCR v5 (≈13 МБ)
    ├── tessdata/rus.traineddata, eng.traineddata            языки Tesseract (tessdata_fast 4.1.0)
    └── tesseract/tesseract55.dll, leptonica-1.85.0.dll      только Windows
```

Программа об OCR ничего не знает: в `SmartBase.dll` нет ни одного типа расширения (проверяет
тест `Extension_is_not_built_into_the_program`), в поставке программы нет ни OpenCV, ни Paddle.
Удаление расширения (**Настройки → Расширения → Удалить**) удаляет только папку плагина при
следующем запуске: программа, другие расширения, документы и шаблоны не затрагиваются.

## Как работает

### Шаблоны и цветные рамки

Шаблон — PDF в папке шаблонов; **имя файла — тип документа**. Читается заново при каждом
запуске (кэша нет — измененная разметка учитывается сразу). Размеченная страница — первая
страница с цветными рамками (рамки на нескольких страницах — ошибка шаблона).

Страница рисуется с длинной стороной 3000 точек (тонкая линия рамки не теряется), цвет
определяется по тону HSV, а не по точному RGB:

| Цвет | Тон OpenCV (0..180) | Роль |
|------|---------------------|------|
| синий | 95..130 | обозначение |
| зеленый | 40..85 | наименование |
| красно-оранжевый | 0..22 и 165..180 | обозначение и наименование вместе |

Цветная точка — насыщенность ≥ 80 и яркость ≥ 70: серый скан, желтизна бумаги и черный текст
(S < 60 даже с цветной каймой JPEG) в маску не попадают. Тона в промежутках (желтый,
бирюзовый, фиолетовый) — «непонятный цвет», роль не назначается. Рамка — контур, у которого
все четыре стороны прямоугольника закрыты линией не меньше чем на 85%, а внутри почти нет
цвета; цвет рамки — преобладающий (≥ 80% точек). Подписи синей ручкой и круглые печати под это
не подходят и игнорируются.

Шаблон отклоняется с причиной, если: рамок нет; синяя без зеленой (и наоборот); рамок одного
цвета несколько; красно-оранжевая вместе с синей/зеленой; рамки перекрываются; рамка
закрашена; рамка проходит по тексту (по обе стороны линии в одном месте есть штрихи, не
являющиеся линиями таблицы); цвет непонятен или смешан. Неисправный шаблон не мешает
остальным.

Из шаблона сохраняются: имя типа, размер страницы в пунктах (с учетом /Rotate), внутренние
прямоугольники рамок **в долях страницы** и признаки для сопоставления — серая картинка без
цвета и без содержимого полей (длинная сторона 1600), маска линий и 5000 ключевых точек ORB.

### Подбор шаблона и совмещение

1. **Формат**: отношение сторон страницы совпадает с шаблоном (с поворотом на 90° или без) с
   допуском 8%. Физический размер из PDF — только подсказка: у сканов он бывает записан
   неверно; если у части кандидатов он совпал (±12%), выбор идет среди них.
2. **Совмещение**: точки ORB страницы сопоставляются с точками шаблона (тест Лоу 0,8), RANSAC
   (`estimateAffinePartial2D`) находит поворот на любой угол, масштаб и сдвиг. Принимается
   наклон до ±10° от кратного 90°, масштаб 0,7..1,45 от ожидаемого, не меньше 20 совпавших точек.
3. **Проверка формы**: страница переносится в координаты шаблона, ее линии (рамка листа, графы
   основной надписи, таблицы) должны лечь на линии шаблона: F-мера с допуском 3 точки по всей
   странице ≥ 0,5 и рядом с полями ≥ 0,75. Оценка — (общая + 2 × местная) / 3.
4. **Выбор**: лучший из прошедших; если второй отстает меньше чем на 0,08 — неоднозначно,
   пропуск («подходят несколько шаблонов одинаково»). Ни одного — «подходящий шаблон не найден»
   (с ближайшим кандидатом и его оценкой).

Один размер листа тип не определяет: чертеж и спецификация A4 различаются формой основной
надписи и таблицы (замер: верный шаблон 0,86–1,0, чужой того же формата 0,57–0,61).

### Многостраничные PDF

Просматриваются страницы по порядку, не больше 10. Страница, не подошедшая ни к одному шаблону,
пропускается (обложка, листы продолжения, приложения). Каждая подошедшая страница распознается;
все должны дать **одни и те же** обозначение и наименование. Если хоть одна подошедшая страница
неоднозначна, не подтвердила поля или дает другие данные — пропуск всего файла (в PDF может быть
несколько документов). Нужные поля не обязаны быть на первой странице.

### Вырезание полей

Прямоугольник поля переводится в координаты страницы обратным преобразованием совмещения
(с запасом 1 мм), этот фрагмент **рисуется PDFium заново в 300 dpi** — не вырезается из
уменьшенной картинки и не требует отрисовки всего листа (A1 в 300 dpi — сотни мегабайт) —
и поворачивается так, как стоит в шаблоне. Подготовка к OCR: оттенки серого, выравнивание
фона (деление на максимум в окне 31×31), линии граф длиннее 7 мм — в белый, белые поля 24 точки.

### Два движка

| Движок | Как подключен | Модели / данные |
|--------|---------------|-----------------|
| Tesseract 5 (LSTM) | собственный P/Invoke к C API (`Ocr/TesseractApi.cs`); Windows — `tesseract55.dll` в папке плагина, Linux — системная `libtesseract.so.5`, macOS — Homebrew | `rus+eng`, режим одного блока (PSM 6), строки с уверенностью и рамками |
| PaddleOCR v5 | Sdcb.PaddleOCR 3.3.1 на Paddle Inference (CPU, OpenBLAS, один поток вычислений на движок) | детектор `mobile_zh_det`, распознавание `eslav_PP_OCRv5_mobile_rec` (русский, латиница, цифры) |

`OcrComponents.CheckReady` перед прогоном **создает** оба движка (а не только ищет файлы);
не поднялся хоть один — прогон не начинается, причина в журнале. Работать одним движком
расширение не умеет намеренно.

### Правила текста

- **Нормализация**: тире всех видов → `-`, типографские кавычки → прямые, «е с точками» → `е`, пробелы
  схлопнуты, без пробелов вокруг дефиса, мусор от линий таблиц (`| _ ~`) по краям убран.
  Строки соединяются пробелом; строка, оканчивающаяся дефисом, — без пробела, дефис сохраняется.
- **Буквы-двойники** (латинская «A» и кириллическая «А»): заменяются только по правилу —
  в слове с однозначно кириллическими буквами (Б, Г, Ц…) латинские двойники кириллические (и
  наоборот); код организации в обозначении ГОСТ — кириллица. Слово из одних двойников («ТКС» /
  «TKC») не меняется — решает сверка. **Латинская «B» — не однозначный двойник**: на скане ей
  соответствуют и «В», и «Б» (на проверочных сканах оба движка читали «Б» как «B»). Она не
  меняется никогда; «В» становится, только если второй движок прочитал на этом месте именно «В».
  Буквы и цифры (О/0, З/3) не заменяются никогда.

### Обозначение

`Recognition/Designations.cs`, формат не ограничен одним примером:

| Правило | Пример |
|---------|--------|
| ЕСКД (ГОСТ 2.201) | `АБВГ.461411.123`, `-01`, `-01.02`, код документа `СБ`, `Э3`, `ПЭ3`, `Д1`…, `-ЛУ` |
| ЕСПД (ГОСТ 19.103) | `АБВГ.12345-01 34 01`, `АБВГ.12345-01` |
| технологические | `АБВГ.12345.12345` |
| отраслевые «через точки» | `ВЛ2.700.004-01`, `8А1.234.567`, `8.112.006` (средняя группа ≥ 3 цифр — дата не проходит) |

Каноническая запись: прописные, без пробелов у точек и внутри групп цифр между точками (Tesseract
ставит их по ширине цифр), тире → дефис, код документа, отделенный пробелом, присоединяется.
Код документа — только известный (неизвестная буква после номера — «…123З» — не обозначение).
Строка вида ГОСТ с некириллическим кодом организации не принимается и «отраслевым» правилом.

### Разбор полей и сверка

- **Синяя** область: ровно одно обозначение и ничего, кроме него.
- **Зеленая**: весь текст — наименование: есть буквы, не больше 5 строк (иначе похоже на
  таблицу), не длиннее 180 символов, нет обозначения внутри.
- **Красно-оранжевая**: ровно одно обозначение; наименование — текст по одну сторону от него
  (строки выше или ниже, или остаток строки). Текст и до, и после — разделение неоднозначно.
- **Сверка** (`EngineAgreement`): поле принимается, только если оба движка его прочитали, оно
  прошло проверки и значения совпали символ в символ (с единственным допущением «B»/«В», см.
  выше). Любое другое расхождение — пропуск с обоими прочтениями в журнале (по 60 символов).
  «Более уверенный» ответ не выбирается: шкалы уверенности несравнимы.
- **Пороги уверенности** — у каждого движка свой, подобраны на синтетических сканах: Tesseract ≥ 0,30
  (на верно прочитанных строках он сам давал 0,37–0,38), PaddleOCR ≥ 0,5. Это фильтр мусора;
  главный критерий — совпадение двух движков.

### Имя файла и переименование

`Rename/FileNames.cs`: `Обозначение Наименование.pdf`; прямые двойные кавычки → одинарные;
`< > : / \ | ? *` и управляющие символы — пропуск (заменять — значило бы менять наименование);
не длиннее 255 символов и 255 байт UTF-8; зарезервированные имена Windows запрещены. Правила
одинаковы на всех ОС (по самой строгой — Windows).

`Rename/OcrRenameRun.cs`: распознавание в нескольких потоках (половина ядер, 1..4; у каждого своя
пара движков), очередь между шагами ограничена — в памяти лишь несколько документов.
**Переименование — в одном потоке**, и конфликт проверяется прямо перед ним: файл на месте и не
изменился (размер и время записи), целевое имя свободно (иначе пропуск «имя занято», никаких
суффиксов), на Windows путь короче 260 символов. `File.Move` без перезаписи — одна атомарная
операция. Текущее имя совпадает с итоговым — «Имя уже соответствует результату», без операции.
Регистр на Windows и macOS сравнивается без учета (там так устроены файловые системы).

Папка шаблонов и файлы-шаблоны исключаются из обработки, даже если лежат внутри исходного
дерева. «Стоп»: новые файлы не берутся, документы в работе дочитываются и **не**
переименовываются, сделанное остается.

### Окно и журнал

Порядок: режим, папка шаблонов (с подсказкой по цветам), папка с PDF, «Искать в подпапках»,
статус со счетчиками (найдено, обработано, переименовано, пропущено, уже с верным именем),
индикатор, «Запустить» / «Стоп», журнал. Перед запуском — одно подтверждение. Журнал — список с
виртуализацией (полный результат на тысячи файлов листается без задержек), строки копируются
Ctrl+C, весь журнал сохраняется в `.txt`. Фоновые потоки пишут в очередь, окно забирает ее
пачкой раз в 200 мс. В журнале — путь от исходной папки (одинаковые имена в подпапках
различимы), новое имя или причина; содержимое документов и картинки не выводятся.

Последние папки, режим и флажок запоминаются (`ext.pdf-rename.*`).

## Проверено и замерено

- **Тесты** (179, ≈1 мин 15 с на Linux, ≈1,5 мин на Windows): рамки и оттенки, роли по цвету, ошибки разметки,
  нормализованные координаты; повороты 90/180/270, наклон до 4°, масштаб 0,9–1,06, сдвиг;
  выбор среди шаблонов одного формата, неоднозначность, нет шаблона; входные документы без рамок;
  настоящие Tesseract и PaddleOCR на синтетических сканах, отдельные и общая области, многостраничные,
  поврежденные и пустые PDF; правила текста и сверки; занятые и совпадающие имена, подпапки,
  исключение шаблонов, неизменность байтов PDF, изменение и исчезновение файла во время работы,
  остановка; пакет из 8000 файлов (с подменным распознаванием: очередь, журнал, память — **не**
  качество OCR); установка, загрузка в свой контекст и удаление плагина.
- **Замер движков** на 40 синтетических сканах (шрифт DejaVu Sans, 150–300 dpi, повороты, шум,
  JPEG): PaddleOCR верно прочитал 28–33 обозначения из 40 и 38 наименований из 40; типичные
  ошибки — «Б»→«В»/«B», «З»→«3», «Щ»→«Ц». Tesseract — 21 обозначение из 24 и все наименования.
  Такие файлы **пропускаются** сверкой; неверного имени тесты не допускают.
- **Скорость**: 1,3–2,8 с на одностраничный документ в одном потоке (Linux, x64), прогон идет в
  нескольких потоках. На 8000 реальных сканах не замерялось.

## Ограничения и что нужно для проверки точности

- Точность на **реальных** сканах не подтверждена: нужны разрешенные образцы — по 20–50 сканов
  каждого вида бланка (чертежи A4/A3/A1, спецификации первый и последующие листы, текстовые
  документы), с типичными дефектами (наклон, серый фон, печати, подписи) и с известными
  правильными обозначением и наименованием; плюс шаблоны с рамками, размеченные пользователем.
- PaddleOCR (модель eslav mobile) путает «Б»/«В», «З»/«3», «Щ»/«Ц» — такие документы будут
  пропускаться чаще. Совпадающая ошибка обоих движков возможна (так у любой пары OCR); латинская
  «B» на месте «Б» — разобранный случай, он отсекается.
- **Платформы**:
  - Linux x64 — все 179 тестов (локально и в CI); архив `linux-x64` собран, распакованная папка
    проверена отдельным процессом; программа, опубликованная одним файлом, загружает плагин и
    поднимает оба движка; окно и блок настроек проверены в headless-режиме Avalonia.
  - Windows x64 — все 179 тестов в CI (windows-latest), с Tesseract 5.5 из папки плагина и
    PaddleOCR; нужен Microsoft Visual C++ 2015–2022 x64 (на раннере есть). Архив `win-x64` и
    установка через окно настроек на живой машине Windows не проверялись.
  - macOS (Apple Silicon и Intel) — OCR-часть не поставляется (нет готовых библиотек OpenCV для
    поставки): тесты обработки картинок и OCR там пропускаются с этой причиной, остальные тесты
    плагина (правила текста, прогон, манифест) проходят в CI.
- Два плагина, каждый со своей копией Paddle Inference, в одном процессе несовместимы (вторая
  копия нативной библиотеки роняет процесс). Следующему расширению с PaddleOCR нужно будет общее
  размещение OCR-библиотек.
- Загруженная сборка плагина не выгружается: установка, обновление и удаление вступают в силу
  после перезапуска программы.
