# Расширение «Водяной знак на PDF»

Часть [обзора расширений](overview.md): устройство одного расширения. Общий механизм
(контракт, реестр, настройки, видимость) — там же.

## Назначение

Накладывает на каждую страницу PDF многострочный диагональный знак. Есть два
независимых выбора: режим текста и размещение. Свободный текст работает без базы данных;
учтенная выдача использует существующий журнал, подбирает номер экземпляра и записывает выдачу.
Размещение — один блок по центру либо повторяющиеся блоки диагональными рядами по всей странице.
Окно открывается в режиме «Свободный текст» с повторением блоков до самых краев листа.

Подходит текстовым PDF, сканам и чертежам. Страница и надпись объединяются в одно изображение,
поэтому знак не остается отдельным объектом PDF.

## Как работает

### Два режима текста

`StampMode.Journal` сохраняет существующий способ выдачи. Текст знака составляется из
фактических данных текущего документа:

```text
КОПИЯ
Экземпляр № 3
Выдан: Иванов Иван Иванович
Дата выдачи: 09.11.2026
Передача третьим лицам запрещена
```

Последняя строка может переноситься внутри блока. В окне подпись получателя — **«Выдан»**.
Название столбца существующего журнала остается **«Кому выдан»**: переименовывать данные не нужно.
Номер экземпляра выбирается автоматически перед записью выдачи.

`StampMode.FreeText` использует многострочный ввод пользователя. В знак не подставляются
«КОПИЯ», номер, получатель, дата или предупреждение учтенной выдачи. Пример:

```text
Для внутреннего использования
Отдел разработки
Передача третьим лицам запрещена
```

Для этого режима не требуются открытая база, приемник журнала и его структура. Ветка движка не
создает `AppDbContext`, не читает `NumberLedger`, не резервирует номер и не записывает строки.
Текст находится в памяти текущего окна и в выходном PDF; в настройки, таблицы и журналы он не
попадает. Нельзя передать его через сохранение предупреждения учтенного режима.

### Окно и настройки

Начальный режим — «Свободный текст», начальное размещение — «Блоками по всей странице».
Списки баз и коллекций журнала загружаются при выборе режима «С записью в таблицу».
Открытие свободного режима не требует приемника журнала.

Источник выбирается двумя кнопками — **«Файл…»** и **«Папка…»**. Рядом с выбором источника
показан текст: **«Для смены надписи выбирайте исходный PDF без водяного знака.»** Рекурсивный
поиск доступен для папки. Папка результата обязательна в обоих режимах; рекомендуется отдельная
папка. При обходе исходной папки вложенная папка результата и ее подпапки исключаются из поиска.
Если источник и результат совпадают, файлы этой папки участвуют в обработке. Явно выбранный PDF
обрабатывается независимо от папки. В свободном режиме виден многострочный ввод, в учтенном —
получатель, дата, предупреждение, база и коллекция выдачи. Пустой свободный текст блокирует
запуск. Прогресс, кнопка остановки и журнал выполнения общие.

`StampRequest` переносит в фон только значения. Запрос фиксирует выбранный режим, его текст и
размещение до первого `await`; дальнейшее переключение контролов не меняет
текущий запуск. Параметры режима и размещения добавлены так, чтобы прежние вызовы выдачи
продолжали работать. Поля приемника журнала используются только в учтенном режиме.

Сохраненные настройки остаются прежними:

| Ключ | Когда записывается |
|---|---|
| `warning` | при запуске учтенной выдачи; пустое значение означает предупреждение по умолчанию |
| `output` | при выборе папки результата |
| `database` | когда выбрана подходящая коллекция журнала |
| `collection` | когда проверена структура журнала |

Получатель и свободный текст настройками не являются. Изменение свободного текста не должно
вызывать запись другого поля с отложенным `TextBox.TextChanged`.

### Диагональный блок

Все строки составляют один блок, выровненный по центру. Узкий полужирный шрифт PT Sans Narrow
Bold имеет основной размер 30 pt; заголовок «КОПИЯ» увеличен в 1,35 раза, до 40,5 pt. Длинные
строки переносятся внутри заданной ширины. Весь блок, включая номер, получателя, дату и
предупреждение, поворачивается целиком на постоянный угол −35°: снизу слева вверх направо,
под 35° к горизонтали. Наклон одинаков для портретных и альбомных листов.

`StampLayout` задает размещение, ширину и высоту блока до поворота, промежутки между
столбцами и рядами блоков и отступ от края страницы. Размеры выражены в миллиметрах; для
рисования они переводятся в пиксели выбранного растра. Физический размер надписи не зависит
от dpi. Начальные значения — область переноса текста 130 × 115 мм, промежутки 6 × 7 мм и
отступ 0 мм. Окно по умолчанию выбирает повторение блоков; значение размещения по умолчанию
в API `StampLayout` остается `Center` для прежних вызовов.

Границы блока ограничивают разметку текста. Если после переносов надпись не помещается при
30 pt, кегль подбирается в пределах 10–30 pt; заголовок сохраняет множитель 1,35. Если и
минимальный размер не помещается, обработка сообщает об этом и предлагает увеличить область
блока или сократить текст. Текст внутри области разметки молча не обрезается.

- `StampPlacement.Center` — один диагональный блок по центру каждой страницы. На небольшом
  листе область блока вписывается в доступное место с учетом отступа.
- `StampPlacement.Tiled` — повторение всего блока диагональными рядами по всему листу.
  Сетка продолжается за его пределами, поэтому части крайних блоков могут быть обрезаны
  границей страницы или заданных полей. Отбрасывания всех частично выходящих блоков нет:
  заполнение доходит до краев. При отступе 0 мм чистые поля специально не оставляются.

Шаг сетки определяется фактической максимальной шириной строки и фактической высотой
составленного текста с добавлением `GapXmm` и `GapYmm`. Размеры области переноса не создают
лишних пустот вокруг короткой надписи. Промежутки сохраняют управление плотностью заполнения
из окна. Сами ряды повернуты вместе с текстом, а не расположены в горизонтальной сетке.

Страницы разного размера и ориентации размечаются отдельно. PDFium уже учитывает `/Rotate`
при растеризации; повторно доворачивать исходное содержимое не нужно.

### Впечатывание в пиксели

PDFium через Docnet.Core растеризует страницу. Skia рисует знак прямо на ее пикселях; PDFsharp
собирает новый PDF с готовым изображением каждой страницы. Удалить знак отдельным текстовым
объектом или слоем невозможно. Свободный и учтенный режимы используют один путь нанесения.

Буквы имеют единственную сплошную светлую серо-голубую полупрозрачную заливку, без обводки.
Значения по умолчанию — RGB `(80, 120, 155)` и непрозрачность `60/255`: на белом фоне получается
примерно RGB `(214, 223, 231)` (`#D6DFE7`). Межстрочный шаг задается множителем `1.12`.
Заливка использует умножение цветов (`Multiply`), поэтому черные буквы и линии исходного
документа остаются черными.

При повторной обработке выходного PDF прежний знак уже входит в пиксели источника и остается
под новой надписью. Расширение не распознает и не заменяет ранее нанесенные знаки. Для смены
надписи нужен исходный PDF без водяного знака.

Ручная ретушь пикселей возможна. Запись в журнале отражает факт выдачи, но сама по себе не
восстанавливает стертый знак и не определяет происхождение очищенной копии.

Растеризация сохраняет размеры листа для печати. PDFium возвращает незакрашенные места
прозрачными, поэтому до JPEG применяется `NaiveTransparencyRemover(255, 255, 255)`; иначе
обычная текстовая страница могла бы получить черный фон.

`PageRaster` выбирает минимальное из трех ограничений:

| Ограничение | Значение |
|---|---|
| целевое разрешение | 200 dpi |
| родное разрешение скана | ширина изображения / физическая ширина листа |
| предел памяти | 5000 пикселей по длинной стороне |

Родное разрешение учитывается для изображений шириной от `NativeFloorPx` (1000 пикселей), чтобы
не принять маленький логотип за скан страницы. Качество JPEG задает `PageRaster.JpegQuality`.
Все вызовы PDFium, включая освобождение страниц и документа, проходят через общую `PdfGate`.

Шрифт PT Sans Narrow Bold встроен в сборку с полной кириллицей. Системный шрифт не требуется,
поэтому начертание одинаково на поддерживаемых ОС. Ресурс `ptsansnarrow-bold.ttf.gz` содержит
очертания, `ptsans-OFL.txt.gz` — полный текст лицензии OFL. В результат шрифт отдельным объектом
не встраивается: там уже пиксели страницы.

### Журнал выдачи и номера

Проверка `JournalSchema` действует в учтенном режиме. Требуются ровно четыре столбца в порядке
показа:

| № | Столбец | Тип | Значение |
|---|---|---|---|
| 1 | Документ | системный столбец записи | имя PDF без расширения |
| 2 | Экземпляр | Число | номер экземпляра |
| 3 | Кому выдан | Текст | значение поля «Выдан» |
| 4 | Дата выдачи | Дата | дата без времени |

Тумблер календаря у даты должен быть выключен. Имена сравниваются без учета регистра и крайних
пробелов, порядок и типы обязательны. Не прошедшая проверку коллекция не сохраняется как
приемник в настройках.

Номер уникален в пределах документа — имени файла без расширения. Выбирается первый свободный
номер; у разных документов независимая нумерация. `NumberLedger` читает снимок нужных записей
пакетом и обновляется при обнаружении сторонних изменений. Перед резервом проверяется
актуальность; параллельные выдачи не должны получать одинаковый номер.

Последовательность учтенной выдачи:

1. **Предполет:** PDF открывается до любой записи в журнал. Поврежденный или защищенный файл
   пропускается, строка выдачи не создается.
2. **Резерв:** подбирается номер и записываются данные выдачи.
3. **Знак:** готовится PDF по уникальному пути.
4. **Сбой или отмена:** незавершенный результат удаляется, резерв снимается. Если снять его не
   удалось, номер остается занятым и это явно указано в отчете.

Резерв предшествует знаку, чтобы не выдать файл с номером, отсутствующим в журнале. Готовый
файл и его строка при остановке последующих файлов сохраняются. Переименование документа в
журнале меняет ключ нумерации и может освободить ранее выданный номер; это ограничение описано
пользователю.

### Результат и отказы

Свободный режим создает `<имя> водяной знак.pdf`, учтенный — `<имя> экз. N.pdf`. Имя занято —
добавляется счетчик. Путь исходника всегда считается занятым, исходные файлы не переписываются.
Ни число страниц, ни число повторенных блоков не увеличивает число строк выдачи.

В свободном режиме готовый PDF сначала сохраняется под уникальным временным именем в папке
результата. Выбранное имя резервируется через `FileMode.CreateNew`, и PDF копируется в открытый
эксклюзивный файл. `File.Move(false)` не используется: на Unix между проверкой наличия и rename
возможна перезапись результата другого запуска. Коллизия повторяет выбор имени, а не нанесение
знака. При сбое или отмене убираются временный файл и созданный этим запуском частичный результат.

Единица отказа — файл. Защищенные и поврежденные PDF пропускаются, ошибка сохранения отражается
в отчете, следующие файлы продолжают обрабатываться. Недоступный источник, неверные параметры,
отсутствующая папка результата и ошибка встроенного шрифта останавливают запуск. В учтенном
режиме дополнительно обязательны подходящий журнал и права записи.

## Взаимодействия и ограничения

- UI проверяет права `CreateRecord` и `EditRecord` на коллекцию учтенной выдачи. Фоновый движок
  использует собственный контекст; общий `AppDbContext` UI-потока в `Task.Run` не передается.
- Режим свободного текста работает без базы и не выполняет проверки прав на журнал.
- В общий журнал приложения расширение не пишет. Журнал окна сообщает о файлах и сбоях,
  не выводя свободный текст.
- У выходной копии отсутствует текстовый слой. Поиск и выделение требуют OCR; закладки и ссылки
  пропадают, векторные чертежи становятся изображениями.
- Электронная подпись исходного PDF теряет силу, PDF/A может потерять соответствие.
- Растеризация и водяной знак не исключают ручную ретушь, печать и пересъемку экрана.

## Проверка

Тесты расширения используют созданные на стенде PDF и временные базы. Проверяются строки
учтенного знака, номера экземпляров, отсутствие обращения к базе в свободном режиме, сохранность
исходников и поведение при ошибках и отмене. Геометрия и отрисовка проверяются по расположению
блоков и пикселям готового PDF: проверяются постоянный наклон, заполнение у всех четырех
краев листа, заданные поля, сплошная светлая серо-голубая заливка и сохранение черных линий
исходного документа. Отдельный UI-стенд использует Avalonia.Headless и проверяет также
изоляцию параметров запуска при переключении режимов.

Тесты логики и PDF запускаются обычным набором расширения:

```bash
dotnet test Tests/Extensions/PdfWatermark
```

Дополнительный UI-гейт запускается отдельно от набора xUnit:

```bash
dotnet run --project Tests/Extensions/PdfWatermark/Ui
```

Для сохранения снимков окна передайте `-- --out /tmp/pdf-watermark-ui`. Стенд проверяет
настоящие контролы: переключение режимов, свободный ввод без базы, отсутствие сохраненного
текста, проверку размеров, запуск создания PDF и доступность действий при разных размерах
окна. Он использует временные файлы и не открывает документы пользователя.

Проверка на стенде не заменяет проверку на документах пользователя: отдельно оцениваются
читаемость исходного мелкого текста, плотность повторения и качество печати выходного PDF.
