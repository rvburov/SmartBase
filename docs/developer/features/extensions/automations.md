# Расширение «Автоматизации»

Часть [обзора расширений](overview.md): устройство одного расширения. Общий механизм
(контракт, реестр, настройки, видимость) — там же.

## Назначение

Хозяин над маленькими автоматизациями сценариев обмена — шаг 13
[плана интеграций](../../../ROADMAP-API.md). От остальных расширений отличается двумя вещами:
**окна у него нет вовсе** (все, что оно умеет, ставится шагом сценария) и **внутри у него не
одна функция, а список** — каждая автоматизация это отдельный класс, который сам появляется в
списке шагов.

Это ответ на вопрос «а можно писать скрипты для автоматизаций?». Нельзя и не будет: песочницы в
.NET нет, и скрипту в окне нельзя запретить открыть сокет мимо шлюза — один такой шаг обнулил бы
весь контур безопасности (раздел 13 плана). Расширение дает тот же C# под анализатором
запрещенных вызовов — с типами, отладкой и историей в репозитории, — а церемония написания
срезана до одного файла.

## Где в коде

Папка [Extensions/Automations/](../../../../Extensions/Automations/):

- [IAutomation.cs](../../../../Extensions/Automations/IAutomation.cs) — контракт автоматизации,
  строка (`AutomationRow`), вход (`AutomationInput`) и отказ словами (`AutomationRefusal`).
- [AutomationRegistry.cs](../../../../Extensions/Automations/AutomationRegistry.cs) — поиск
  автоматизаций по сборке и проверка уникальности ключей.
- [AutomationAction.cs](../../../../Extensions/Automations/AutomationAction.cs) — мост
  «автоматизация → действие расширения»: один файл на все автоматизации.
- [AutomationsExtension.cs](../../../../Extensions/Automations/AutomationsExtension.cs) — сам
  контракт `IExtension`: описание и список действий.
- [SumByKeyAutomation.cs](../../../../Extensions/Automations/SumByKeyAutomation.cs) —
  автоматизация «Свести строки по ключу»: образец и рабочий инструмент.
- [SheetAction.cs](../../../../Extensions/Automations/SheetAction.cs) — действие «Выгрузить
  строки в книгу Excel».
- [Заготовка.cs.txt](../../../../Extensions/Automations/Заготовка.cs.txt) — то, что копируют,
  чтобы завести новую автоматизацию.

Тесты — [Tests/Extensions/Automations/](../../../../Tests/Extensions/Automations/); работа шага
в сценарии проверяется в ядре:
[ScenarioAutomationTests.cs](../../../../Tests/Integration/ScenarioAutomationTests.cs).

## Как завести автоматизацию

1. Скопировать [Заготовка.cs.txt](../../../../Extensions/Automations/Заготовка.cs.txt) рядом,
   в ту же папку, и дать копии расширение `.cs`.
2. Переименовать класс, вписать `Key`, `Name`, `What` и логику в `Run`.
3. Собрать.

Все. Новый пункт уже стоит в списке шагов сценария: править не надо ни реестр расширений, ни
окно настройки шага, ни документацию оболочки.

```csharp
public sealed class SumByKeyAutomation : IAutomation
{
    public string Key  => "sum-by-key";
    public string Name => "Свести строки по ключу";
    public string What => "Одна строка на каждое значение ключевой колонки…";

    public IReadOnlyList<ExtensionActionField> Settings =>
    [
        new("key", "Колонка-ключ", Watermark: "Проект"),
    ];

    public IReadOnlyList<AutomationRow> Run(AutomationInput input) { … }
}
```

### Почему список нигде не перечислен

Реестр находит автоматизации **по сборке**: типы своего пространства имен, реализующие
`IAutomation` и создающиеся без аргументов. Список в коде означал бы второе место, которое надо
не забыть, а забытое второе место — это автоматизация, которой нет в интерфейсе, и полдня на
выяснение почему.

Это **не загрузка чужих DLL**: ищутся типы своей сборки, приехавшей дистрибутивом и прошедшей
анализатор запрещенных вызовов. Папки с плагинами программа не читает и читать не будет
(раздел 13 плана).

Поиск идет один раз за запуск: перебор типов стоит миллисекунды, но делать его на каждую
перерисовку окна сценария незачем.

### Что автоматизации доступно

Строки предыдущего шага и настройки этого шага. Больше ничего — ни базы, ни сети, ни файлов:

| Что нужно | Как | Почему так |
|---|---|---|
| значение колонки | `row["Проект"]` | регистр не важен, нет колонки — пусто |
| есть ли колонка | `row.Has("Проект")` | отличать «нет колонки» от «пусто» |
| число | `row.Number("Цена")` | `null`, если не число; запятая — разделитель |
| новая колонка | `row.With("Итого", 120)` | КОПИЯ строки: то, что дали, портить нельзя |
| настройка шага | `input.Setting("key")` | заполняется один раз на шаг, а не на строку |
| отказ словами | `throw new AutomationRefusal("…")` | текст доедет до отчета и до квитанции |

Пустой список в ответе означает «дальше идти незачем»: сценарий кончится на этом шаге без
жалобы — так же, как на отборе, не нашедшем ни одной подходящей строки.

## Действие «Выгрузить строки в книгу Excel»

Второе, что дает расширение, — сборка книги из строк предыдущего шага. Живет оно здесь, а не в
каждой автоматизации, по той же причине, что и мост: выгрузка в книгу нужна почти каждому
обмену.

**Файл оно собирает, но никуда не кладет.** Книга возвращается байтами
(`ActionResult.MadeFile`), а на диск ее пишет оболочка в папку шага.
Оболочка проверяет имя, создает уникальный путь и обрабатывает ошибки записи.

Число в книге лежит числом, а не текстом: ради итога выгрузку чаще всего и делают. Имя листа, в
котором есть запрещенные Excel знаки, поправляется молча — отказывать человеку из-за двоеточия
в названии дешевле поправить, чем объяснить ограничение чужого формата.

## Особенности

- **Окна нет.** `CanRun = false`, `CreateWindow()` → `null`: автоматизации живут шагами
  сценария, и делать им в окне нечего.
- **Настроек у расширения нет.** Все настраивается в шаге — там же, где выбирается действие.
- **Ключ автоматизации хранится в шаге сценария**, поэтому он обязан быть уникальным и
  стабильным между выпусками: тезки означали бы шаг, выполняющий не то, что настроили.
  Проверка стоит на старте приложения (`AutomationRegistry.EnsureUniqueKeys`).
- **Строк за один запуск — не больше 500**: столько сценарий передает между шагами.
