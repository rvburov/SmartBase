# Автозапуск и фоновый режим

## Назначение

Чтобы напоминания ([[notifications]]) приходили **и при старте системы, и когда окно закрыто**,
в раздел **Настройки → Общее** добавлены два независимых тумблера (оба по умолчанию **выключены**):

- **Автозапуск при входе в систему** — запускать программу автоматически при входе в ОС.
- **Фоновый режим** — не закрывать программу при закрытии окна, а сворачивать её в **значок**
  (трей Windows / строка меню macOS / панель Linux) с меню «Открыть SmartBase» / «Выход».

Оба служат уведомлениям, но между собой независимы (можно включить любой). Хранятся дельтами в
app.db (`autostartEnabled`, `backgroundEnabled`), как остальные настройки ([[settings]]).

## Как работает

### Автозапуск
Пер-ОС запись «запускать при входе», ссылающаяся на текущий установленный бинарь/бандл. Если
включён фоновый режим — в команду добавляется `--background` (тихий старт).

| ОС      | Запись автозапуска                                              |
|---------|----------------------------------------------------------------|
| Windows | ключ реестра `HKCU\…\CurrentVersion\Run\SmartBase`             |
| macOS   | LaunchAgent `~/Library/LaunchAgents/com.romanburov.smartbase.plist` (RunAtLoad) |
| Linux   | `~/.config/autostart/smartbase.desktop`                        |

Построение записи (`BuildWindowsCommand`/`BuildMacPlist`/`BuildLinuxDesktop`) — **чистое**, без
записи на диск, покрыто [AutostartTests](../../../Tests/Unit/AutostartTests.cs). Вне установленного
приложения (`dotnet run`, на macOS — нет `.app`-бандла) `Autostart.IsSupported = false` и тумблер
неактивен — как и уведомления, автозапуск работает только из собранного приложения.

### Фоновый режим и значок
При включённом фоне нажатие на «крестик» окна его **скрывает**, а не завершает приложение
(различаем по `WindowCloseReason` в `MainWindow.Closing`; решение — чистая
`BackgroundBehavior.ShouldHideOnClose`). Служба уведомлений тикает на UI-потоке и продолжает
работать при скрытом окне. В системной области висит **значок** (`Avalonia.Controls.TrayIcon`,
иконка `Assets/Branding/icon.ico`, та же, что у окна) с меню **«Открыть SmartBase» / «Выход»**.
Значок виден, только когда фоновый режим включён. Возврат окна — значок, клик по уведомлению или
повторный запуск; выход — «Выход», ⌘Q (штатное меню macOS), Ctrl+Q. Выключение тумблера прячет
значок и возвращает окно, чтобы оно не осталось скрытым без точки возврата.

**На Linux трей — best-effort:** GNOME по умолчанию прячет значки трея (нужно расширение
AppIndicator); там остаются запасные пути (клик по уведомлению, повторный запуск).

### Тихий старт `--background`
Из автозапуска приложение стартует с `--background`: [Program.cs](../../../Program.cs) выставляет
`LaunchBackground`, [App.axaml.cs](../../../App.axaml.cs) не показывает сплэш и скрывает окно сразу
после `Show()` — так отрабатывает `Opened` (монтирование БД, служба уведомлений, трей), но окно
не мозолит глаза при входе в систему.

### Один экземпляр
[SingleInstance](../../../Utils/SingleInstance.cs) держит эксклюзивный лок-файл (`instance.lock`,
`FileShare.None`) по **локальной** папке данных. Второй запуск не поднимает второй фоновый
процесс (иначе — двойные уведомления), а пишет `show.signal` и выходит; работающий экземпляр по
`FileSystemWatcher` показывает окно. Локальность лока не мешает сценарию общей **сетевой** БД
между разными машинами — у каждой машины своя папка данных.

## Взаимодействия

- **Уведомления** ([[notifications]]) — ради них и сделаны оба режима: автозапуск и фон дают
  напоминаниям приходить без открытого окна / после входа в систему.
- **Настройки** ([[settings]]) — тумблеры в разделе «Общее»; хранение в app.db.
- **Иконка приложения** ([[icons]]) — значок трея и автозапуск используют ту же иконку/бандл.
- **Сборка** ([[../guides/build-and-run]]) — автозапуск и трей на macOS работают из собранного `.app`,
  не из `dotnet run`.
