# Автообновление приложения (план / ТЗ)

Статус: **готово для Windows** (этапы 1–5). Проверка версии, загрузка с прогрессом,
самозамена (`--apply-update`), установщик install/uninstall (вариант A — тот же `.exe`
под именем `DataBase-Setup.exe`). Осталось: кроссплатформа (Linux/macOS).

## Цель

Пользователь, которому раздали приложение, может из раздела **«О программе» →
«Обновления»** проверить наличие новой версии и обновиться: приложение закрывается,
`.exe` перезаписывается новым и приложение снова открывается. Плюс единый
установщик/удалятор (по образцу прежнего PyQt-установщика
[pyqt installer/installer.py](../../pyqt%20installer/installer.py)).

## Принятые решения

| Вопрос              | Решение                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Источник обновлений | **Сетевая/файловая папка** (`\\server\share\…` или диск `Z:\`). Версию читаем прямо из удалённого `.exe` (`FileVersionInfo`) — без скачивания.                                                           |
| Модель установки    | **Установленное приложение, вариант A**: тот же бинарь под именем `DataBase-Setup.exe` ставит в `%LOCALAPPDATA%\DataBase` (+ ярлыки, запись в «Приложения и возможности»), умеет install/update/uninstall. Раздаётся одним файлом, +0 МБ. |
| Путь к обновлению   | Хранится в `app.db` (ключ `UpdatePath`), **пустой по умолчанию** — пользователь вводит сам, сохраняется.                                                                                                 |
| Имя файла в папке   | `DataBase-Setup.exe` (один файл на сервере — и установщик, и обновление); если его нет — берётся `DataBase.exe`. Обновляешь новой сборкой.                                                                 |
| Права               | Установка в `%LOCALAPPDATA%` → **UAC не нужен**.                                                                                                                                                         |

## Где что лежит

| Что                      | Где                                                                                             |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| Установленное приложение | `%LOCALAPPDATA%\DataBase\DataBase.exe` (установщик — тот же бинарь под именем `-Setup`)         |
| Запись об установке      | `HKCU\…\Uninstall\DataBase` («Параметры → Приложения»); версия — в самом `.exe`                  |
| Данные пользователя      | `%APPDATA%\DataBase\database.db`, `app.db` — **отдельно**, при обновлении/удалении не трогаются |
| Путь обновления          | ключ `UpdatePath` в `app.db` (через [AppSettings](../../Utils/AppSettings.cs))                  |
| Папка обновлений (сеть)  | напр. `\\server\share\DataBase\DataBase.exe`                                                    |

## Архитектура: две программы

1. **`DataBase.exe`** — приложение. В «О программе» раздел «Обновления»: поле пути +
   кнопка «Проверить». **Самозамену делает само приложение**: новый `.exe` запускается
   в режиме `--apply-update` (ждёт выхода старого процесса, копирует себя поверх,
   перезапускает) — отдельный процесс-помощник для апдейта не нужен.
2. **`DataBase-Setup.exe`** — **тот же бинарь** под именем `…-Setup` (по имени файла
   включается режим установщика). GUI на Avalonia ([Setup/InstallerWindow](../../Setup/InstallerWindow.axaml)):
   установка/обновление в `%LOCALAPPDATA%\DataBase`, ярлыки, `--uninstall`. Логика —
   [Setup/InstallService.cs](../../Setup/InstallService.cs). Нужен для первичной установки и
   удаления; обновление работает и без него.

## Потоки

### Установка (первый раз)
1. Пользователь скачивает и запускает `DataBase-Setup.exe` (по имени `-Setup` открывается
   окно установки).
2. Выбор папки (по умолчанию `%LOCALAPPDATA%\DataBase`) → бинарь **копирует себя** туда
   под именем `DataBase.exe`, создаёт ярлыки (рабочий стол + Пуск + папка установки,
   включая «Uninstall DataBase»), регистрирует в «Параметры → Приложения».

### Проверить обновление
1. В «Обновления» введён путь к папке (напр. `\\server\share\DataBase`), сохранён в `app.db`.
2. Кнопка «Проверить» → берём `<UpdatePath>\DataBase-Setup.exe` (или `DataBase.exe`, если Setup нет).
3. Проверяем доступность папки/файла **в фоне**; если недоступно — красное уведомление (без таймаута).
4. `FileVersionInfo.GetVersionInfo(remote).FileVersion` → сравниваем с текущей
   (`Assembly.GetExecutingAssembly().GetName().Version`).
5. Новее → модалка: «Доступна версия X.Y.Z. Приложение закроется, обновится и снова
   откроется. [Отмена] [Обновить]». Иначе → «У вас актуальная версия».

### Обновить
1. Подтверждение в модалке: «Доступна версия X… [Обновить] [Отмена]».
2. Приложение копирует найденный файл (`DataBase-Setup.exe`/`DataBase.exe`) во временный файл
   (`%TEMP%\DataBase.update.exe`) — **с прогрессом, пока окно открыто** (тяжёлая часть:
   122 МБ по сети). Проверка: скопировано целиком (размер совпал).
3. Запуск нового `.exe`: `DataBase.update.exe --apply-update --target <текущий .exe> --pid <pid>`.
4. Приложение **закрывается**.
5. Новый `.exe` ждёт выхода старого (по `--pid`) → копирует себя поверх `--target`
   (с повторами при блокировке) → запускает обновлённое приложение → выходит.

> Прогресс-индикатор показывает **копирование из сети в temp** (в приложении). Сама
> замена локальным `File.Copy` — быстрая; её делает уже новый `.exe` без окна, пока
> старый закрыт.

### Удаление
Ярлык «Удалить DataBase» (= `DataBase.exe --uninstall`) → окно подтверждения → удаляет
ярлыки и папку установки. Папку (где лежит запущенный `.exe`) сносит **отложенный bat**:
ждёт выхода приложения → `rmdir` → удаляет себя. Данные в `%APPDATA%` — по галочке
«удалить и данные» (по умолчанию **сохранить**).

## Нюансы и их решения

| Нюанс                                       | Решение                                                                             |
| ------------------------------------------- | ----------------------------------------------------------------------------------- |
| Запущенный `.exe` нельзя перезаписать собой | Замену делает **новый** `.exe` в режиме `--apply-update`, пока старый закрыт |
| UAC                                         | Не нужен — установка в `%LOCALAPPDATA%`                                             |
| Битая копия при обрыве сети                 | Сначала в temp → проверка размера/хеша → только потом атомарный `move`              |
| Как узнать версию в папке без скачивания    | `FileVersionInfo` удалённого `.exe` (работает по SMB/диску)                         |
| Путь недоступен (нет VPN/сервера)           | Красное уведомление (как «файл недоступен» в «Управлении БД»); проверка в фоне, без таймаута |
| Антивирус/SmartScreen                       | Неподписанный `.exe` → предупреждение; подпись кода — опц. на будущее               |
| Критерий «новее»                            | Версия больше → обновить; при равной версии — дата изменения файла новее (новая сборка) |
| Кроссплатформенность                        | Сейчас Windows; ОС-зависимые куски (ярлык/замена/удаление) для Linux/macOS — этап 6 |

## Упаковка установщика (решено: вариант A)

Выбран **вариант A — тот же `.exe`**: бинарь `DataBase-Setup.exe` (копия `DataBase.exe`)
включает режим установщика по имени файла. Один файл раздачи, +0 МБ, GUI на Avalonia
в едином стиле, обычный запуск приложения не меняется. Альтернатива (отдельный
self-contained установщик ~120 МБ) отклонена из-за удвоения размера раздачи.

## Этапы реализации (по частям)

1. ✅ **Настройка пути.** Ключ `UpdatePath` в `app.db`; раздел «Обновления» в «О программе».
2. ✅ **Проверка версии.** `FileVersionInfo` по пути, сравнение, уведомления (фон, без таймаута).
3. ✅ **Загрузка + самозамена.** Сеть → temp с прогрессом, проверка целостности (размер),
   модалка «Обновить/Отмена», `--apply-update` (новый `.exe` заменяет старый и перезапускает).
4. ✅ **Установщик (вариант A).** Тот же `.exe` в режиме install/uninstall: окно на
   Avalonia, копия в `%LOCALAPPDATA%\DataBase`, ярлыки (рабочий стол + Пуск + папка),
   регистрация в «Параметры → Приложения» (HKCU\…\Uninstall), самоудаление через отложенный bat.
5. ✅ **Сборка установщика.** `windows-build.sh` кладёт `DataBase-Setup.exe` рядом с `DataBase.exe`.
6. ⏳ **Кроссплатформенность** (Linux/macOS) — ярлыки/замена/удаление под XDG и `.app`.
