# Режим «Журнал»

## Назначение

Лента событий, сгруппированных по дням, с прокруткой. Сегодняшний день всегда
присутствует (даже без событий) и подсвечен; при открытии лента
автопрокручивается к сегодня. Навигация ← → прыгает к соседней группе-дню.

- Запросы: `GetCalendarDayCountsByRange` / `LoadCalendarDayPageAsync`
  в [ConstructorRepository.cs](../../../Database/Repositories/ConstructorRepository.cs)

## Как работает

### Полная виртуализация (вся история данных без материализации)

Событий в окне могут быть **миллионы**, поэтому лента, как и «Расписание», полностью
виртуализирована. Список — ПЛОСКИЙ (`JournalVirtualList : IList`): строка = заголовок дня /
событие / «Нет записей на сегодня» / заглушка «Загрузка…»; все строки одной высоты, поэтому
позиции (скролл к дню, дата по клику) считаются по индексам. Карта окна строится из
**счётчиков по дням** (`GetCalendarDayCountsByRange`, GROUP BY по покрывающему индексу),
которые считаются **асинхронно** до построения (на огромных БД — секунды, на время подсчёта
в ленте «Загрузка…»); сами события НЕ читаются. Полоса прокрутки — на все строки окна.

Режимы (по суммарному числу событий окна):
- **InMemory** (≤ 10 000): события окна грузятся сразу (диапазонный запрос) и **сливаются по
  времени** между БД; внутри дня — «весь день» первыми. Покрывает все реальные данные.
- **Virtual** (миллионы): страницы строк грузятся **в фоне** offset'ом на изолированных
  подключениях (заглушки «Загрузка…», дебаунс — транзитные страницы при быстром драге запрос
  не тратят, LRU-кеш). Заголовки дней строятся без обращения к БД — мгновенно.
  **Порядок внутри дня — по времени** (all-day первыми) независимо от числа БД:
  - день ≤ 10 000 событий (`MergeDayCap`) — слитый по времени день целиком (LRU-кеш слитых дней);
  - гигантский день (миллионы) — **посекундная карта** (`LoadCalendarDayTimeHistogramAsync`:
    гистограмма «HH:MM:SS → счётчики по БД», строится в фоне один раз на день, LRU-кеш):
    события идут строго по секундам без материализации дня; конкатенация по БД остаётся
    только среди событий одной и той же секунды — визуально неотличимо от полного порядка.
- **Search**: фоновый SQL-поиск по ВСЕМУ окну (`SearchCalendarEventsAsync`: нативный LIKE с
  регистровыми вариантами подстроки — LIKE в SQLite не знает кириллицу без учёта регистра),
  первые 1000 совпадений на БД; на огромной БД скан занимает секунды в фоне («Загрузка…»).
  FTS5-trigram пробовали и откатили (минуты бэкафилла + деградация на частых подстроках).

Заголовок дня — «день_недели – число месяц ГОД» (лента охватывает годы — без года не понять,
где находишься); цвет: сегодня — красный, прошлое — серое, будущее — тёмное. Пустой «сегодня»
всегда вставляется в правильное место (заголовок + подсказка). После построения лента
прокручивается к сегодняшнему дню (по индексу строки).

### Создание/правка/удаление записи (тихое обновление, без прыжка к «сегодня»)

Полная перезагрузка после каждой правки означала бы секунды пересчёта на больших БД, в течение
которых видна УСТАРЕВШАЯ запись. Вместо этого:

- **правка НА МЕСТЕ** (`JournalVirtualList.ApplyDeltaAsync`): контроллер передаёт точечное
  изменение (запись, −1/+1), и текущий список **мутируется без пересоздания** — реализованные
  страницы, слитые дни и посекундные карты переживают правку, поэтому она видна в том же кадре
  и БЕЗ волны «Загрузка…» (пересоздание списка на разреженной истории перечитывало десятки
  видимых дней по одному — 3–4 с после каждого удаления). Строки пересаживаются на новые
  позиции по ключам (слитый день) или арифметикой смещений (гигантский день); посекундная
  карта правится точечно (± секунда записи), а страницы «с дырами» дочитывают только
  недостающие сегменты. Если мутация невозможна (InMemory, день пересёк порог слияния) —
  мгновенная пересборка по **кешу счётчиков дней** без полного GROUP BY; полный пересчёт
  остаётся для смены коллекций/БД и пересборки без дельты (внешнее изменение — кеш
  сбрасывается: неизвестно, что поменялось). Сигнатура кеша включает набор БД **и активных
  коллекций**; дельта правит кеш и при активном поиске (сама лента поиска пересобирается),
  поэтому **выход из поиска — мгновенный**, по кешу, без GROUP BY по всей истории;
- **позиция сохраняется**: лента остаётся на месте; к созданной/изменённой записи едет
  (плавно, запись по центру окна), только если её строка сейчас **не видна** — строку записи
  находит `RowOfEventAsync` (слитый день / бакет секунды в гигантском дне);
- **выделение переживает правку**: строки живут дальше со своим выделением (при пересборке
  ключи восстанавливаются), созданная/изменённая запись подсвечивается сразу — видно, какую
  запись меняли; «Редактировать» из меню и двойной клик выделение не сбрасывают;
- **удаление — всегда с подтверждением** (и одной записи, и нескольких — один диалог
  «Вы удаляете N записей»); пока диалог открыт, записи остаются выделенными — видно,
  ЧТО удаляется; после «Отмена» выделение сохраняется;
- **дублирование — из контекстного меню (одна или несколько записей), с подтверждением**
  («Вы дублируете N записей»): копии встают в ленту по порядку времени (сразу после
  оригиналов — тай-брейк по новому Id), выделение ПЕРЕХОДИТ с оригиналов на копии, и лента
  едет к последней по дате/времени копии, только если её строка сейчас не видна.

### Навигация (особая для Журнала)

В отличие от других режимов, контроллер не сдвигает дату, а вызывает методы
самого контрола, которые **плавно прокручивают** (`AnimateScroll`, easing 300 мс):

- `GoNext()` — к заголовку следующего дня (`NextHeaderRow`);
- `GoPrev()` — к заголовку текущего дня, если он выше, иначе предыдущего (`PrevHeaderRow`);
- `GoToday()` — к строке «сегодня» (`TodayHeaderRow`).

Позиции считаются по карте дней (индекс строки × высота), а не по визуальному дереву —
под виртуализацией реализованы только видимые строки.

## Взаимодействия

- **Клик / Shift+клик** — выделение (одиночное / множественное); **Ctrl+Shift+клик** — диапазон
  от последней выделенной записи до кликнутой (заголовки дней пропускаются).
- **Двойной клик по событию** → выделяет запись и открывает редактирование (`RecordClicked`);
  после «Сохранить»/«Отмена» запись остаётся подсвеченной.
- **Двойной клик по фону** / меню фона → `CreateRequested(дата под курсором)` (`GetDateForY` определяет день по вертикальной позиции).
- **Delete/Backspace** — удалить выделенное (с подтверждением; выделение видно, пока открыт диалог).
- **Правый клик** — контекстное меню: «Редактировать» / «Дублировать» / «Удалить»
  (по нескольким выделенным — «Дублировать» + «Удалить»).
