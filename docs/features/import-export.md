# Импорт и экспорт

## Назначение

Перенос данных извне и наружу. На сегодня **реально работает импорт из Excel**
(создание коллекции из листа). Часть путей экспорта/импорта пока заглушки.

## Где в коде

- Excel-импорт: [ExcelImporter.cs](../../Core/Importers/ExcelImporter.cs)
- UI: [ImportExportDialog](../../Controls/Dialogs/ImportExportDialog.axaml.cs)
- Создание коллекции из импорта: `ConstructorRepository.ImportExcelCollection(...)`
- Перенос коллекций/групп между БД: методы `ExportCollection`/`ImportCollection`,
  `ExportGroup`/`ImportGroup`, `MoveCollection`/`MoveGroup` в [ConstructorRepository](../../Database/Repositories/ConstructorRepository.cs)

## Импорт из Excel

### Зафиксированные решения

- **Форматы:** `.xlsx` и `.xlsm` → библиотека **ClosedXML** (MIT, чисто
  управляемая, совместима с single-file сборкой).
- **Поля «название / база данных / расположение»:** переиспользуются контролы и
  валидация из [CreateItemDialog](../../Controls/Dialogs/CreateItemDialog.axaml.cs).
- **Цель импорта:** всегда **новая** коллекция.
- **Экспорт:** пункт виден, но отключён («скоро»).

### Структура окна

Открывается по кнопке в сайдбаре. Стиль — как у остальных диалогов:
`SizeToContent`, баннер ошибок, удержание позиции окна.

1. **Режим** (выпадающий список): «Импорт» (выбран по умолчанию) / «Экспорт»
   (виден, но неактивен). При выборе «Импорт» раскрываются поля ниже.
2. **Файл**: поле для ручного ввода пути + кнопка «Обзор…» справа для выбора файла
   (фильтр `*.xlsx; *.xlsm`).
3. **Название коллекции** — обязательное. Пусто → ошибка «Укажите название
   коллекции»; дубль → «Коллекция с таким названием уже существует».
4. **База данных** — выбор подключённой БД.
5. **Расположение** — родительская группа (перестраивается при смене БД).
6. **Тип импорта** (выпадающий список): «Стандартный» / «Ручной».
7. Кнопки: **Импортировать** / **Отмена**. Чтение файла — асинхронно (`Task.Run`),
   чтобы не подвешивать интерфейс.

### Стандартный тип

Под выпадающим списком — серым текстом пояснение, как он работает:

- берётся только первый лист;
- первая строка — заголовки (имена свойств);
- 1-й столбец → название записи;
- остальные столбцы → текстовые свойства;
- колонка «Описание» создаётся пустой и ставится в конец (данные в неё не импортируются);
- данные читаются со второй строки; все значения сохраняются как текст.

### Ручной тип

Показывается только при выборе «Ручной». Значения вводятся вручную (не выбираются
из файла):

- **Лист** — вводится название листа (пусто → первый);
- **Строка заголовков** — вводится число (номер строки заголовков, ≥ 1);
- **Строка данных** — вводится число (с какой строки начинаются записи, ≥ 1);
- **Столбец названия** — вводится число или буква (например, `1` или `A`).

Поля ручного режима показываются отдельным блоком (карточкой с рамкой). Столбец
описания не задаётся: колонка «Описание» всегда создаётся пустой в конце.

### Правила пустых значений (фолбэк «Без названия»)

- Пустая ячейка в строке заголовков → подставляется «Без названия»; если таких
  ячеек несколько → «Без названия 1», «Без названия 2» и т.д.
- Пустое название у записи (пустая ячейка в столбце названия) → запись получает
  «Без названия»; если таких несколько → «Без названия 1», «Без названия 2» и т.д.
  Строки **не пропускаются**, а импортируются под этим именем.
- Повторяющиеся имена свойств дедуплицируются.

### Ошибки и сообщения

- **Никаких отчётов** в конце (нет «Импортировано N, пропущено M»).
- Показываются **только ошибки** — как `ExcelImportException` с дружелюбным текстом
  в баннере диалога: файл не найден/занят, лист не найден, пустой лист, неверный
  столбец, сбой при импорте и т.п.

### Прочие дефолты

- Тип «текст»: сохраняется **отображаемое** значение ячейки (даты/числа — строкой).
- Новая коллекция получает цвет `#007AFF` и иконку `table`.

### Поток данных в коде

`ExcelImporter.Parse(Spec)` → `ExcelImportData` (подпись названия, имена свойств,
записи) → `ConstructorRepository.ImportExcelCollection(collectionName, groupId, data)`
создаёт новую коллекцию: колонка «Название», поля под остальные столбцы, пустая
колонка «Описание» в конце (порядок задаётся через `SaveColumnOrder`) и записи-строки —
всё в одной транзакции.

## Перенос между БД

Внутри приложения коллекции и группы можно экспортировать в снимок
(`CollectionSnapshot`/`GroupSnapshot`) и импортировать в другую БД, а также
перемещать (`MoveCollection`/`MoveGroup`). Это используется при работе с
несколькими БД — см. [../architecture/multi-database.md](../architecture/multi-database.md).
